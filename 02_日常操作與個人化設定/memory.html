How Claude remembers your project

Give Claude persistent instructions with CLAUDE.md files, and let Claude accumulate learnings automatically with auto memory.

CLAUDE.md vs auto memory

Claude Code has two complementary memory systems, both loaded at the start of every conversation. Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead.

CLAUDE.md files

Who writes it: you.

What it contains: instructions and rules.

Scope: project, user, or org.

Use for: coding standards, workflows, project architecture.

Auto memory

Who writes it: Claude.

What it contains: learnings and patterns.

Scope: per repository, shared across worktrees.

Use for: build commands, debugging insights, preferences Claude discovers.

Both load into every session, though CLAUDE.md files load in full while auto memory's MEMORY.md loads only its first 200 lines or 25KB. Subagents can also maintain their own auto memory.

CLAUDE.md files

CLAUDE.md files are markdown files that give Claude persistent instructions for a project, personal workflow, or entire organization. Claude reads them at the start of every session.

When to add to CLAUDE.md

Repeated mistakeClaude makes the same mistake a second time
Code review catchA review catches something Claude should have known about this codebase
Repeated correctionYou type the same clarification into chat that you typed last session
Onboarding contextA new teammate would need the same context to be productive

Choose where to put CLAUDE.md files

Managed policy
e.g. /etc/claude-code/CLAUDE.md, org-wide instructions managed by IT/DevOps, all users
User instructions
~/.claude/CLAUDE.md, personal preferences for all projects, just you
Project instructions
./CLAUDE.md or ./.claude/CLAUDE.md, team-shared, shared via source control
Local instructions
./CLAUDE.local.md, personal project-specific, add to .gitignore, just you

Loaded in order from broadest to most specific, so a project instruction appears in context after a user instruction.

Write effective instructions

Size
Target under 200 lines per file. Longer files reduce adherence
Structure
Use markdown headers and bullets to group related instructions
Specificity
"Use 2-space indentation" beats "Format code properly"
Consistency
Contradicting rules make Claude pick one arbitrarily

How CLAUDE.md files load

Claude Code walks up the directory tree from your working directory, checking each directory for CLAUDE.md and CLAUDE.local.md. All discovered files are concatenated, ordered from filesystem root down to your working directory, so instructions closer to where you launched Claude are read last. Block-level HTML comments are stripped before injection into context.

Organize rules with .claude/rules/

For larger projects, organize instructions into multiple files in .claude/rules/. Rules can be scoped to specific file paths with YAML frontmatter.

---
paths:
  - "src/api/**/*.ts"
---

# API Development Rules

- All API endpoints must include input validation
**/*.ts
All TypeScript files in any directory
src/**/*
All files under src/ directory

User-level rules in ~/.claude/rules/ apply to every project and load before project rules.

Manage CLAUDE.md for large teams

Managed CLAUDE.md

Behavioral instructions, code style, data handling and compliance reminders.

Managed settings

Technical enforcement: permissions.deny, sandbox.enabled, env, forceLoginMethod.

The claudeMdExcludes setting lets you skip specific ancestor CLAUDE.md files in large monorepos by path or glob pattern. Managed policy CLAUDE.md files cannot be excluded.

Auto memory

Auto memory lets Claude accumulate knowledge across sessions without you writing anything: build commands, debugging insights, architecture notes, code style preferences, and workflow habits. Requires Claude Code v2.1.59 or later.

Enable or disable

{
  "autoMemoryEnabled": false
}

Or set CLAUDE_CODE_DISABLE_AUTO_MEMORY=1.

Storage location

~/.claude/projects/<project>/memory/
├── MEMORY.md          # Concise index, loaded into every session
├── debugging.md       # Detailed notes on debugging patterns
├── api-conventions.md # API design decisions
└── ...                # Any other topic files Claude creates

Each project gets its own memory directory derived from the git repository, so all worktrees and subdirectories share one auto memory directory. Auto memory is machine-local.

How it works

The first 200 lines of MEMORY.md, or the first 25KB, whichever comes first, load at the start of every conversation. Topic files like debugging.md are not loaded at startup; Claude reads them on demand with its standard file tools when it needs the information.

View and edit with /memory

The /memory command lists all CLAUDE.md, CLAUDE.local.md, and rules files loaded in your current session, lets you toggle auto memory on or off, and links to the auto memory folder.

remember that the API tests require a local Redis instance

Saying this saves it to auto memory. To add instructions to CLAUDE.md instead, ask Claude directly, like "add this to CLAUDE.md."

Troubleshoot memory issues

Issue:
Not following CLAUDE.md
Don't know what was saved
CLAUDE.md too large
Lost after /compact

CLAUDE.md is delivered as a user message after the system prompt, not part of it, so there's no guarantee of strict compliance. Run /memory to verify files are loaded, check the location is one that gets loaded, and make instructions more specific. For instructions that must run at a fixed point, use a hook instead.

Run /memory and select the auto memory folder to browse what Claude has saved. Everything is plain markdown you can read, edit, or delete.

Files over 200 lines consume more context and may reduce adherence. Use path-scoped rules to load instructions only when Claude works with matching files.

Project-root CLAUDE.md survives compaction and is re-injected after /compact. Nested CLAUDE.md files in subdirectories are not re-injected automatically; they reload the next time Claude reads a file in that subdirectory.
