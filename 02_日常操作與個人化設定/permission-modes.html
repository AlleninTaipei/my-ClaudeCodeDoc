選擇權限模式

控制 Claude 在編輯檔案, 執行指令前是否需要詢問你, 用 Shift+Tab 在 CLI 中循環切換

可用模式

每種模式在便利性與監督程度之間做出不同取捨。下方顯示每種模式在不需詢問的情況下, Claude 可以做什麼。

重要

除了 bypassPermissions 模式以外, 所有模式對受保護路徑 (protected paths) 的寫入永遠不會自動核准, 藉此保護儲存庫狀態與 Claude 自身的設定不受意外破壞。權限規則 (permission rules) 可疊加在模式之上, 用來預先核准或封鎖特定工具; deny 規則與明確的 ask 規則在所有模式下都會生效, 包含 bypassPermissions。

切換權限模式

可以在 session 中途, 啟動時, 或作為持久預設值來切換模式。模式是透過下方控制方式設定, 而非在對話中要求 Claude 切換。選擇你的介面查看切換方式。

Step 1 of 5

用 acceptEdits 模式自動核准檔案編輯

acceptEdits 模式讓 Claude 建立與編輯工作目錄中的檔案, 不需詢問。啟用時狀態列顯示 accept edits on。除了檔案編輯外, 也會自動核准常見的檔案系統 Bash 指令: mkdir, touch, rm, rmdir, mv, cp, sed, 以及搭配安全環境變數 (如 LANG=C) 或行程包裝工具 (timeout, nice, nohup) 的前綴形式。自動核准僅適用於工作目錄或 additionalDirectories 內的路徑, 範圍外路徑與受保護路徑的寫入仍會詢問。

啟用 PowerShell 工具時, acceptEdits 模式也會自動核准範圍內路徑的 Set-Content, Add-Content, Clear-Content, Remove-Item 及其常見別名。

claude --permission-mode acceptEdits

想在事後用編輯器或 git diff 檢視變更, 而非逐一核准編輯時使用此模式。從 default 模式按一次 Shift+Tab 即可進入。

用 plan 模式先分析再編輯

Plan 模式讓 Claude 研究並提出變更建議, 但不實際修改。Claude 會讀取檔案, 執行 shell 指令來探索, 並撰寫計畫, 但不編輯原始碼。權限提示規則與 default 模式相同。

claude --permission-mode plan

按 Shift+Tab 或在單一提示前加上 /plan 進入計畫模式, 再按一次 Shift+Tab 可離開而不核准計畫。

用 auto 模式消除權限提示研究預覽

Auto 模式讓 Claude 執行時不會出現例行的權限提示。獨立的分類模型會在動作執行前審查, 封鎖任何超出你要求範圍, 針對未知基礎設施, 或看似受 Claude 讀取的惡意內容驅動的動作。明確的 ask 規則仍會強制觸發提示。

警告

Auto 模式是研究預覽版本, 能減少權限提示但不保證安全, 請用於信任大方向的任務, 而非取代對敏感操作的審查。

你在對話中陳述的界線

分類器會將你在對話中陳述的界線視為封鎖訊號。例如告訴 Claude 「先不要推送」或「等我審閱後再部署」, 即使預設規則允許, 分類器仍會封鎖對應動作。界線會持續生效直到你在之後的訊息中解除, Claude 自行判斷條件已滿足並不會解除界線。

注意

界線不是以規則形式儲存, 分類器每次檢查時會重新從逐字稿讀取, 若上下文壓縮移除了陳述界線的訊息, 界線可能因此遺失。若需要硬性保證, 改用 deny 規則。

Auto 模式回退機制

每個被拒絕的動作會顯示通知, 並出現在 /permissions 的 Recently denied 分頁, 可按 r 以手動核准重試。若分類器連續 3 次或總計 20 次封鎖動作, auto 模式會暫停並恢復詢問, 核准被提示的動作後恢復 auto 模式。這些門檻無法調整。

分類器如何評估動作›

每個動作依固定順序決策, 第一個符合的步驟勝出: 1) 符合 allow/deny 規則的動作立即解析 (受保護路徑寫入除外); 2) 工作目錄內的唯讀動作與檔案編輯自動核准 (受保護路徑除外); 3) 其餘動作交給分類器; 4) 若分類器封鎖, Claude 會收到原因並嘗試替代方案。進入 auto 模式時, 授予任意程式碼執行權限的寬鬆 allow 規則 (如 Bash(*)) 會被移除, 離開 auto 模式後會恢復。

Auto 模式如何處理子代理›

分類器在三個時間點檢查子代理工作: 1) 子代理啟動前評估委派的任務描述, 危險的任務會在產生時就被封鎖; 2) 子代理執行期間, 每個動作都以與父 session 相同規則通過分類器, 子代理 frontmatter 中的 permissionMode 會被忽略; 3) 子代理結束時, 分類器審查其完整動作歷史, 若發現疑慮會在結果前附加安全警告。

成本與延遲›

分類器在伺服器設定的模型上執行, 與 /model 選擇無關, 因此切換模型不影響分類器可用性。分類器呼叫會計入 token 用量, 每次檢查都會傳送部分逐字稿與待執行動作, 在執行前增加一次往返。工作目錄內受保護路徑之外的讀取與編輯會跳過分類器, 因此額外開銷主要來自 shell 指令與網路操作。

用 dontAsk 模式只允許預先核准的工具

dontAsk 模式會自動拒絕任何原本會觸發提示的工具呼叫, 只有符合 permissions.allow 規則與唯讀 Bash 指令的動作可以執行, 明確的 ask 規則會被拒絕而非提示。這使得此模式完全非互動, 適合 CI 流水線或需要預先定義 Claude 可做之事的受限環境。

claude --permission-mode dontAsk

用 bypassPermissions 模式跳過所有檢查

bypassPermissions 模式停用權限提示與安全檢查, 工具呼叫會立即執行 (v2.1.126 起也包含受保護路徑寫入)。明確的 ask 規則仍會強制提示, 針對檔案系統根目錄或家目錄的刪除 (如 rm -rf / 或 rm -rf ~) 仍會提示作為斷路保護。只應在容器, VM 等隔離環境, 且無網際網路存取的環境中使用此模式。

claude --permission-mode bypassPermissions

--dangerously-skip-permissions 旗標效果相同。在 Linux 與 macOS 上, 以 root 或 sudo 執行時 Claude Code 會拒絕以此模式啟動 (在已知的沙盒環境中此檢查會自動跳過)。

警告

bypassPermissions 對提示注入或非預期動作沒有任何防護。若要在保留較少權限提示的同時做背景安全檢查, 請改用 auto 模式。管理員可透過 managed settings 的 permissions.disableBypassPermissionsMode 封鎖此模式。

受保護路徑

在 bypassPermissions 以外的每個模式中, 對一小組路徑的寫入永遠不會自動核准, 以防止意外破壞儲存庫狀態與 Claude 自身的設定。
