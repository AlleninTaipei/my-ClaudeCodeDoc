自訂鍵盤快捷鍵

透過 keybindings.json 設定檔, 為 Claude Code 客製化每個情境下的按鍵行為

設定檔結構

執行 /keybindings 建立或開啟位於 ~/.claude/keybindings.json 的設定檔。此檔案是一個包含 bindings 陣列的物件, 每個區塊指定一個情境 (context) 與按鍵對應動作的映射表。修改後會自動偵測並套用, 不需要重新啟動。

$schema
選用的 JSON Schema URL, 供編輯器自動完成
$docs
選用的文件說明 URL
bindings
依情境分組的綁定區塊陣列
{
  "$schema": "https://www.schemastore.org/claude-code-keybindings.json",
  "$docs": "https://code.claude.com/docs/en/keybindings",
  "bindings": [
    {
      "context": "Chat",
      "bindings": {
        "ctrl+e": "chat:externalEditor",
        "ctrl+u": null
      }
    }
  ]
}
範例說明

此範例將 Ctrl+E 綁定為在聊天情境開啟外部編輯器, 並取消綁定 Ctrl+U。

情境 (Contexts)

每個綁定區塊都要指定套用的情境。點擊下方分類瀏覽所有可用情境。

可用動作 (Available Actions)

動作採用 namespace:action 格式, 例如 chat:submit 送出訊息, 或 app:toggleTodos 顯示任務清單。每個情境有各自可用的動作, 點選下方分類查看對應的動作清單與預設按鍵。

按鍵語法 (Keystroke Syntax)

1 · 修飾鍵
2 · 大寫字母
3 · 組合鍵 (Chords)
4 · 特殊按鍵

使用 + 分隔修飾鍵:

ctrl / control
Control 鍵
shift
Shift 鍵
alt / opt / option / meta
Windows/Linux 的 Alt 鍵, macOS 的 Option 鍵
cmd / command / super / win
macOS 的 Command 鍵, Windows 鍵, Linux 的 Super 鍵
注意

cmd 群組只有在支援 Kitty keyboard protocol 或 xterm modifyOtherKeys 模式的終端機才會被偵測到, 大多數終端機不會送出此訊號, 建議使用 ctrl 或 meta 以確保跨終端機皆可運作。

ctrl+k          Ctrl + K
shift+tab       Shift + Tab
meta+p          macOS 上為 Option + P, 其他系統為 Alt + P
ctrl+shift+c    多重修飾鍵

單獨的大寫字母隱含 Shift, 例如 K 等同於 shift+k, 適用於 vim 風格的綁定 (大小寫代表不同意義)。

差異

搭配修飾鍵的大寫字母 (例如 ctrl+K) 視為風格性寫法, 不隱含 Shift: ctrl+K 等同於 ctrl+k。

Chords 是以空白分隔的按鍵序列:

ctrl+k ctrl+s   按下 Ctrl+K, 放開後再按 Ctrl+S
escape / esc
Escape 鍵
enter / return
Enter 鍵
tab
Tab 鍵
space
空白鍵
up / down / left / right
方向鍵
backspace / delete
刪除鍵

取消綁定預設快捷鍵

將動作設為 null 即可取消綁定預設快捷鍵, 對 chord 綁定也同樣適用。取消綁定某個前綴下所有的 chord, 該前綴就會釋放出來供單鍵綁定使用。

{
  "bindings": [
    {
      "context": "Chat",
      "bindings": {
        "ctrl+x ctrl+k": null,
        "ctrl+x ctrl+e": null,
        "ctrl+x": "chat:newline"
      }
    }
  ]
}
提示

如果只取消綁定某個前綴下的部分 chord, 按下該前綴仍會進入等待 chord 的狀態, 等待其餘尚存的綁定。

保留快捷鍵與終端機衝突

無法重新綁定的快捷鍵

Ctrl+C — 硬編碼的中斷/取消

Ctrl+D — 硬編碼的結束

Ctrl+M — 在終端機中等同 Enter (皆送出 CR)

Caps Lock — 不會傳遞給終端機應用程式

可能與終端機多工工具衝突

Ctrl+B — tmux 前綴鍵 (按兩次才送出)

Ctrl+A — GNU screen 前綴鍵

Ctrl+Z — Unix 行程暫停 (SIGTSTP)

Vim 模式互動

透過 /config → Editor mode 啟用 vim 模式後, 鍵盤綁定與 vim 模式各自獨立運作:

Vim 模式在文字輸入層級處理輸入 (游標移動, 模式, 動作)
Keybindings在元件層級處理動作 (切換任務清單, 送出訊息等)
Escape (vim)從 INSERT 切換到 NORMAL 模式, 不會觸發 chat:cancel
Ctrl+按鍵大多數 Ctrl 快捷鍵會穿透 vim 模式傳給鍵盤綁定系統
? (NORMAL 模式)顯示說明選單 (vim 行為)
/ (NORMAL 模式)開啟歷史搜尋, 與標準模式下的 Ctrl+R 相同

驗證

Claude Code 會驗證你的鍵盤綁定設定, 並針對以下情況顯示警告:

解析錯誤無效的 JSON 或結構
無效情境名稱拼寫錯誤或不存在的 context
保留快捷鍵衝突嘗試重新綁定無法變更的快捷鍵
終端機多工衝突與 tmux, screen 等工具的前綴鍵衝突
重複綁定同一情境內出現重複的按鍵綁定

執行 /doctor 可以看到所有鍵盤綁定相關的警告訊息。
