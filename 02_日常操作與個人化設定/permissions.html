設定權限

用細緻的權限規則, 模式與 managed policies 控制 Claude Code 能存取與執行的內容

權限系統

Claude Code 使用分層的權限系統, 在能力與安全之間取得平衡。

唯讀 (File reads, Grep)
不需核准
Bash 指令 (Shell execution)
需要核准, "不再詢問"後在該專案目錄與指令永久生效
檔案修改 (Edit/write files)
需要核准, 直到 session 結束為止

管理權限

用 /permissions 檢視與管理 Claude Code 的工具權限, 此介面會列出所有規則及其來源的 settings.json 檔案。

Allow讓 Claude Code 不需人工核准即可使用指定工具
Ask每次嘗試使用指定工具時都提示確認
Deny禁止 Claude Code 使用指定工具

規則依 deny, ask, allow 的順序評估, 該順序中第一個符合的規則決定結果, 規則的specificity 不會改變順序。像 Bash(aws *) 這種寬泛的 deny 規則會封鎖所有符合的呼叫, 即使有更精確的 allow 規則也一樣。

差異

裸工具名稱的 deny 規則 (如 Bash) 會將該工具整個從 Claude 的上下文中移除, Claude 永遠看不到它。範圍化規則 (如 Bash(rm *)) 則保留工具可見, 但封鎖符合的呼叫。

注意

權限規則由 Claude Code 強制執行, 而非模型本身。提示或 CLAUDE.md 中的指示會影響 Claude 嘗試做的事, 但不會改變 Claude Code 允許的範圍。

權限模式

在 settings 檔案設定 defaultMode 來控制核准工具呼叫的方式。

default
標準行為: 每個工具首次使用時提示核准
acceptEdits
自動接受檔案編輯與常見檔案系統指令
plan
計畫模式: 讀取與唯讀探索, 不編輯原始碼
auto
背景安全檢查自動核准工具呼叫 (研究預覽)
dontAsk
除非預先在 /permissions 或 allow 規則核准, 否則自動拒絕
bypassPermissions
跳過權限提示, 明確 ask 規則除外
警告

bypassPermissions 模式會跳過對 .git, .config/git, .claude, .vscode, .idea, .husky, .cargo, .devcontainer, .yarn, .mvn 等路徑寫入的提示。僅在容器或 VM 等隔離環境使用。

權限規則語法

權限規則採用 Tool 或 Tool(specifier) 的格式。點選下方分類查看各種語法情境與範例。

Bash 萬用字元範例

Bash 規則支援用 * 做萬用字元比對, 可以出現在指令的任何位置。此設定允許 npm 與 git commit 指令, 但封鎖 git push:

{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git commit *)",
      "Bash(git * main)",
      "Bash(* --version)",
      "Bash(* --help *)"
    ],
    "deny": [
      "Bash(git push *)"
    ]
  }
}
重要

Bash(ls *) 前面有空白, 會比對 ls -la 但不比對 lsof (要求單字邊界); Bash(ls*) 沒有空白則兩者都比對。:* 後綴等同於結尾加空白星號。

工具專屬的權限規則

不同工具在規則比對上有各自的細節。點選下方標籤切換查看。

Bash
PowerShell
Read/Edit
WebFetch
MCP
Agent
Cd

Claude Code 能識別 shell 運算子, 因此 Bash(safe-cmd *) 不會授權執行 safe-cmd && other-cmd。可識別的分隔符為 && || ; | |& & 與換行, 規則必須各自比對每個子指令。

核准複合指令的「不再詢問」時, Claude Code 會為每個需要核准的子指令各自儲存一條規則, 而非整條複合字串一條規則。單一複合指令最多儲存 5 條規則。

比對前會先剝除固定的行程包裝工具 (timeout, time, nice, nohup, stdbuf), 所以 Bash(npm test *) 也會比對 timeout 30 npm test。裸 xargs 也會被剝除。

Claude Code 內建一組唯讀 Bash 指令 (ls, cat, echo, pwd, head, tail, grep, find, wc, which, diff, stat, du, cd, 唯讀形式的 git), 這些指令在所有模式下都不需提示。

PowerShell 規則語法與 Bash 相同, 星號比對任意位置, :* 後綴等同於結尾空白星號, 裸 PowerShell 或 PowerShell(*) 比對所有指令。

{
  "permissions": {
    "allow": ["PowerShell(Get-ChildItem *)", "PowerShell(git commit *)"],
    "deny": ["PowerShell(Remove-Item *)"]
  }
}

常見別名會先正規化再比對, 例如 PowerShell(Get-ChildItem *) 也比對 gci, ls, dir。Claude Code 會解析 PowerShell AST, 並各自檢查複合指令中的每個子指令。

Edit 規則適用於所有內建的檔案編輯工具。Read 規則盡力適用於 Grep, Glob, @file 提及, 以及已連接 IDE 分享的選取與開啟檔案上下文。四種路徑寫法皆遵循 gitignore 規格:

//path
檔案系統根目錄的絕對路徑, 例如 Read(//Users/alice/secrets/**)
~/path
從家目錄開始的路徑, 例如 Read(~/Documents/*.pdf)
/path
相對於專案根目錄, 例如 Edit(/src/**/*.ts)
path 或 ./path
相對於目前目錄, 例如 Read(*.env)
警告

像 /Users/alice/file 這種寫法不是絕對路徑, 而是相對於專案根目錄, 絕對路徑要用 //Users/alice/file。Windows 路徑會先正規化為 POSIX 形式再比對。

WebFetch 規則使用 domain: 前綴比對請求網址的主機名稱, 比對不分大小寫, 支援 * 萬用字元。

WebFetch(domain:example.com)
比對 example.com 的請求
WebFetch(domain:*.example.com)
比對任意深度子網域, 但不比對 example.com 本身
WebFetch(domain:*)
比對所有網域, 等同裸 WebFetch 規則

MCP 規則使用 Claude Code 中設定的伺服器名稱, 選擇性加上該伺服器的工具名稱。

mcp__puppeteer
比對 puppeteer 伺服器提供的任何工具
mcp__puppeteer__*
同樣比對 puppeteer 伺服器的所有工具
mcp__puppeteer__puppeteer_navigate
比對特定的 puppeteer_navigate 工具

用 Agent(AgentName) 規則控制 Claude 可使用哪些子代理。

{
  "permissions": {
    "deny": ["Agent(Explore)"]
  }
}

Cd 規則控制 /cd 指令可以移動到哪些目錄。Cd 不是模型可呼叫的工具, Claude 無法呼叫它, 規則只在你自己執行 /cd 時套用。加入任何 Cd allow 規則會將 /cd 切換為允許清單模式。

Cd(~/code/*)
比對 ~/code/app, 但不比對 ~/code/app/src 或 ~/code 本身
Cd(~/code/**)
比對 ~/code 與其下任何目錄
Cd(**/node_modules)
比對任意深度的 node_modules 目錄

用 Hooks 擴充權限

Claude Code hooks 提供在執行期間註冊自訂 shell 指令來做權限評估的方式。工具呼叫發生時, PreToolUse hooks 會在權限提示前執行, hook 輸出可以拒絕工具呼叫, 強制提示, 或跳過提示讓呼叫繼續。

重要

Hook 決策不會繞過權限規則。Deny 與 ask 規則無論 PreToolUse hook 回傳什麼都會被評估, 因此符合的 deny 規則仍會封鎖呼叫。退出碼 2 的封鎖型 hook 則優先於 allow 規則。

工作目錄

預設情況下, Claude 只能存取啟動時所在目錄中的檔案, 可透過以下方式擴充存取範圍:

啟動時使用 --add-dir <path> 參數
Session 中使用 /add-dir 指令
持久設定在 settings 檔案的 additionalDirectories 中新增
注意

新增目錄只會擴充檔案讀寫的存取範圍, 並不會讓該目錄成為完整的設定根目錄, 大多數 .claude/ 設定不會從額外目錄中被發現, 只有少數例外 (skills, subagents, 部分 settings 鍵, 需搭配環境變數的 CLAUDE.md)。

權限與沙盒的關係

權限與沙盒是互補的安全層。

Permissions

控制 Claude Code 能使用哪些工具, 能存取哪些檔案或網域, 適用於所有工具, 包含 Bash, Read, Edit, WebFetch, MCP。

Sandboxing

提供作業系統層級的強制執行, 限制 Bash 工具的檔案系統與網路存取, 僅適用於 Bash 指令與其子行程。

兩者搭配使用可達成縱深防禦: 權限的 deny 規則封鎖 Claude 嘗試存取受限資源, 沙盒限制則防止 Bash 指令觸及邊界外資源, 即使提示注入繞過了 Claude 的決策。

Managed settings

需要集中控管 Claude Code 設定的組織, 管理員可以部署無法被使用者或專案設定覆寫的 managed settings, 透過 MDM/OS 層級政策, managed settings 檔案, server-managed settings, 或自架的 Claude apps gateway 傳遞。

設定優先順序

1. Managed settings無法被任何其他層級覆寫, 包含命令列參數
2. 命令列參數臨時性的 session 覆寫
3. Local project settings.claude/settings.local.json
4. Shared project settings.claude/settings.json
5. User settings~/.claude/settings.json
重要

若某個工具在任一層級被拒絕, 其他層級都無法允許它。使用者層級的 deny 會封鎖專案層級的 allow, 因為任何範圍的 deny 規則都會在 allow 規則之前被評估。
