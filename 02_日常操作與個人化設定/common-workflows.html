Common Workflows

探索程式碼庫, 修 bug, 重構, 測試等日常任務的逐步指南

提示語範例 (Prompt Recipes)

以下是日常任務常見的提示模式, 每種都適用於任何 Claude Code 介面, 依需求調整措辭。點選分類切換範例。

情境: 理解新的程式碼庫 修 bug 重構 撰寫測試 建立 PR 處理文件 處理圖片 排程執行
1cd /path/to/project 進入專案根目錄
2claude 啟動 Claude Code
3"give me an overview of this codebase" 詢問高層次總覽
4"explain the main architecture patterns used here" 深入特定元件
提示

從廣泛問題開始再逐步縮小範圍; 詢問專案慣例與模式; 請求專案專屬術語表。

1"I'm seeing an error when I run npm test" 分享錯誤訊息
2"suggest a few ways to fix the @ts-ignore in user.ts" 請求修復建議
3"update user.ts to add the null check you suggested" 套用修復
提示

告訴 Claude 重現問題的指令並取得 stack trace; 說明重現步驟; 告知錯誤是間歇性或持續發生。

1"find deprecated API usage in our codebase" 找出待重構的舊程式碼
2"suggest how to refactor utils.js to use modern JavaScript features" 取得重構建議
3"refactor utils.js to use ES2024 features while maintaining the same behavior" 安全套用變更
4"run tests for the refactored code" 驗證重構結果
提示

請 Claude 解釋現代做法的優點; 需要時要求保留向後相容性; 以小而可測試的增量進行重構。

1"find functions in NotificationsService.swift that are not covered by tests" 找出未測試的程式碼
2"add tests for the notification service" 產生測試骨架
3"add test cases for edge conditions" 補齊邊界案例
4"run the new tests and fix any failures" 執行並驗證測試
提示

Claude 會檢視現有測試檔案以符合風格, 框架與斷言慣例; 也可請 Claude 找出容易被忽略的邊界值與例外情況。

1"summarize the changes I've made to the authentication module" 摘要變更
2"create a pr" 產生 pull request
3"enhance the PR description with more context" 審閱並補強說明
提示

用 gh pr create 建立的 PR 會自動連結該 session, 之後可用 claude --from-pr <number> 或貼上 PR URL 到 /resume 選擇器找回。

1"find functions without proper JSDoc comments in the auth module" 找出缺文件的程式碼
2"add JSDoc comments to the undocumented functions in auth.js" 產生文件
3"improve the generated documentation with more context and examples" 審閱並強化
4"check if the documentation follows our project standards" 驗證文件
提示

指定想要的文件風格 (JSDoc, docstring 等); 要求文件包含範例; 針對公開 API, 介面與複雜邏輯撰寫文件。

1拖放圖片, 或用 Ctrl+V 貼上, 或提供圖片路徑
2"What does this image show?" 請 Claude 分析圖片內容
3"Generate CSS to match this design mockup" 依視覺內容取得程式碼建議
提示

當文字描述不夠清楚時使用圖片; 可在同一對話中處理多張圖片; 圖片分析適用於流程圖, 截圖與設計稿。

Routines在 Anthropic 代管基礎架構上執行, 即使電腦關機也能跑, 於 claude.ai/code/routines 設定
Desktop scheduled tasks透過桌面版 app 在本機執行, 適合需要直接存取本機檔案的任務
GitHub Actions在 CI pipeline 中執行, 適合綁定 repo 事件的任務
/loop在目前 CLI session 中快速輪詢, session 結束任務即停止
提示

撰寫排程任務提示時要明確定義成功樣貌與後續處理方式, 因為任務自動執行, 無法詢問澄清問題。

恢復先前的對話

當任務橫跨多次工作階段時, 從上次停下的地方繼續, 而不用重新解釋 context。Claude Code 會持續在本機儲存每次對話。

claude --continue
說明

恢復目前目錄中最近的 session; 若尚無對話, 印出 "No conversation found to continue" 並結束。用 claude --resume 從清單選擇, 或在 session 內用 /resume。

用 Worktree 執行平行 session

在一個終端機處理功能, 同時在另一個終端機修 bug, 彼此的編輯不會衝突。每個 worktree 是獨立分支上的獨立檢出。

claude --worktree feature-auth
說明

在第二個終端機以不同名稱執行相同指令即可啟動獨立的平行 session。要從單一畫面監控多個平行 session, 可使用背景代理人 (agent view)。

編輯前先規劃

對於希望先審閱再落地的變更, 切換到 plan mode。Claude 會讀取檔案並提出計畫, 在你核准前不會做任何編輯。

claude --permission-mode plan
說明

也可在 session 中按 Shift+Tab 切換進入 plan mode。

將研究工作委派給 Subagent

探索大型程式碼庫會讓 context 塞滿檔案讀取內容。將探索工作委派出去, 只讓結論回傳。

use a subagent to investigate how our auth system handles token refresh
說明

subagent 會在自己的 context window 中讀取檔案並回報摘要。

將 Claude 接入腳本

以非互動方式執行 Claude, 用於 CI, pre-commit hook 或批次處理。標準輸入輸出的行為如同任何 Unix 工具。

git log --oneline -20 | claude -p "summarize these recent commits"

要點: 探索用 subagent 保持主 context 乾淨; 大變更用 plan mode 先審閱; 平行任務用 worktree 避免衝突; 自動化用管線接入 -p。
