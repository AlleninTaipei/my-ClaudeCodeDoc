Claude Code 設定

用全域與專案層級的設定, 以及環境變數配置 Claude Code 的行為

適用範圍: 通用 所有安裝方式皆適用 Managed 專屬 僅限管理員部署的 managed settings

設定範圍 (Configuration Scopes)

Claude Code 用範圍系統決定設定套用在哪裡, 與誰共享。點選下方範圍查看位置與影響對象。

範圍如何互動

同一個設定出現在多個範圍時, Claude Code 依優先順序套用:

1. Managed (最高)無法被任何其他層級覆寫
2. 命令列參數臨時性的 session 覆寫
3. Local覆寫 project 與 user 設定
4. Project覆寫 user 設定
5. User (最低)當其他層級都沒有指定時套用
例外

權限規則的行為不同, 它們是跨範圍合併而非互相覆寫, 詳見下方「設定優先順序」章節。

設定檔案 (Settings Files)

settings.json 是設定 Claude Code 的官方機制, 採階層式設定。點選下方分頁瀏覽各主題。

1 · 檔案位置
2 · 可用設定
3 · 沙盒設定
4 · 歸屬與檔案建議
5 · Hooks 與 Footer 徽章
6 · 優先順序與驗證
User settings
~/.claude/settings.json, 適用所有專案
Project settings
.claude/settings.json, 納入版控與團隊共享
Local settings
.claude/settings.local.json, 不納入版控, 個人偏好用
Managed settings
server-managed, MDM/OS 政策, 或 managed-settings.json 檔案

另一個檔案 ~/.claude.json 儲存 OAuth session, 使用者與本機範圍的 MCP 伺服器設定, 每個專案的狀態與各種快取。專案範圍的 MCP 伺服器則獨立存放於 .mcp.json。

{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": ["Bash(npm run lint)", "Bash(npm run test *)"],
    "deny": ["Bash(curl *)", "Read(./.env)"]
  },
  "env": { "CLAUDE_CODE_ENABLE_TELEMETRY": "1" }
}
何時生效

Claude Code 會監看設定檔並在變更時重新載入, permissions, hooks, apiKeyHelper 等大多數鍵值都能在執行中的 session 立即套用。model 與 outputStyle 則只在下次重啟或 /clear 時套用。

settings.json 支援上百個設定鍵, 依主題分類瀏覽以下代表性設定 (完整清單請見原始文件的 Available settings 表格)。

進階沙盒行為設定, 隔離 Bash 指令的檔案系統與網路存取。

sandbox.enabled
啟用 bash 沙盒 (macOS, Linux, WSL2), 預設 false
sandbox.autoAllowBashIfSandboxed
沙盒化時自動核准 bash 指令, 預設 true
sandbox.filesystem.allowWrite / denyWrite
額外允許或禁止寫入的路徑, 跨範圍合併
sandbox.network.allowedDomains / deniedDomains
允許或封鎖出站網路流量的網域, 支援萬用字元
credentials.files / envVars
禁止沙盒讀取的憑證檔案或環境變數
network.httpProxyPort / socksProxyPort
自備代理伺服器的埠號
{
  "sandbox": {
    "enabled": true,
    "filesystem": { "allowWrite": ["/tmp/build", "~/.kube"] },
    "network": { "allowedDomains": ["github.com", "*.npmjs.org"] }
  }
}
重要

filesystem 與 network 限制可透過 sandbox 設定 (OS 層級沙盒邊界) 或權限規則 (Edit/Read/WebFetch allow deny) 兩種方式設定, 兩者會合併生效。

歸屬設定 (Attribution)

Git commit 與 PR 說明的歸屬文字可分別設定, commit 預設使用 git trailer。

# 預設 commit 歸屬
Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>
attribution.commit
commit 的歸屬文字, 空字串隱藏
attribution.pr
PR 說明的歸屬文字, 空字串隱藏
attribution.sessionUrl
是否附加 claude.ai session 連結, 預設 true

檔案建議設定

為 @ 檔案路徑自動完成設定自訂指令, 大型 monorepo 適合用專案專屬索引取代預設的檔案系統遍歷。

{
  "fileSuggestion": { "type": "command", "command": "~/.claude/file-suggestion.sh" }
}

指令透過 stdin 收到 {"query": "..."}, 輸出換行分隔的檔案路徑 (最多 15 筆) 到 stdout。

Footer link badges

footerLinksRegexes 設定會在輸入框下方頁尾渲染可點擊的徽章, 把專案 CLI 印出的 ID (例如審查工具或問題追蹤器) 轉成 session 連結。

{
  "footerLinksRegexes": [{
    "type": "regex",
    "pattern": "\\b(?<key>PROJ-\\d+)\\b",
    "url": "https://issues.example.com/browse/{key}",
    "label": "{key}"
  }]
}
URL 長度上限
超過 2048 字元的組成網址會被捨棄
徽章數量上限
最多顯示 5 個, 最舊的會被新符合項目取代
設定範圍
僅讀取自 user settings, --settings 旗標, managed settings

Hook 設定

allowManagedHooksOnly
為 true 時只載入 managed/SDK hooks 與強制啟用外掛的 hooks
allowedHttpHookUrls
HTTP hook 可鎖定的網址白名單, 支援萬用字元
httpHookAllowedEnvVars
HTTP hook 可內插進標頭的環境變數名稱白名單

設定優先順序細節

Managed 層內部還有子順序: policyHelper 輸出 (若設定, 為唯一來源) > remote > MDM/OS 政策 > 檔案式 > HKCU 登錄檔 (僅 Windows)。

陣列合併

相同的陣列型設定 (如 permissions.allow) 出現在多個範圍時, 會被串接並去除重複, 而非互相取代, 讓較低優先層級可以新增項目而不覆寫較高層級。fallbackModel 與部分情境下的 availableModels 是例外, 採用最高優先層級的完整值。

驗證目前生效的設定

在 Claude Code 中執行 /status 查看目前生效的設定來源, Status 分頁的 Setting sources 會列出每個已載入的層級, managed settings 會額外標示傳遞管道, 例如 (remote), (plist), (HKLM), (HKCU), (file)。設定檔若有錯誤, /status 會列出受影響的檔案, 執行 /doctor 查看細節。

系統提示詞與敏感檔案

Claude Code 的內部系統提示詞未公開, 若要加入自訂指示, 使用 CLAUDE.md 檔案或 --append-system-prompt 旗標。要排除敏感檔案 (API 金鑰, 密鑰, 環境檔), 在 permissions.deny 中設定:

{
  "permissions": {
    "deny": ["Read(./.env)", "Read(./secrets/**)", "Read(./config/credentials.json)"]
  }
}

子代理設定 (Subagent Configuration)

Claude Code 支援可在使用者與專案層級設定的自訂 AI 子代理, 這些子代理以帶有 YAML frontmatter 的 Markdown 檔案儲存。

User subagents
~/.claude/agents/, 適用於你所有的專案
Project subagents
.claude/agents/, 特定於此專案並可與團隊共享

子代理檔案定義具備自訂提示詞與工具權限的專門化 AI 助理。

外掛設定 (Plugin Configuration)

Claude Code 支援外掛系統, 讓你用 skills, agents, hooks, MCP 伺服器擴充功能, 外掛透過 marketplace 發佈, 可在使用者與儲存庫層級設定。

{
  "enabledPlugins": {
    "formatter@acme-tools": true,
    "deployer@acme-tools": true,
    "analyzer@security-plugins": false
  },
  "extraKnownMarketplaces": {
    "acme-tools": { "source": { "source": "github", "repo": "acme-corp/claude-plugins" } }
  }
}

管理外掛

使用 /plugin 指令互動管理外掛:

瀏覽從 marketplace 瀏覽可用外掛
安裝/移除安裝或解除安裝外掛
啟用/停用切換外掛的啟用狀態
檢視細節檢視外掛提供的 skills, agents, hooks
Marketplace 管理新增或移除 marketplace 來源

環境變數

環境變數讓你不需編輯設定檔就能控制 Claude Code 的行為, 任何變數也能在 settings.json 的 env 鍵下設定, 套用到每個 session 或推行給整個團隊。

完整清單請見環境變數參考文件。

Claude 可用的工具

Claude Code 提供一組工具供讀取, 編輯, 搜尋, 執行指令, 與協調子代理。工具名稱就是你在權限規則與 hook matcher 中使用的確切字串。
