探索 .claude 目錄

Claude Code 從專案目錄與家目錄下的 .claude 讀取指令, 設定, hooks, skills, commands, subagents, workflows, rules 以及自動記憶。這份課程帶你逐一認識這些檔案的用途, 何時載入, 以及範例寫法。

基本觀念

Claude Code 會從兩個位置讀取設定: 專案目錄 (通常是 repo 根目錄或 .claude/) 以及家目錄的 ~/.claude。把專案檔案 commit 進 git 可以與團隊共享, 而 ~/.claude 內的檔案屬於你個人, 會套用到所有專案。

平台差異

在 Windows 上, ~/.claude 會對應到 %USERPROFILE%\.claude。若你設定了 CLAUDE_CONFIG_DIR 環境變數, 本頁提到的所有 ~/.claude 路徑都會改到該目錄之下。

多數使用者只需要編輯 CLAUDE.md 與 settings.json。目錄裡其餘的檔案都是選用的, 需要時再加入 skills, rules 或 subagents 即可。

CLAUDE.local.md專案根目錄
你個人在此專案的私人偏好設定, 與 CLAUDE.md 一起載入。需要自行建立並加入 .gitignore。
已安裝的 plugins~/.claude/plugins
已 clone 的 marketplace, 已安裝的 plugin 版本與各 plugin 的資料, 由 claude plugin 指令管理。孤兒版本會在更新或移除後 7 天被刪除。

~/.claude 同時也存放 Claude Code 在工作過程中寫入的資料: 逐字稿, 提示歷史, 檔案快照, 快取與紀錄檔, 詳見下方的「應用程式資料」章節。

該編輯哪個檔案

不同類型的自訂內容會放在不同的檔案裡。用下表找到你要修改的位置。

給 Claude 專案脈絡與慣例編輯 CLAUDE.md (project 或 global)
允許或封鎖特定工具呼叫編輯 settings.json 的 permissions 或 hooks
在工具呼叫前後執行腳本編輯 settings.json 的 hooks
設定 session 的環境變數編輯 settings.json 的 env
讓個人覆寫設定不進 git編輯 settings.local.json (僅限 project)
新增以 /name 呼叫的提示或能力建立 skills/<name>/SKILL.md
定義擁有自己工具的專屬 subagent建立 agents/*.md
用腳本協調多個 subagent建立 workflows/*.js
透過 MCP 連接外部工具編輯 .mcp.json (僅限 project)
改變 Claude 的回覆格式建立 output-styles/*.md

應用程式資料

除了你自己撰寫的設定之外, ~/.claude 還存放 Claude Code 在工作過程中寫入的資料。這些檔案都是純文字, 任何經過工具的內容 (檔案內容, 指令輸出, 貼上的文字) 都會被寫進逐字稿。

1 · 自動清除
2 · 永久保留
3 · 明文儲存
4 · 清除本機資料

以下路徑中的檔案, 只要超過 cleanupPeriodDays 設定的天數 (預設 30 天), 會在啟動時自動刪除。

projects/<project>/<session>.jsonl
完整對話逐字稿: 每則訊息, 工具呼叫與結果
.../subagents/
Subagent 對話逐字稿, 隨父 session 逐字稿一起過期刪除
.../tool-results/
過大的工具輸出會被獨立存成檔案
file-history/<session>/
Claude 修改檔案前的快照, 用於 checkpoint 還原
plans/
Plan mode 期間寫入的規劃檔案
debug/
每個 session 的除錯紀錄, 只在 --debug 或 /debug 時才寫入
paste-cache/, image-cache/
大型貼上內容與附加圖片的快取
shell-snapshots/
Bash 工具使用的 shell 環境快照, 正常結束時會移除
feedback-bundles/
/feedback 在第三方 provider 上寫入的去識別化逐字稿封包

下列路徑不受自動清除機制影響, 會一直保留到你自行刪除。

history.jsonl
你輸入過的每個提示, 含時間戳與專案路徑, 供上下鍵回顧使用
stats-cache.json
/usage 顯示的累計 token 與費用統計
remote-settings.json
組織的 server-managed settings 快取副本, 每次啟動時刷新
安全提醒

逐字稿與歷史紀錄並未加密儲存, 只靠作業系統的檔案權限保護。若工具讀取了 .env 檔案或指令印出了憑證, 該值就會被寫入 projects/<project>/<session>.jsonl。

  • 調低 cleanupPeriodDays 縮短逐字稿保留時間
  • 設定 CLAUDE_CODE_SKIP_PROMPT_HISTORY 環境變數, 在任何模式下都不寫入逐字稿與提示歷史; 非互動模式下也可搭配 -p 使用 --no-session-persistence, 或在 Agent SDK 中設定 persistSession: false
  • 使用 permission 規則封鎖讀取憑證檔案

執行 claude project purge 可以刪除 Claude Code 為某個專案保留的狀態 (需要 v2.1.124 以上), 會刪除: projects/ 下的逐字稿與自動記憶, 每個 session 的 tasks/, debug/, file-history/ 項目, history.jsonl 中相符的紀錄, 以及 ~/.claude.json 中該專案的項目。

# 預覽刪除計畫, 不實際刪除
claude project purge ~/work/my-repo --dry-run

# 單次確認後刪除
claude project purge ~/work/my-repo

# 略過確認, 適合腳本使用
claude project purge ~/work/my-repo --yes

省略路徑會跳出互動式清單讓你挑選專案; 用 --all 取代路徑可一次清除所有專案 (此時會直接刪除整份 history.jsonl 而非過濾); 加上 -i 可以逐項確認刪除計畫。此指令不會動到 shell-snapshots/ 與 backups/, 因為它們不屬於特定專案。

Step 1 of 4

不要刪除 ~/.claude.json, ~/.claude/settings.json, 或 ~/.claude/plugins/, 這些檔案保存了你的登入狀態, 偏好設定與已安裝的 plugins。
