Model configuration

Learn about the Claude Code model configuration, including model aliases like opusplan.

Available models

For the model setting you can configure a model alias, or a model name: a full Anthropic API model name, a Bedrock inference profile ARN, a Microsoft Foundry deployment name, or a Google Cloud Agent Platform version name.

Model aliases

default
Clears any override, reverts to the recommended model or org default
best
Fable 5 where available, otherwise the latest Opus
fable
Claude Fable 5, hardest and longest-running tasks
sonnet
Latest Sonnet model for daily coding tasks
opus
Latest Opus model for complex reasoning
haiku
Fast and efficient model for simple tasks
sonnet[1m] / opus[1m]
1 million token context window for long sessions
opusplan
opus during plan mode, then switches to sonnet for execution
NOTE

Where an alias resolves to an older model, newer models are available by selecting the full model name explicitly or setting ANTHROPIC_DEFAULT_OPUS_MODEL / ANTHROPIC_DEFAULT_SONNET_MODEL. Sonnet 5 requires Claude Code v2.1.197+, Opus 4.8 requires v2.1.154+.

Work with Fable 5

Claude Fable 5 is the most capable model in Claude Code, suited to tasks larger than a single sitting. It sustains long autonomous sessions, investigates before acting, and verifies its work more often. Not the default model, select it with /model fable.

Restrict model selection

Enterprise administrators use availableModels in managed or policy settings to restrict which models users can select. Entries match a model family, a version prefix, or a full model ID.

{
  "availableModels": ["sonnet", "haiku"]
}

Surface coverage

Server-managed
Enforced on CLI/IDE, Desktop, web/mobile/cloud, Agent SDK. Not delivered to Cowork
MDM / managed file
Enforced on CLI/IDE, Desktop. Not delivered to web/mobile/cloud sessions

Enforce the allowlist for Default

{
  "availableModels": ["sonnet", "haiku"],
  "enforceAvailableModels": true
}

Without enforceAvailableModels, the Default option resolves to the account-type default regardless of the allowlist. With it, Default resolves to the first allowlist entry that names an allowed, available model.

Organization model restrictions

Enterprise admins disable individual models in the admin console. Delivered with account entitlements. Haiku models can never be disabled.

Merge behavior

When the highest-precedence managed source defines availableModels, that list alone applies. Otherwise lists from user, project, and local settings are concatenated and deduplicated.

Organization default model

Enterprise admins can set a default model for the whole organization or per custom role, requiring Claude Code v2.1.196+. The Default row shows Org default. Any other model selection takes precedence: the --model flag, ANTHROPIC_MODEL, or a model value in settings.

OVERRIDE

With override on, the org default takes precedence over user, project, and local settings, so a model saved with /model applies only for the current session and the org default returns on the next launch.

Organization effort limits

Enterprise admins can set a maximum effort level per model for each custom role. Levels above the cap aren't offered in the /effort picker; naming a higher level runs at the cap instead. Requires Claude Code v2.1.195+.

Fallback model chains

When the primary model is overloaded, unavailable, or returns a non-retryable server error, Claude Code can switch to a fallback model. Chains are capped at three models after duplicate removal.

claude --fallback-model sonnet,haiku
{
  "fallbackModel": ["claude-sonnet-5", "claude-haiku-4-5"]
}

Automatic model fallback

Fable 5 runs with safety classifiers for cybersecurity and biology content. When flagged, Claude Code re-runs the request on Opus 4.8. To decide each time instead, run /config and turn off "switch models when a message is flagged".

CHECK

Fallback can trigger on the first request of a session because it carries workspace context such as CLAUDE.md and git status. Start with claude --safe-mode to check whether customizations are the trigger.

Checking your current model

You can see which model you're currently using in the status line, if configured, or in /status, which also displays your account information.

Add a custom model option

Use ANTHROPIC_CUSTOM_MODEL_OPTION to add a single custom entry to the /model picker without replacing the built-in aliases.

export ANTHROPIC_CUSTOM_MODEL_OPTION="my-gateway/claude-opus-4-8"
export ANTHROPIC_CUSTOM_MODEL_OPTION_NAME="Opus via Gateway"
export ANTHROPIC_CUSTOM_MODEL_OPTION_DESCRIPTION="Custom deployment routed through the internal LLM gateway"

Environment variables

ANTHROPIC_DEFAULT_FABLE_MODEL
Model used for fable and Fable 5 identification
ANTHROPIC_DEFAULT_OPUS_MODEL
Model for opus, or opusplan in Plan Mode
ANTHROPIC_DEFAULT_SONNET_MODEL
Model for sonnet, or opusplan outside Plan Mode
CLAUDE_CODE_SUBAGENT_MODEL
Model for all subagents and agent teams

Adjust effort level

Effort levels control adaptive reasoning: lower effort is faster and cheaper, higher effort provides deeper reasoning.

high
Balances token usage and intelligence. Default on Fable 5, Sonnet 5, Opus 4.8, Opus 4.6, and Sonnet 4.6.

Prompt caching configuration

DISABLE_PROMPT_CACHING
Disable for all models, takes precedence over per-model settings
DISABLE_PROMPT_CACHING_HAIKU
Disable for Haiku models only
DISABLE_PROMPT_CACHING_SONNET
Disable for Sonnet models only
DISABLE_PROMPT_CACHING_OPUS
Disable for Opus models only

Third-party deployments (Bedrock, Google Cloud's Agent Platform, Microsoft Foundry, Claude Platform on AWS) should pin model versions with these environment variables before rollout, since aliases resolve to a built-in default that can lag the newest release. Use modelOverrides to map individual model IDs to provider-specific strings for governance or regional routing.
