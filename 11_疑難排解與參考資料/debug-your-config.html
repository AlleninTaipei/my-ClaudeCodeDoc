Debug your configuration

診斷為什麼 CLAUDE.md, settings, hooks, MCP servers, 或 skills 沒有生效, 學會用 /context, /doctor, /hooks, /mcp 檢查實際載入了什麼

檢視目前載入到 context 中的內容

/context 會顯示目前 session 中 context window 被哪些類別佔用: system prompt, memory files, skills, MCP tools, 對話訊息。先執行這個指令確認 CLAUDE.md, rules, skill 描述是否真的存在。

NOTE

CLAUDE.md 和 permissions 解決的是不同問題。CLAUDE.md 告訴 Claude 專案如何運作以便做出好決策; permissions 與 hooks 則不論 Claude 決定什麼都強制限制。CLAUDE.md 用於「我們這裡是這樣做的」, permissions 或 hooks 用於安全邊界與絕不能發生的事情。

檢查解析後的設定 (Check resolved settings)

Settings 會跨 managed, user, project, local 四個範圍合併。Managed settings 永遠優先, 其餘範圍中越接近的範圍 (local, project, user 依序) 會覆蓋越外層的範圍。CLI flags 與環境變數則是另一層覆蓋。

/doctor驗證設定檔, 找出無效的 key 或 schema 錯誤, 按 f 可將診斷報告傳給 Claude 一起修
/status顯示哪些設定來源生效中, 包含 managed settings 是否生效

當某個設定值似乎沒生效時, 通常是被另一個範圍或某個環境變數覆蓋掉了。

檢查 MCP servers

執行 /mcp 查看每個已設定的 server, 連線狀態, 以及目前專案是否已核准。伺服器定義正確卻仍拿不到工具, 常見原因如下:

一次性核准未通過
.mcp.json 中的專案範圍 server 需要手動核准一次, 若提示被關掉就會保持停用直到你在 /mcp 中核准
相對路徑
command 或 args 使用相對路徑, 會相對於啟動 Claude Code 的目錄解析, 而非 .mcp.json 所在位置
已連線但 0 個工具
在 /mcp 選 Reconnect, 若仍是 0 個, 執行 claude --debug mcp 查看 server 的 stderr 輸出

檢查 hooks

執行 /hooks 列出目前 session 依事件分組的所有 hook。若定義的 hook 沒出現, 代表沒被讀到: hook 必須寫在 settings 檔中的 "hooks" key 下, 而不是獨立檔案。

// 正確的 matcher 寫法, 使用 | 分隔多個工具名稱
{
  "matcher": "Edit|Write"
}
常見錯誤

matcher 若寫成 JSON 陣列會是 schema 錯誤; matcher 小寫 (如 "bash") 不會比對成功, 因為比對是區分大小寫的, 工具名稱要用 Bash, Edit, Write, Read。

若 /hooks 有顯示 hook 但仍未觸發, 用 claude --debug hooks 啟動 session 並觸發該工具呼叫, debug log 會記錄每個事件, 檢查了哪些 matcher, 以及 hook 的結束碼與輸出。

在乾淨的設定下測試

1 · Safe mode
2 · 乾淨的設定目錄

用 claude --safe-mode 啟動, 會停用所有客製化項目, 包含 CLAUDE.md, skills, plugins, hooks, MCP servers, 自訂指令與 agents。認證, 模型選擇, 內建工具, permissions 仍正常運作。若問題在 safe mode 下消失, 代表就是上述其中一項造成的, 再用前面的檢查逐一排除。

注意

組織部署的 managed settings 仍會部分套用, 因此政策設定的 hooks 與 status line 即使在 safe mode 下也會執行。

若 safe mode 下問題依然存在, 或懷疑 settings 本身有問題, 可以對照一個完全不載入平常設定的 session。將 CLAUDE_CONFIG_DIR 指向空目錄, 並從沒有 .claude 資料夾的目錄啟動:

cd /tmp && CLAUDE_CONFIG_DIR=/tmp/claude-clean claude

這個乾淨 session 沒有 user 或 project settings, hooks, MCP servers, plugins, 或 memory。若問題在這裡消失, 原因就在你原本的 ~/.claude 或專案 .claude 檔案中, 逐一放回檔案來找出是哪一個。
