Error reference

查詢 Claude Code 執行期的錯誤訊息, 了解每一則代表什麼意義以及如何修復。這些錯誤與復原方式適用於 CLI, Desktop app, 以及 Claude Code on the web, 因為三者都包裝同一個 Claude Code CLI。

自動重試機制

Claude Code 在顯示錯誤前, 會先自動重試暫時性失敗。伺服器錯誤, overloaded 回應, request timeout, 暫時性 429 節流, 以及斷線, 都會以指數退避方式重試最多 10 次。當你看到本頁列出的錯誤時, 代表這些重試已經用盡。

CLAUDE_CODE_MAX_RETRIES
重試次數, 預設 10, v2.1.186 起上限為 15
CLAUDE_CODE_RETRY_WATCHDOG
在無人值守的 session (如 CI) 設為 1, 對 429/529 容量錯誤無限重試而非在達到上限後失敗
API_TIMEOUT_MS
每個請求的逾時毫秒數, 預設 600000, 網路慢或走 proxy 時可調高

回應品質似乎變差時該檢查什麼

若沒有錯誤訊息但回答品質不如預期, 通常是對話狀態而非模型本身的問題。Claude Code 不會悄悄切換模型版本, 只有三種特定情況會 fallback。

模型選擇
執行 /model 確認目前用的模型, 先前的選擇或 ANTHROPIC_MODEL 可能讓你停在較小的模型上
Effort 等級
執行 /effort 檢查目前推理等級, 困難的除錯或設計工作可調高
Context 壓力
執行 /context 查看視窗使用狀況, 接近上限時執行 /compact 或 /clear
過時的指令
過大或過時的 CLAUDE.md 與 MCP 工具定義會佔用 context 並影響回應, /doctor 會標記過大的 memory 檔案

回應出錯時, rewind 通常比在對話中糾正更有效。按兩下 Esc 或執行 /rewind 回到錯誤發生前, 再用更具體的說法重新描述, 避免錯誤的嘗試殘留在 context 中影響後續回答。

回報錯誤

本頁涵蓋來自 Claude API 的錯誤。其他 Claude Code 元件的錯誤請見對應指南: MCP server 連線或認證失敗見 MCP 頁面, hook 腳本失敗見 Debug hooks, 安裝時的權限或檔案系統錯誤見 Troubleshoot installation。

仍未解決

執行 /feedback 將逐字稿與描述送給 Anthropic, 該指令也會提供開啟預填 GitHub issue 的選項。也可以執行 /doctor 檢查本機設定問題, 或查看 status.claude.com 的服務事件。
