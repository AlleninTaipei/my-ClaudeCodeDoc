Access analytics for Team and Enterprise

Navigate to claude.ai/analytics/claude-code. Admins and Owners can view the dashboard, which includes usage metrics (lines accepted, suggestion accept rate, daily active users and sessions), contribution metrics (PRs and lines shipped with Claude Code assistance, via GitHub integration), a leaderboard of top contributors, and CSV data export. For per-user token counts and cost estimates, configure OpenTelemetry export.

Enable contribution metrics

BETA

Contribution metrics are in public beta, available on Team and Enterprise plans, and only cover users within your claude.ai organization — usage through the Console API or third-party integrations is not included.

ZDR

Contribution metrics are not available for organizations with Zero Data Retention enabled — the dashboard shows usage metrics only.

You need the Owner role to configure analytics settings, and a GitHub admin must install the GitHub app. Four steps:

1 · Install app
2 · Enable analytics
3 · Enable GitHub
4 · Authenticate

A GitHub admin installs the Claude GitHub app on your organization's GitHub account at github.com/apps/claude.

A Claude Owner navigates to claude.ai/admin-settings/claude-code and enables the Claude Code analytics feature.

On the same page, enable the "GitHub analytics" toggle.

Complete the GitHub authentication flow and select which GitHub organizations to include in the analysis.

Step 1 of 4

Data typically appears within 24 hours, with daily updates. If no data appears you may see "GitHub app required" (install the app) or "Data processing in progress" (check back in a few days). Supports GitHub Cloud and GitHub Enterprise Server.

Review summary metrics

NOTE

These metrics are deliberately conservative — an underestimate of Claude Code's actual impact. Only lines and PRs with high confidence in Claude Code's involvement are counted.

PRs with CC
Total merged pull requests containing at least one line of code written with Claude Code.
Lines of code with CC
Total "effective lines" across merged PRs written with Claude Code — lines with more than 3 characters after normalization, excluding empty lines and trivial punctuation.
PRs with Claude Code (%)
Percentage of all merged PRs containing Claude Code-assisted code.
Suggestion accept rate
Percentage of times users accept Claude Code's editing suggestions, including Edit, Write, and NotebookEdit usage.
Lines of code accepted
Total lines written by Claude Code that users accepted in their sessions. Excludes rejected suggestions and later deletions.

PR attribution

When contribution metrics are enabled, Claude Code analyzes merged pull requests to determine which code was written with its assistance, by matching session activity against the code in each PR.

Tagging criteria
PRs are tagged "with Claude Code" if they contain at least one line written during a session, using conservative matching — only high-confidence involvement counts.
Attribution process
Added PR-diff lines are extracted, matching sessions within a time window are identified, lines are matched against session output, then metrics are calculated. Lines are normalized first: whitespace trimmed, quotes standardized, lowercased. Merged PRs are labeled claude-code-assisted in GitHub.
Time window
Sessions from 21 days before to 2 days after the PR merge date are considered.
Excluded files
Lock files, generated code, build directories, test fixtures/snapshots, and lines over 1,000 characters (likely minified) are excluded automatically.

Additional notes: code rewritten by developers by more than 20% is not attributed to Claude Code; sessions outside the 21-day window are not considered; the algorithm ignores the PR's source or destination branch.

Get the most from analytics

Monitor adoption via the Adoption chart to find active users who can share best practices and spot usage dips that may signal friction. Measure ROI with contribution metrics, tracking PRs-per-user over time and comparing PRs/lines shipped with vs. without Claude Code, alongside DORA metrics or sprint velocity. Identify power users via the Leaderboard to find people who can share prompting techniques and help onboard others. Access data programmatically by searching GitHub for PRs labeled claude-code-assisted.

Access analytics for API customers

API customers using the Claude Console access analytics at platform.claude.com/claude-code. You need the UsageView permission, granted to Developer, Billing, Admin, Owner, and Primary Owner roles.

NOTE

Contribution metrics with GitHub integration are not currently available for API customers — the Console dashboard shows usage and spend metrics only.

Lines of code accepted
Total lines written by Claude Code that users accepted in their sessions. Excludes rejected suggestions and later deletions.
Suggestion accept rate
Percentage of times users accept code editing tool usage (Edit, Write, NotebookEdit).
Activity
Daily active users and sessions shown on a chart.
Spend
Daily API costs in dollars alongside user count.

View team insights

The team insights table shows per-user metrics:

•Members — all users who have authenticated to Claude Code. API key users display by key identifier, OAuth users by email.
•Spend this month — per-user total API costs for the current month.
•Lines this month — per-user total of accepted code lines for the current month.
NOTE

Spend figures in the Console dashboard are estimates for analytics purposes. Refer to your billing page for actual costs.
