Claude Code 如何使用 Prompt Caching

了解為何切換模型會觸發較慢的未快取回合, /compact 要付出什麼代價, 為何 CLAUDE.md 編輯不會即時套用, 以及如何檢查快取命中率.

快取如何組織

每次送出訊息都會產生新的 API 請求, 模型不會記得請求之間的內容, 因此 Claude Code 會重送完整上下文. API 依請求開頭 (稱為 prefix) 比對最近處理過的內容, 比對是精確的, prefix 中任何位置的變動都會導致之後的內容全部重新計算.

System prompt
核心指令, 工具定義, 輸出風格; 工具定義集合改變或 Claude Code 升級時變動
Project context
CLAUDE.md, auto memory, 未限定範圍的規則; session 開始或 /clear /compact 後變動
Conversation
你的訊息, Claude 的回應, 工具結果; 每個回合都會變動
額外的快取鍵

模型與 effort level 也是快取鍵的一部分但不屬於 prompt 文字本身, 切換模型或 effort level 都會導致整個請求重新計算.

快取存續時間 (TTL)

快取過的 prefix 會在閒置一段時間後過期, 每次命中快取都會重設計時器.

1 · Claude 訂閱
2 · API key / 第三方
3 · 覆寫 TTL

Claude Code 自動要求一小時 TTL, 用量計入方案而非按 token 計費, 較長的 TTL 不會產生額外費用. 若已超過方案限制並開始使用 usage credits, 則自動降回五分鐘.

使用 API key, Bedrock, Vertex, Foundry 或 Claude Platform on AWS 時預設維持五分鐘 TTL, 設定 ENABLE_PROMPT_CACHING_1H=1 可選用一小時 TTL.

設定 FORCE_PROMPT_CACHING_5M=1 可強制使用五分鐘 TTL, 常用於除錯快取行為或比較兩種 TTL.

cache_creation_input_tokens
本回合寫入快取的 token 數, 以快取寫入費率計費
cache_read_input_tokens
本回合從快取讀取的 token 數, 費率約為標準輸入的 10%

高讀取對建立比表示快取運作良好. 若建立數持續偏高, 表示 prefix 中有內容持續變動, 對照上方會讓快取失效的動作清單找出原因.

Subagent 與快取

Subagent 會啟動自己的對話, 有自己的 system prompt 與工具集, 建立自己的快取, 對父層的快取沒有影響. Fork 則不同, 它會完整繼承父層的 system prompt, 工具與對話歷史, 因此第一個請求就能讀取父層的快取.

停用 Prompt Caching

DISABLE_PROMPT_CACHING
停用所有模型的快取
DISABLE_PROMPT_CACHING_HAIKU
只停用 Haiku 的快取
DISABLE_PROMPT_CACHING_SONNET
只停用 Sonnet 的快取
DISABLE_PROMPT_CACHING_OPUS
只停用 Opus 的快取
