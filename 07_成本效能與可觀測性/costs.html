速率限制建議 (依團隊規模)

Agent Team Token 成本

每個 teammate 都有自己的 context window, 用量大致與團隊規模成正比. 建議使用 Sonnet, 保持小團隊, spawn prompt 精簡, 並在完成後關閉 teammate.

Bedrock / Vertex / Foundry

Claude Code 不會從雲端傳送指標. 自架 Claude apps gateway 可提供逐使用者的用量歸屬與支出上限.

降低 Token 用量

Token 成本隨 context 大小增加. Claude Code 會透過 prompt caching 與 auto-compaction 自動最佳化成本, 以下策略能進一步縮小 context.

主動管理 context切換任務時用 /clear, 用 /compact 加上自訂保留重點的指示
選擇合適的模型Sonnet 處理大多數任務, Opus 保留給複雜架構決策
降低 MCP 額外負擔工具定義預設延遲載入, 優先使用 CLI 工具如 gh, aws, gcloud
安裝程式碼智慧外掛提供精確符號導覽, 減少不必要的檔案讀取
交給 hooks 與 skills 前處理用 hook 過濾大型 log 檔案, 用 skill 提供領域知識減少探索
CLAUDE.md 精簡將特定工作流程指示移至 skills, 讓 CLAUDE.md 維持在 200 行以內
調整 extended thinking簡單任務可用 /effort 降低推理深度或關閉 thinking
委派給 subagent執行測試, 抓取文件或處理 log 時把冗長輸出留在 subagent

寫出具體的提示詞

模糊的請求如「改善這個程式碼庫」會觸發大範圍掃描. 具體的請求如「在 auth.ts 的登入函式加入輸入驗證」讓 Claude 更有效率地工作.

模糊: 大範圍掃描具體: 精準最小讀取
