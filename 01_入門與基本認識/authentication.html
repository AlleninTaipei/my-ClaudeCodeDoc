Authentication

認識 Claude Code 對個人, 團隊與企業提供的多種驗證方式, 以及憑證儲存與優先順序機制

登入 Claude Code

安裝 Claude Code 後, 在終端機執行 claude. 第一次啟動時, Claude Code 會開啟瀏覽器視窗讓你登入. 若瀏覽器沒有自動開啟, 按下 c 複製登入網址後貼到瀏覽器. 若瀏覽器顯示登入代碼而非自動導回, 將代碼貼到終端機的提示欄位, 這常發生在 WSL2, SSH session 與容器環境中.

選擇帳號類型 :
Claude Pro / Max
Teams / Enterprise
Claude Console
雲端供應商
雲端閘道
SUBSCRIPTION

使用 Claude.ai 帳號登入. 於 claude.com/pricing 訂閱 Claude Pro 或 Max 方案即可使用.

TEAM

使用團隊管理員邀請你加入的 Claude.ai 帳號登入.

CONSOLE

使用 Console 憑證登入, 管理員必須先邀請你.

CLOUD

若組織使用 Amazon Bedrock, Google Vertex AI 或 Microsoft Foundry, 執行 claude 前先設定所需環境變數, 不需要瀏覽器登入.

GATEWAY

若組織自架 Claude apps gateway, 透過 /login 以企業 SSO 登入, 該 gateway 核發的 token 會是此 session 唯一的憑證.

要登出並重新驗證, 在 Claude Code 提示字元輸入 /logout 即可.

設定團隊驗證

針對團隊與組織, 可透過以下方式之一設定 Claude Code 存取權限.

選擇設定方式 :
Claude for Teams / Enterprise
Claude Console
雲端供應商

Claude for Teams 是自助方案, 具備協作功能, 管理工具與帳務管理, 適合較小型團隊. Claude for Enterprise 則新增 SSO, 網域驗證, 角色權限, 合規 API 與集中式政策設定, 適合對安全與合規有較高需求的大型組織.

Step 1訂閱 Claude for Teams, 或聯繫業務洽談 Claude for Enterprise.
Step 2從管理後台邀請團隊成員.
Step 3團隊成員安裝 Claude Code 並以 Claude.ai 帳號登入.

適合偏好以 API 計費的組織, 透過 Claude Console 設定存取權限.

Step 1使用現有 Console 帳號, 或建立新帳號.
Step 2透過 Console 內 Settings → Members → Invite 大量邀請使用者, 或設定 SSO.
Step 3邀請時指派角色: Claude Code 角色僅能建立 Claude Code API key, Developer 角色可建立任何類型的 API key.
Step 4受邀使用者接受邀請, 確認系統需求, 安裝 Claude Code, 並以 Console 帳號憑證登入.

適合使用 Amazon Bedrock, Google Vertex AI 或 Microsoft Foundry 的團隊.

Step 1依照 Bedrock, Vertex 或 Microsoft Foundry 文件完成供應商端設定.
Step 2將環境變數與雲端憑證產生方式分發給使用者.
Step 3使用者安裝 Claude Code 即可使用.

憑證管理

Claude Code 會安全地管理你的驗證憑證, 儲存位置依作業系統而異.

macOS
Linux
Windows
儲存位置加密的 macOS Keychain
儲存位置~/.claude/.credentials.json, 檔案權限為 0600
儲存位置%USERPROFILE%\.claude\.credentials.json, 繼承使用者設定檔目錄的存取控制, 預設僅限本機使用者帳號存取
NOTE

若設定了 CLAUDE_CONFIG_DIR 環境變數 (Linux 或 Windows), .credentials.json 會改存放於該目錄下. 支援的驗證型別包含 Claude.ai 憑證, Claude API 憑證, Azure Auth, Bedrock Auth, Vertex Auth, 以及 Claude apps gateway 的 session token. 可透過 apiKeyHelper 設定自訂憑證腳本; 預設每 5 分鐘或收到 HTTP 401 時會重新呼叫, 也可用 CLAUDE_CODE_API_KEY_HELPER_TTL_MS 自訂間隔. 若 apiKeyHelper 執行超過 10 秒, 提示列會顯示警示.

驗證優先順序

當環境中存在多組憑證時, Claude Code 依下列順序選擇使用:

1. 雲端供應商當 CLAUDE_CODE_USE_BEDROCK, CLAUDE_CODE_USE_VERTEX 或 CLAUDE_CODE_USE_FOUNDRY 已設定時.
2. ANTHROPIC_AUTH_TOKEN以 Authorization: Bearer header 送出, 適用於透過 LLM gateway 或 proxy 路由的情境.
3. ANTHROPIC_API_KEY以 X-Api-Key header 送出, 適用於直接存取 Anthropic API.
4. apiKeyHelper腳本輸出結果, 適用於動態或輪替憑證, 例如從密碼庫取得的短效 token.
5. CLAUDE_CODE_OAUTH_TOKEN由 claude setup-token 產生的長效 OAuth token, 適用於無法瀏覽器登入的 CI 流程.
6. 訂閱 OAuth 憑證來自 /login, 是 Claude Pro, Max, Team, Enterprise 使用者的預設方式.
EXCEPTION

已登入的 Claude apps gateway session 不在此順序之列, 它本身是與 Bedrock, Vertex 同級的供應商選擇, 且優先權高於它們. 若同時設定了 ANTHROPIC_API_KEY 與有效的 Claude 訂閱, 一經核准後 API key 會優先生效, 可執行 unset ANTHROPIC_API_KEY 改回訂閱憑證, 並用 /status 確認目前使用中的驗證方式. Claude Code on the Web 一律使用訂閱憑證, sandbox 環境中的 ANTHROPIC_API_KEY 與 ANTHROPIC_AUTH_TOKEN 不會覆蓋它.

產生長效 token

針對 CI pipeline, 腳本或其他無法互動式瀏覽器登入的環境, 可用 claude setup-token 產生效期一年的 OAuth token.

claude setup-token

此指令會引導完成 OAuth 授權並印出 token, 不會儲存於任何地方, 需自行複製後設定為環境變數.

export CLAUDE_CODE_OAUTH_TOKEN=your-token

此 token 會使用你的 Claude 訂閱進行驗證, 需要 Pro, Max, Team 或 Enterprise 方案, 且僅能用於推論, 無法建立 Remote Control session. Bare mode 不會讀取 CLAUDE_CODE_OAUTH_TOKEN, 若腳本使用 --bare, 請改用 ANTHROPIC_API_KEY 或 apiKeyHelper.
