Claude Code 最佳實踐

從環境設定到跨多個平行 session 擴展工作規模, 這裡整理了讓 Claude Code 發揮最大效益的實用模式。

核心限制: 上下文視窗

Claude Code 是一種代理式編碼環境。不同於等待你發問的聊天機器人, 它能讀取檔案, 執行指令, 進行修改, 並在你觀察, 調整方向或暫時離開時持續自主工作。

大多數最佳實踐都建立在同一個限制之上: Claude 的上下文視窗會很快被填滿, 而效能會隨著填滿程度而下降。單次除錯或程式碼庫探索, 可能就會產生並消耗數萬個 token。

TIP

用自訂狀態列持續追蹤上下文使用量, 並參考 costs 頁面中的策略來降低 token 用量。

給 Claude 一個可驗證工作成果的方法

TIP

給 Claude 一個牠可以自己執行的檢查方式: 測試, 建置, 或用來比對的截圖。這就是「你全程盯著看」和「你可以放心離開」的差別。

沒有可執行的檢查時,「看起來完成了」是唯一的訊號, 你就得自己當那個驗證迴圈。給 Claude 一個能回傳成功或失敗的東西, 迴圈就能自己收斂。

檢查可以有多種把關強度

單一 prompt 內請 Claude 在同一則訊息裡執行檢查並反覆修正
跨 session設成 /goal 條件, 由獨立評估者每輪重新檢查直到成立
確定性關卡用 Stop hook 執行腳本, 檢查不過就不能結束該輪, 連續 8 次會被系統覆寫
第二意見用驗證用 subagent 或 workflow, 讓另一個乾淨的模型嘗試反駁結果

讓 Claude 展示證據而非單純宣稱成功: 測試輸出, 執行的指令與其回傳結果, 或成果截圖。審查證據比自己重新驗證更快, 也適用於你沒有全程盯著的 session。

先探索, 再規劃, 最後才寫程式

TIP

把研究與規劃從實作中分離出來, 避免一開始就解錯問題。

讓 Claude 直接跳去寫程式碼, 可能會產出解決錯誤問題的程式碼。使用 plan mode 把探索和執行分開, 建議的工作流程包含四個階段。

1 · Explore
2 · Plan
3 · Implement
4 · Commit

進入 plan mode。Claude 會讀取檔案並回答問題, 但不做任何修改。

# claude (plan mode)
read /src/auth and understand how we handle sessions and login.
also look at how we manage environment variables for secrets.

請 Claude 產出詳細的實作計畫。按下 Ctrl+G 可在文字編輯器中直接編輯計畫。

# claude (plan mode)
I want to add Google OAuth. What files need to change?
What's the session flow? Create a plan.

切出 plan mode, 讓 Claude 依照計畫寫程式碼, 並對照計畫驗證。

# claude (default mode)
implement the OAuth flow from your plan. write tests for the
callback handler, run the test suite and fix any failures.

請 Claude 用具描述性的訊息提交並開一個 PR。

# claude (default mode)
commit with a descriptive message and open a PR

CLAUDE.md 是 Claude 在每次對話開始時都會讀取的特殊檔案。執行 /init 可依目前專案結構產生初始版本。

# Code style
- Use ES modules (import/export) syntax, not CommonJS (require)
- Destructure imports when possible (eg. import { foo } from 'bar')

# Workflow
- Be sure to typecheck when you're done making a series of code changes
- Prefer running single tests, and not the whole test suite, for performance

預設情況下, Claude Code 會針對可能修改系統的動作要求授權。三種減少中斷的方式: auto mode (分類模型審查), 權限允許清單, 以及 sandboxing (作業系統層級隔離)。

CLI 工具是與外部服務互動時最節省上下文的方式。若使用 GitHub, 安裝 gh CLI。Claude 也擅長學習牠還不熟悉的 CLI 工具。

Use 'foo-cli-tool --help' to learn about foo tool, then use it to solve A, B, C.

透過 MCP 伺服器, 你可以請 Claude 依 issue tracker 實作功能, 查詢資料庫, 分析監控資料, 整合 Figma 設計稿, 並自動化工作流程。執行 claude mcp add 連接外部工具。

Hooks 會在 Claude 工作流程的特定時間點自動執行腳本。不同於僅具建議性質的 CLAUDE.md 指示, hooks 是確定性的, 保證動作一定發生。

Skills 用專案, 團隊或領域特定的資訊擴充 Claude 的知識。Claude 會在相關時自動套用, 也可以用 /skill-name 直接呼叫。

---
name: api-conventions
description: REST API design conventions for our services
---
# API Conventions
- Use kebab-case for URL paths
- Use camelCase for JSON properties

Subagents 在自己的上下文中執行, 擁有自己的一組允許工具, 適合處理需要讀取大量檔案或需要專門聚焦的任務, 又不會弄亂主對話。

Plugins 把 skills, hooks, subagents 與 MCP 伺服器打包成單一可安裝單元, 來自社群與 Anthropic。執行 /plugin 瀏覽市集。

有效溝通

你與 Claude Code 溝通的方式, 會大幅影響結果的品質。

詢問程式庫問題

把 Claude Code 當作資深工程師來提問: 「logging 是怎麼運作的?」「怎麼新增一個 API endpoint?」不需要特殊提示技巧。

讓 Claude 訪談你

針對較大型功能, 先讓 Claude 用 AskUserQuestion 工具訪談你, 涵蓋技術實作, UI/UX, 邊界情境與取捨, 訪談完後寫成完整的 SPEC.md。

管理你的 Session

對話是持久且可回復的, 善用這項特性。

及早修正方向Esc 立即停止, Esc+Esc 或 /rewind 開啟回溯選單, 兩次修正無效就 /clear 重新開始
積極管理上下文/clear 重置, /compact 附加指示決定保留重點, /btw 側問不進入對話紀錄
用 subagent 做調查"use subagents to investigate X" 在獨立上下文探索並回報摘要
用 checkpoint 回溯每則提示都會建立檢查點, 可還原對話, 程式碼或兩者
恢復對話claude --continue 接續最近的 session, claude --resume 從清單挑選

用 claude -p "prompt" 在 CI, pre-commit hook 或腳本中執行 Claude。

# One-off queries
claude -p "Explain what this project does"

# Structured output for scripts
claude -p "List all API endpoints" --output-format json

依你想自己協調多少工作, 挑選合適的平行方式: worktrees, Desktop app, Claude Code on the web, 或 agent teams。

大型遷移或分析任務, 可以把工作分散到多個平行的 Claude 呼叫。

for file in $(cat files.txt); do
  claude -p "Migrate $file from React to Vue. Return OK or FAIL." \
    --allowedTools "Edit,Bash(git commit *)"
done

在把任務視為完成前, 讓 subagent 在乾淨的上下文中審查 diff 並回報缺口。跑久的無人值守任務越久, 獨立檢查就越重要。

避免常見的失敗模式

大雜燴 session修正: 不相關任務之間執行 /clear
不斷重複修正修正: 兩次失敗後 /clear, 用學到的東西寫更好的初始提示
過度膨脹的 CLAUDE.md修正: 無情地精簡, 已經做對的事就刪掉或轉成 hook
信任後才驗證的落差修正: 一律提供驗證方式, 無法驗證就不要出貨
無限探索修正: 縮小調查範圍, 或用 subagent 避免耗盡主上下文

培養你的直覺

本指南中的模式並非鐵律。留意什麼有效: Claude 表現出色時, 注意你做了什麼; Claude 卡住時, 問問為什麼。隨著時間累積, 你會培養出任何指南都無法涵蓋的直覺。
