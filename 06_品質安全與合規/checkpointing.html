Checkpointing 檢查點機制

追蹤, 回溯與摘要 Claude 的編輯與對話, 掌控 session 狀態

檢查點如何運作

在你與 Claude 協作的過程中, 每次編輯之前的程式碼狀態都會被自動記錄下來。這個安全網讓你能夠放心嘗試大規模的變更, 因為隨時都能回到先前的狀態。

自動追蹤

每一次使用者提示都會建立一個新的檢查點; 檢查點會跨 session 保留, 可在恢復的對話中存取; 預設 30 天後隨 session 一併清除 (可調整)。

回溯選單

執行 /rewind, 或在輸入框為空時連按兩下 Esc, 即可開啟回溯選單。選擇一則訊息後, 可從下列動作中擇一執行:

1 · 復原程式碼與對話
2 · 只復原對話
3 · 只復原程式碼
4 · 從此處摘要
5 · 摘要至此處

提示

若輸入框內有文字, 連按兩下 Esc 會先清空輸入框而不是開啟選單, 清空的文字會存入輸入歷史, 按 Up 即可取回。若曾在同一個 Claude Code 行程中執行過 /clear, 回溯選單頂端會多出一個項目, 可用來恢復 clear 之前的對話 (需要 Claude Code v2.1.191 以上)。

Summarize 與 fork 不同: summarize 會壓縮同一個 session 的內容, 而 fork (claude --continue --fork-session) 則會另外分支出一個新 session, 完整保留原本的對話。

常見使用情境

探索不同做法
嘗試不同的實作方式, 而不必擔心失去原本的起點
從錯誤中復原
快速復原引入 bug 或破壞功能的變更
反覆疊代功能
實驗各種變化, 知道隨時能回到可運作的狀態
釋放 context 空間
從除錯過程的中間點開始摘要, 同時保留最初的指示

限制

Bash 指令修改不被追蹤

Checkpointing 不會追蹤由 Bash 指令修改的檔案, 例如 rm, mv, cp。這些變更無法透過 rewind 復原, 只有透過 Claude 檔案編輯工具做的直接編輯才會被追蹤。

外部變更不被追蹤

Checkpointing 只追蹤在目前 session 內被編輯過的檔案。你在 Claude Code 之外手動修改的檔案, 以及其他並行 session 的編輯, 通常不會被捕捉到, 除非剛好修改到同樣的檔案。

不能取代版本控制

Checkpoints 是為了 session 層級的快速復原而設計。永久的版本歷史與協作仍需持續使用 Git 等版本控制系統。

定位

可以把 checkpoints 想成「本機 undo」, 而 Git 則是「永久歷史」, 兩者互補而非取代。
