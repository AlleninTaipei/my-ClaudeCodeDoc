Security Guidance Plugin

安裝 security-guidance 外掛, 讓 Claude 在寫程式碼的同時審查並修正自己的漏洞

先決條件

Claude Code CLI
2.1.144 版或以上
Python
3.8 版以上, 且在 PATH 中; 外掛依序嘗試 python3, python, py -3
Git 儲存庫
結束對話與 commit 審查需比對 git 狀態, 在非 git 目錄會靜默略過
首次執行
會在 ~/.claude/security/ 建立虛擬環境並安裝 Claude Agent SDK, 需要 pip 與網路存取
Windows 差異

Windows 上會略過虛擬環境步驟, 僅在 claude-agent-sdk 已可匯入時才會執行 agentic commit 審查, 否則同樣退回單次審查模式。

安裝外掛

在 Claude Code session 中, 從官方 Anthropic marketplace 安裝:

/plugin install security-guidance@claude-plugins-official

安裝時會詢問範圍, 選擇 user scope 會寫入使用者設定, 讓這台機器上每個新的本機 session 都會載入。接著在目前 session 啟用:

/reload-plugins

在雲端 session 與共享儲存庫中啟用

跨環境啟用

User-scoped 外掛不會帶入 Claude Code on the web, 因為那些 session 執行於 Anthropic 基礎架構而非你的機器上。要在該處啟用, 或讓每個複製此儲存庫的人都套用, 需在專案已檢入的設定中宣告。

// .claude/settings.json
{
  "enabledPlugins": {
    "security-guidance@claude-plugins-official": true
  }
}

外掛檢查什麼

外掛在三個時間點審查 Claude 的工作, 各有不同深度:

每次編輯
每個 turn 結束時
每次 commit 或 push

Claude 寫入檔案時, 外掛會掃描新內容找出已知的高風險模式, 這是不呼叫模型的字串比對, 不會增加任何成本。

動態程式碼執行
eval(, new Function, os.system, child_process.exec
不安全反序列化
pickle
DOM 注入
dangerouslySetInnerHTML, .innerHTML =, document.write
工作流程檔案
編輯 .github/workflows/ 下的檔案, 可能授予儲存庫層級權限

每個警告在每個 session 中對每個檔案的每個模式只會觸發一次。

一個 turn 是 Claude 回應的一輪: 你傳訊息, Claude 工作並回覆, turn 就結束。每個 turn 結束後, 外掛會計算該 turn 中工作樹的完整 git diff, 送給另一個專注於安全性的 Claude 審查, 該審查在背景執行, 不會延遲 Claude 的回覆。

授權繞過
字串比對無法抓到的問題類別
不安全直接物件參照
同上

同上
伺服器端請求偽造
同上

同上

審查範圍涵蓋每個 turn 最多 30 個變更檔案, 連續最多觸發三次後便交還給你。

當 Claude 透過 Bash 工具執行 git commit 或 git push 時, 外掛會在背景執行更深入的 agentic 審查, 會讀取周邊程式碼 (呼叫者, 清理函式與相關檔案) 以判斷發現是否為真, 藉此在看似危險但實際安全的模式上維持低誤判率。

此層僅在 Claude 透過 Bash 工具執行的 commit 與 push 上觸發, 你自己 shell 執行的 commit 不會被審查。commit 與 push 審查上限為每小時 20 次。

審查獨立性: 外掛不會讓寫程式碼的同一個 Claude 實例自我評分。逐次編輯檢查是無模型涉入的字串比對, 結束 turn 與 commit 審查則是全新 context 的獨立 Claude 呼叫, 專注於找出問題。沒有任何一層會封鎖寫入或 commit。

新增自訂規則

外掛有兩個延伸點: 給模型審查用的 Markdown 指引檔, 以及給逐次編輯字串比對用的 YAML/JSON 規則檔, 兩者都是附加性質, 無法從這些檔案停用內建檢查。

選擇延伸類型:
模型審查指引
逐次編輯規則

在專案中建立 .claude/claude-security-guidance.md, 以白話文描述威脅模型與審查清單, 模型審查會與內建漏洞清單一併載入這份內容作為額外情境。

# Security guidance for this repo

- Do not log customer_id or account_number at INFO level or above.
- All routes under /admin must call require_role("admin") before any database read.
- Use crypto.timingSafeEqual for token comparison instead of ===.

建立 .claude/security-patterns.yaml, 為逐次編輯的字串比對加入正規表示式或子字串規則, 與內建模式一起執行:

patterns:
  - rule_name: internal_api_key
    substrings: ["sk_live_", "AKIA"]
    reminder: "Hardcoded API key prefix."
  - rule_name: tenant_unfiltered_query
    regex: "\\.objects\\.all\\(\\)"
    paths: ["**/src/tenants/**"]

外掛也讀取 .yml 與 .json 同結構檔案, JSON 在任何 Python 環境都能用, YAML 需要可匯入 PyYAML。最多載入 50 條自訂規則。

規則檔查找位置

User
~/.claude/claude-security-guidance.md, 適用於機器上每個專案
Project
.claude/claude-security-guidance.md, 隨儲存庫檢入
Project local
.claude/claude-security-guidance.local.md, 已加入 gitignore, 供個人覆寫

所有存在的位置都會被載入並串接, 指引檔合計上限 8 KB。

使用成本

成本

逐次編輯的字串比對不呼叫模型, 不增加成本。結束 turn 與 commit 審查各自消耗額外的模型用量, 計入你的一般用量。commit 審查是 agentic 的, 每次 commit 可能花費多個模型 turn, 上限為每小時 20 次審查。兩個模型審查預設使用 Claude Opus 4.7, 可用 SECURITY_REVIEW_MODEL 與 SG_AGENTIC_MODEL 分別調整。此外掛在所有方案皆可使用。

停用或解除安裝

ENABLE_PATTERN_RULES=0
停用逐次編輯的字串比對
ENABLE_STOP_REVIEW=0
停用結束 turn 的 diff 審查
ENABLE_COMMIT_REVIEW=0
停用 commit 與 push 審查
ENABLE_CODE_SECURITY_REVIEW=0
一次停用所有模型審查
SECURITY_GUIDANCE_DISABLE=1
不解除安裝, 直接停用整個外掛
/plugin disable security-guidance@claude-plugins-official
/plugin uninstall security-guidance@claude-plugins-official

外掛如何與 Claude Code 整合

外掛完全建立在 hooks 之上, 註冊了以下事件:

SessionStart
啟動外掛的 Python 環境
UserPromptSubmit
擷取工作樹基準, 供結束 turn 審查比對 diff
PostToolUse (Edit/Write/NotebookEdit)
逐次編輯字串比對
Stop
在背景執行結束 turn 的 diff 審查
PostToolUse (git commit/push)
Commit 與 push 審查

與其他安全工具的搭配

外掛是縱深防禦中的一層, 在程式碼還在編輯器中時就最早攔截問題, 但不是保證, 也不能取代後續檢查:

Session 中
Security guidance plugin: 修正 Claude 撰寫程式碼中的常見漏洞, 在同一 session 內修正
依需求
/security-review: 對目前分支進行一次性安全審查
Pull request
Code Review (Team/Enterprise): 具完整程式碼庫情境的多代理正確性與安全審查
CI 中
既有的靜態分析與相依性掃描工具

疑難排解

診斷記錄
外掛將執行期診斷寫入 ~/.claude/security/log.txt
非 git 目錄
結束 turn 與 commit 審查需要 git 狀態, 在非儲存庫中會略過
無 Anthropic 驗證
模型審查會略過, 只執行逐次編輯的字串比對
PyYAML 不可用
security-patterns.yaml 會被忽略, 改用 .json 檔案
