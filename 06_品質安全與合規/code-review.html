Code Review

透過多代理程式分析你完整的程式碼庫, 建立能捕捉邏輯錯誤, 安全漏洞與回歸問題的自動化 PR 審查

審查如何運作

Owner 為組織啟用 Code Review 後, 審查會依照每個儲存庫設定的行為, 在 PR 開啟時, 每次 push, 或手動要求時觸發。留言 @claude review 可在任何模式下啟動審查。

1 · 並行分析
多個代理在 Anthropic 基礎架構上平行分析 diff 與周邊程式碼, 各自負責不同類型的問題
2 · 驗證
驗證步驟會根據實際程式碼行為檢查候選發現, 過濾掉偽陽性
3 · 去重與排序
結果去除重複, 依嚴重程度排序
4 · 發佈
在發現問題的具體行號張貼行內留言, 並在審查內文中附上摘要

審查成本會隨 PR 大小與複雜度而變化, 平均耗時 20 分鐘。

嚴重程度等級

Important
合併前應修正的 bug
Nit
值得修正但不會阻擋合併的小問題
Pre-existing
程式碼庫中原本就存在, 並非此 PR 引入的 bug
check run

Check run 永遠以 neutral 狀態完成, 不會透過分支保護規則阻擋合併。最後一行文字是機器可解析的註解, 可用 gh 與 jq 解析, 例如 {"normal": 2, "nit": 1, "pre_existing": 0}。

設定 Code Review

Owner 為整個組織啟用一次 Code Review, 並選擇要納入的儲存庫。

1 · 開啟管理設定
2 · 開始設定
3 · 安裝 GitHub App
4 · 選擇儲存庫
5 · 設定觸發時機

前往 claude.ai/admin-settings/claude-code 找到 Code Review 區塊。需要 Owner 或 Primary Owner 角色, 以及在 GitHub 組織中安裝 GitHub App 的權限。

點選 Setup, 開始 GitHub App 安裝流程。

依提示將 Claude GitHub App 安裝到你的 GitHub 組織。此 App 會請求以下儲存庫權限:

Contents
read and write
Issues
read and write
Pull requests
read and write

選擇要啟用 Code Review 的儲存庫。若看不到某個儲存庫, 請確認安裝時已授權該儲存庫的存取權, 之後仍可再新增。

為每個儲存庫使用 Review Behavior 下拉選單設定審查觸發時機:

Once
PR 開啟或標記為 ready for review 時審查一次
After every push
每次 push 都審查, 並在問題修正後自動解決討論串
Manual
只有在留言 @claude review 或 @claude review once 時才啟動
Step 1 of 5

手動觸發審查

@claude review

啟動審查, 並將此 PR 訂閱未來 push 觸發的審查

@claude review once

啟動單次審查, 不訂閱未來 push 的審查

觸發條件

必須以頂層 PR 留言方式張貼 (非行內留言), 指令需放在留言開頭, 且你需要對該儲存庫有 owner, member 或 collaborator 存取權, PR 必須是開啟狀態。手動觸發也能在 draft PR 上運作。

自訂審查行為

選擇檔案:
CLAUDE.md
REVIEW.md

Code Review 會讀取儲存庫各層級的 CLAUDE.md, 並將新引入的違規標記為 Nit 等級。這是雙向的: 若你的 PR 讓 CLAUDE.md 的敘述過時, Claude 也會標記文件需要更新。

REVIEW.md 位於儲存庫根目錄, 其內容會以最高優先權注入審查流程中每個代理的系統提示。因為是原文貼入, @ import 語法不會被展開。

# Review instructions

## What Important means here
Reserve Important for findings that would break behavior, leak data,
or block a rollback.

## Cap the nits
Report at most five Nits per review.

## Do not report
- Anything CI already enforces: lint, formatting, type errors
- Generated files under src/gen/

疑難排解

審查失敗或逾時
留言 @claude review once 重新啟動一次不訂閱未來 push 的審查
觸及花費上限
下個計費週期自動恢復, 或由管理員提高上限後立即恢復
找不到行內留言
查看 Check run Details, Files changed 標籤的 annotation, 或審查內文的 Additional findings

在本機審查 diff

執行 /code-review 指令可在終端機審查 diff, 不需安裝 GitHub App。可加上 --comment 張貼為行內 PR 留言, 或 --fix 在審查後套用修正。

/code-review ultra --fix
效力等級

較低的 effort 等級會回傳較少但較高信心的發現; high 到 max 則涵蓋範圍更廣, 可能包含不確定的發現。
