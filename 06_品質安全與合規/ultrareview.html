Ultrareview

用 /code-review ultra 在雲端執行深度多代理程式碼審查, 於合併前找出並驗證真正的錯誤

從 CLI 執行 ultrareview

在任何 git 儲存庫中的 Claude Code CLI 啟動審查:

/code-review ultra

不帶參數時, ultrareview 會比較目前分支與預設分支的 diff, 包含工作樹中未提交與已暫存的變更。要改為審查 GitHub pull request, 傳入 PR 編號:

/code-review ultra 1234
Tip

若儲存庫太大無法打包, Claude Code 會提示改用 PR 模式: 推送分支, 開一個 draft PR, 再執行 /code-review ultra <PR-number>。若 PR 的 diff 太大, Claude Code 會在審查開始前直接拒絕並提供縮小範圍的建議。

啟動前, Claude Code 會顯示確認對話框, 包含審查範圍 (審查分支時含檔案與行數), 剩餘免費次數與預估費用。確認後審查在背景繼續進行, 你可以繼續使用 session。

計費與免費次數

Ultrareview 是計入使用額度而非方案內建用量的進階功能。

方案內含免費次數用完後
Pro3 次計入使用額度
Max3 次計入使用額度
Team 與 Enterprise無計入使用額度

Pro 與 Max 訂閱者可獲得三次免費試用, 這是帳號一次性額度, 不會重新整理。用完後, 每次審查依變更大小計費, 通常介於 5 到 20 美元。即使提早停止或審查失敗未完成, 仍會消耗一次免費次數; 付費審查則只針對實際執行的部分收費。

重點: 帳號或組織必須先開啟使用額度功能才能啟動付費審查, 可用 /usage-credits 檢查或變更目前設定。

追蹤執行中的審查

典型時長
5 到 10 分鐘, 以背景任務執行, 可繼續工作或關閉終端機
/tasks
查看執行中與已完成的審查, 開啟詳細檢視, 或停止進行中的審查
停止審查
會封存雲端 session, 部分結果不會回傳

非互動式執行 ultrareview

使用 claude ultrareview 子指令從 CI 或腳本啟動審查, 不需要互動式 session, 會阻塞直到遠端審查完成, 將發現印到 stdout:

claude ultrareview
claude ultrareview 1234
claude ultrareview origin/main

不帶參數時審查目前分支與預設分支的 diff; 傳入 PR 編號審查該 PR; 傳入分支名稱則與該分支比較。

--json
印出原始 bugs.json 內容而非格式化後的發現
--timeout <minutes>
等待審查完成的最長分鐘數, 預設 30

退出碼 0 表示審查完成 (含有無發現), 1 表示啟動失敗或逾時, 130 表示以 Ctrl-C 中斷。中斷子指令後, 遠端審查仍會繼續執行, 可依 stderr 印出的 session 網址於瀏覽器追蹤。
