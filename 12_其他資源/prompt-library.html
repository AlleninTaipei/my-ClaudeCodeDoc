Prompt Library 提示詞庫互動課程

依開發階段與角色分類的複製貼上提示詞庫, 收錄自 Anthropic 官方指南與團隊實務案例, 是探索 Claude Code 用法的起點, 而非固定腳本。

搜尋與篩選提示詞

總共收錄 則提示詞, 依軟體開發生命週期 (探索, 設計, 建構, 上線, 維運) 與角色 (PM, 設計, 文件, 行銷, 安全, 值班) 分類。點擊分類 chip 或輸入關鍵字即可篩選, 點擊卡片展開查看完整提示詞與使用說明。

這些提示詞為什麼有效

以上提示詞共享幾個模式, 認得出這些模式, 就能把任何一則提示詞調整成適合你自己任務的版本。

描述你要的結果, 而不是步驟

說出你想要什麼, 讓 Claude 自己去找檔案。下面這則提示詞完全沒有指定任何檔案路徑, 依然能運作。

add rate limiting to the public API and make sure existing tests still pass

給它一個自我檢查的方式

在同一則提示詞裡加入「執行, 測試, 比對, 驗證」等字眼, Claude 就會反覆迭代, 而不是做完一次就停下來。

write the migration, run it against the dev database, and confirm the schema matches

指出一個參考對象

指名一個既有的檔案, 測試或模式作為對照, 新程式碼就會與你現有的東西保持一致。

add a settings page that follows the same layout as the profile page

陳述可衡量的目標

當目標是效能或覆蓋率時, 給出具體指標與門檻, 完成的定義就不會模糊。

get the bundle size under 200KB and show me what you removed

提供實際素材

直接貼上錯誤訊息, 日誌, 截圖與 plan 輸出, 或用 @ 引用檔案。Claude 會讀取原始素材, 而不是你對它的描述。

why is the build failing? @build.log

說明你想要的回答方式

指定格式, 長度或閱讀對象, 讓說明符合你實際的使用情境。

explain how the payment retry logic works as an HTML page with a diagram, then open it in my browser

重點回顧: 好的提示詞描述結果而非步驟, 內建自我驗證迴圈, 指向具體參考或素材, 並清楚說明期望的輸出格式。掌握這些模式後, 你可以把任何一則範例改寫成適合自己專案的提示詞。

這些提示詞的來源與延伸資源

來源

這些提示詞整理自已發表的 Anthropic 資源: Common workflows (核心任務逐步指南), Best practices (提示技巧與專案設定), How Anthropic teams use Claude Code (工程, 產品, 設計, 資料團隊的實際工作流程, 含法務, 行銷, 資安深入案例), 以及 Scaling agentic coding guide (企業導入指南)。

本頁的提示詞是起點。當某一則對你的專案奏效後, 下一步是讓它可以重複使用: 存成 skill 讓團隊任何人都能以 /command 執行, 並把 Claude 學到的慣例記錄進 CLAUDE.md, 讓每個新 session 都從這個脈絡開始, 而不必重新摸索。對於更大或風險較高的變更, plan mode 會在任何編輯發生前先列出將異動的檔案清單。
