如何使用這份素材

草稿, 非成稿

把這裡的一切都當成草稿而非成稿。用你組織的語氣重寫每一則訊息, 把範例任務換成你程式碼庫裡真實的 bug 與模組, 並在發送前替換所有 [方括號佔位符]。真正帶動採用的公告, 讀起來會像是公司裡的人自己寫的。

發送前檢查清單

公告發出前先走過這份清單, 每一項都能補上一個原本會變成上線當天支援串的缺口。

建立並連結 #claude-code 頻道讓問題有一個固定去處
在環境中至少一台機器測過安裝指令在所有人同時遇到之前先抓出 proxy 或防火牆問題
準備好安全與資料處理連結「我的程式碼會流向哪裡」會是第一個回覆
選定一個具體的第一個任務通用範例不會促成轉換, 「修好 auth_test.go 裡不穩定的測試」才會
指定前 48 小時的頻道負責人上線當天沒人回答的問題會扼殺動能
找到高層贊助人共同具名發送高層具名發出的公告, 第一週採用率一致高於管理員發出的版本

快速參考

常見問題一句話回覆

支援 VS Code 嗎?
支援. 有 VS Code 擴充套件與 JetBrains 外掛, 功能相同, 內嵌在編輯器裡
要先設定什麼嗎?
不用. 安裝後在任何 repo 執行 claude, 跑一次 /init 就完成設定
我的程式碼會去哪?
CLI 在終端機執行, 把脈絡送到 Anthropic API 做推論, 沒有第三方伺服器. 在 Enterprise 方案下不會被用來訓練模型
它能看到整個 repo 嗎?
它讀取你授權的範圍. 工作目錄內的檔案讀取不會跳出提示, 但編輯, 執行指令與目錄外的存取都會被權限機制擋下確認
跟 Copilot 有什麼不同?
Copilot 自動完成單行. Claude Code 是會讀檔案, 執行指令並做多檔案編輯的代理
該先試什麼?
一個你一直拖延的 bug, 因為它很瑣碎. "[某檔案] 裡的測試不穩定, 查出原因"

提示詞範本

修 bug
"[某檔案] 裡的測試失敗了, 查出原因並修好"
理解程式碼
"帶我看看 [某模組] 如何運作, 然後告訴我進入點在哪"
安全重構
"把 [某模組] 重構成 [目標], 用 plan mode 讓我先審查"
寫測試
"為 [某檔案] 寫測試, 涵蓋 [某情境] 周邊的邊界情況"
commit 前審查
"看看我還沒 commit 的變更, 告訴我哪裡看起來有風險"
開 PR
"修好 [某 issue], 寫一個 conventional commit, 開一個附摘要的 PR"
建立 skill
"幫我做一個 /ship skill, 在 commit 前執行測試與 lint"
除錯堆疊追蹤
"這是堆疊追蹤, 找出根本原因, 不要只是掩蓋它"

重點回顧: 高層具名, 具體的第一個任務, 以及發送前先回答資料流向問題, 是決定上線公告成敗的三個關鍵。上線後用分類清楚的小技巧文宣持續投放, 比一次性的大公告更能帶動長期採用。
