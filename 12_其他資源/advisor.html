Advisor 顧問工具互動課程

讓主要模型在關鍵時刻諮詢一個更強的顧問模型, 學習何時啟用, 如何配對模型, 以及費用與快取的影響。

什麼是 Advisor

實驗性功能

Advisor 工具為實驗性功能, 需要 Claude Code v2.1.98 以上版本並搭配 Anthropic API, 不支援 Amazon Bedrock, Google Vertex AI 或 Microsoft Foundry。行為, 定價與可用性未來可能變動。

Advisor 工具讓 Claude 在任務的關鍵時刻諮詢第二個, 通常更強大的模型, 例如即將決定採用某個做法之前, 卡在反覆出現的錯誤時, 或宣告任務完成之前。顧問會收到完整的對話紀錄, 包含每一次工具呼叫與結果, 並回傳建議供 Claude 在繼續之前採用。

Advisor 是以 server tool 的形式在 Anthropic 的伺服器端執行, 訂閱制與 API 計費帳號皆可使用。你選擇由哪個模型擔任顧問, 而何時呼叫顧問則由 Claude 自行判斷。

什麼時候該用 Advisor

適合使用

長時間, 多步驟的任務, 大部分回合都很例行, 但計畫品質決定成敗。例如大型重構, 反覆出現同一個錯誤的除錯過程, 或希望在 Claude 宣告完成前獨立檢查一次的任務。

不適合使用

短任務, 幾乎不需要規劃, 或每一回合都需要最強模型的工作。這些情境應直接切換主要模型, 或考慮 opusplan 與子代理等其他取得第二意見的方式。

啟用 Advisor 的三種方式

1 · /advisor 指令
2 · advisorModel 設定
3 · --advisor 旗標

在 session 中即時設定或更換顧問, 並存成預設值。不帶參數執行會開啟選擇器列出可用的顧問模型, 也可以直接指定模型。

/advisor opus

選擇結果會存成使用者設定裡的 advisorModel, 並跨 session 保留。若組織的 availableModels 允許清單排除了已儲存的顧問模型, 則要等你用 /advisor 選一個允許的模型後才會啟用。

不開啟 session 也能設定預設顧問, 寫入設定檔即可。

{
  "advisorModel": "opus"
}

只在單一 session 設定顧問, 不影響已儲存的設定。

claude --advisor opus

此旗標的優先順序高於 advisorModel 設定。若 session 的主要模型不支援 advisor, 或請求的顧問模型被組織的允許清單排除, 指令會以錯誤結束。

Step 1 of 3
版本需求

要使用 Fable 5 作為顧問, 需要 Claude Code v2.1.170 以上版本, 並取得組織的 Fable 5 使用權限。

選擇顧問模型

顧問模型的能力必須至少與主要模型相當。每個主要模型可接受的顧問如下:

Haiku 4.5
Fable, Opus, Sonnet — Haiku 可以呼叫顧問, 但不能擔任顧問
Sonnet 4.6
Fable, Opus, Sonnet
Sonnet 5
Fable, Opus, Sonnet 5 — Sonnet 4.6 顧問會被拒絕
Opus 4.6 以上
Fable, 版本等於或高於主要模型的 Opus — Opus 4.7 主模型配 Opus 4.6 顧問會被拒絕, Opus 4.6 主模型也接受 Sonnet 5 顧問
Fable 5 (v2.1.170+)
僅接受 Fable — Opus 或 Sonnet 顧問都會被拒絕

顧問可設定為 opus, sonnet 或 fable, 這些別名會解析為各模型的最新版本, 也可以直接傳入完整的模型 ID, 例如 claude-opus-4-8。子代理會繼承所設定的顧問, 並依自身模型套用相同的配對檢查。

常見的模型配對

選擇配對:

Claude 何時會諮詢顧問

是否呼叫顧問由 Claude 自行決定。它傾向在即將決定採用某個做法之前, 錯誤反覆出現時, 以及宣告任務完成之前諮詢顧問, 但實際時機是由模型判斷, 而非固定規則。

committing to approach即將決定採用某個實作方向之前
recurring error同一個錯誤反覆出現, 卡住時
task completion宣告任務完成之前
提示

你也可以在提示詞中直接要求諮詢顧問, 例如 consult the advisor before you continue。目前沒有設定可以限制或強制顧問呼叫次數, 若想調整頻率, 直接在指示中說明即可。

Session 中會看到什麼

當 Claude 呼叫顧問時, 逐字稿會顯示一行 Advising 並附上顧問模型名稱, 呼叫進行中會持續顯示。結果回傳後, 該行會確認顧問已完成檢視。按下 Ctrl+O 可展開閱讀顧問完整的建議內容。

Claude 通常會依循顧問的建議, 但當自身證據與某個具體主張矛盾時會調整做法: 如果建議的步驟實際嘗試後失敗, 或檔案內容與建議矛盾, Claude 會呈現這個衝突, 而不是無條件遵循建議。

費用

計費方式
每次顧問呼叫都會把對話傳送給顧問模型, 因此除了主要模型的用量外, 還會依顧問模型的費率額外計費
API 計費
顧問的 token 依顧問模型的輸入輸出費率計算
訂閱方案
顧問用量計入方案的使用限額
整體成本
顧問只在決策點被呼叫, 而非每一回合, 因此搭配較快的主要模型與較強的顧問, 通常比全程使用強模型更省錢

對 Prompt Caching 的影響

快取行為

在 session 中途啟用或停用 advisor, 不會讓主要模型的 prompt cache 失效。與切換模型或調整 effort level 不同, 切換 /advisor 會保留已快取的前綴, 顧問回傳的建議也會在後續回合中作為逐字稿的一部分被快取。

顧問模型自己讀取對話的過程不會被快取, 每一次顧問呼叫都會重新處理完整的逐字稿, 呼叫之間沒有重複使用的部分。

關閉 Advisor

要停止使用 advisor 並清除已儲存的 advisorModel, 執行 /advisor off, 或在 /advisor 選擇器中選擇 No advisor。

/advisor off

若要完全停用 advisor 工具, 包含 /advisor 指令與 --advisor 旗標, 設定環境變數:

CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1

與相關功能的比較

Advisor 是結合不同模型能力的其中一種方式, 依你希望更強的模型何時介入來選擇。

Advisor 工具
任務中途的決策點, 由 Claude 判斷何時需要建議而主動呼叫
opusplan
在 plan mode 期間執行 (若組織的 availableModels 允許), 之後切回 Sonnet 執行; 由使用者進入 plan mode 觸發
Subagents (設定 model)
整個委派的子任務都由該模型執行; 由 Claude 委派或使用者呼叫子代理觸發
/model
套用到之後所有回合; 由使用者切換模型觸發

重點回顧: Advisor 適合用在長任務裡少數真正需要更強判斷力的節點, 讓便宜的主要模型處理例行工作, 只在關鍵決策時付出顧問模型的額外成本, 而不必整個 session 都跑最強的模型。
