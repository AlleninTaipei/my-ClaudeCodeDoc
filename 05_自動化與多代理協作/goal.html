用 /goal 讓 Claude 朝目標持續工作

設定一個完成條件, Claude 會跨回合持續工作直到條件成立, 不需要你逐步下指令。

比較讓 Session 持續執行的方式

三種方式都能讓目前 session 在提示之間持續運作, 差別在於下一回合何時開始。

/goal
前一回合結束就開始下一回合, 直到模型確認條件成立才停止
/loop
時間間隔到了才開始下一回合, 你手動停止或 Claude 判斷完成
Stop hook
前一回合結束就開始, 由你自己的腳本或提示詞判斷是否停止

Auto mode 在單一回合內自動核准工具呼叫但不會開新回合, /goal 則加入一個獨立的評估者, 在每回合後檢查你的條件, 兩者互補。

使用 /goal

每個 session 只能有一個活躍的目標, 同一指令依參數決定要設定, 檢查或清除。

1 · 設定目標
2 · 檢查狀態
3 · 清除目標
4 · 恢復 Session
5 · 非互動執行
/goal all tests in test/auth pass and the lint step is clean

設定目標會立即啟動一回合, 條件本身就是指示。若已有目標在執行, 新目標會取代它。

/goal

顯示條件, 已執行時間, 已評估回合數, 目前 token 花費, 以及評估者最近一次的理由。

/goal clear

stop, off, reset, none, cancel 都是 clear 的別名。執行 /clear 開新對話也會一併移除目標。

session 結束時仍在執行的目標, 用 --resume 或 --continue 恢復時會被還原, 條件保留, 但回合數, 計時器與 token 花費基準線都會重設。

claude -p "/goal CHANGELOG.md has an entry for every PR merged this week"

用 -p 設定目標會在單次呼叫中把整個迴圈跑到完成, Ctrl+C 可中斷。

Step 1 of 5

撰寫有效的條件

評估者只根據 Claude 已在對話中呈現的內容判斷, 不會自己執行指令或讀檔案, 所以條件要寫成 Claude 自己的輸出可以證明的形式。

一個可衡量的終止狀態
測試結果, build 結束碼, 檔案數量, 空的佇列
明確的檢查方式
例如 npm test 結束碼為 0, 或 git status 是乾淨的
重要的限制
過程中不能改變的事, 例如不修改其他測試檔案
回合或時間界限
加入例如 or stop after 20 turns 來限制迴圈長度
長度限制

條件最多 4000 字元。

評估如何運作

/goal 是 session 範圍的提示式 Stop hook 包裝。每次 Claude 完成一回合, 條件與目前對話會送給你設定的小型快速模型 (預設 Haiku) 判斷是或否, 並附上簡短理由。

評估 token 以小型快速模型計費, 相較主回合花費通常可忽略不計。

使用需求

/goal 只在已接受信任對話框的工作區中執行, 因為評估者是 hooks 系統的一部分。當 disableAllHooks 或 allowManagedHooksOnly 生效時, /goal 也無法使用, 並會告知原因而非靜默失效。
