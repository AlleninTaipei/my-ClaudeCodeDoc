Channels Reference

建置一個能把 webhook, 警報, 聊天訊息推入 Claude Code session 的 MCP server, 這是頻道協定的完整參考。

概觀

頻道是一個和 Claude Code 在同一台機器上執行的 MCP server, 以子行程方式透過 stdio 溝通。聊天平台輪詢 API 取得新訊息, webhook 則在本機開一個 HTTP port 供外部系統 POST。

Chat platforms
外掛在本機執行, 輪詢平台 API, 收到訊息後轉發給 Claude
Webhooks
server 監聽本機 HTTP port, 外部系統 POST 後推送給 Claude

需要準備什麼

唯一硬性需求是 @modelcontextprotocol/sdk 套件與相容 Node.js 的執行環境, Bun, Node, Deno 皆可。

1宣告 claude/channel 能力, 讓 Claude Code 註冊通知監聽器
2發出 notifications/claude/channel 事件
3透過 stdio transport 連線, Claude Code 會以子行程方式啟動你的 server

範例: 建置 Webhook 接收器

這個範例用 Bun 建立一個單檔 server, 監聽 HTTP 請求並轉發進 Claude Code session。

1 · 建立專案
2 · 撰寫 Server
3 · 註冊到 MCP 設定
4 · 測試
mkdir webhook-channel && cd webhook-channel
bun add @modelcontextprotocol/sdk
import { Server } from '@modelcontextprotocol/sdk/server/index.js'
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js'

// 建立 MCP server 並宣告為頻道
const mcp = new Server(
  { name: 'webhook', version: '0.0.1' },
  {
    capabilities: { experimental: { 'claude/channel': {} } },
    instructions: 'Events arrive as <channel source="webhook" ...>',
  },
)

await mcp.connect(new StdioServerTransport())

Bun.serve({
  port: 8788,
  hostname: '127.0.0.1',
  async fetch(req) {
    const body = await req.text()
    await mcp.notification({
      method: 'notifications/claude/channel',
      params: { content: body, meta: { path: new URL(req.url).pathname } },
    })
    return new Response('ok')
  },
})
// .mcp.json
{
  "mcpServers": {
    "webhook": { "command": "bun", "args": ["./webhook.ts"] }
  }
}
claude --dangerously-load-development-channels server:webhook

# 另一個終端機模擬 webhook
curl -X POST localhost:8788 -d "build failed on main"

負載會以 <channel source="webhook" path="/" method="POST"> 標籤抵達 session。

Step 1 of 4

Server 選項

experimental['claude/channel']
必填, 永遠是 {}, 存在即註冊通知監聽器
experimental['claude/channel/permission']
選填, 宣告此頻道可接收權限轉發請求
capabilities.tools
僅雙向頻道需要, 標準 MCP 工具能力
instructions
加入 Claude 系統提示, 告訴它如何處理事件與回覆

通知格式

server 呼叫 mcp.notification() 送出 notifications/claude/channel, 帶兩個參數:

content
string, 事件本文, 會成為 <channel> 標籤的內容
meta
Record<string,string>, 每一項成為標籤屬性, 鍵只能是字母數字底線
注意

通知不會被確認, await 只代表寫入 transport, 不代表 Claude 已處理完畢。

公開回覆工具

雙向頻道需要公開一個標準 MCP 工具讓 Claude 回訊息, 三個組成部分: capabilities 加入 tools: {}, 註冊工具處理器, 在 instructions 說明何時呼叫。

mcp.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [{
    name: 'reply',
    inputSchema: { type: 'object', properties: {
      chat_id: { type: 'string' }, text: { type: 'string' } },
      required: ['chat_id', 'text'] },
  }],
}))

過濾接收訊息

未經過濾的頻道就是提示注入的攻擊面, 任何能觸及你 endpoint 的人都能把文字塞進 Claude 面前。

安全規則

要用寄件人身分 (message.from.id) 過濾, 不是聊天室身分 (message.chat.id), 否則群組中任何人都能注入訊息。

Telegram 與 Discord 用配對流程建立白名單, iMessage 則自動放行自己的位址, 其他聯絡人以 handle 加入。

轉發權限提示

雙向頻道可選擇同時接收權限提示並轉發到另一台裝置, 本機與遠端都保持有效, 先回應的一方生效。

1Claude Code 產生五字元請求 ID 並通知 server
2server 把提示與 ID 轉發到聊天 App
3遠端使用者以 yes/no 加 ID 回覆
4inbound handler 解析回覆為裁決, ID 相符才會套用
request_id
五個小寫字母, 不含 l, 避免在手機上誤讀為 1 或 I
tool_name
Claude 想使用的工具名稱, 例如 Bash 或 Write
description
這次呼叫的人類可讀摘要
input_preview
工具參數的 JSON 字串, 截斷至 200 字元

打包成外掛

要讓頻道可安裝且可分享, 把它包成外掛並發布到市集, 使用者用 /plugin install 安裝, 再以 --channels plugin:<name>@<marketplace> 啟用。
