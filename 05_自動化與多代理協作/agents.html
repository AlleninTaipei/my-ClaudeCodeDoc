並行執行代理

比較 Claude Code 同時處理多項任務的四種方式: subagents, agent view, agent teams, 與 dynamic workflows.

四種並行方式總覽

Subagents, agent view, agent teams, 與 dynamic workflows 各自以不同方式平行處理工作. 選擇哪一種取決於你是否想親自留在每個對話中, 交辦任務後再回來查看, 或是讓 Claude 協調一整組工作者.

選擇方式查看說明:

Dynamic workflows
提供什麼
在單一 session 內委派的工作者, 於自己的 context 中完成側邊任務並回傳摘要.
適用時機
側邊任務會用大量搜尋結果, 記錄或檔案內容淹沒你的主對話, 而這些內容你之後不會再用到.
NOTE

在每一種做法中, 工作者都是 Claude session. 若要使用不同的工具, 需將該工具以 MCP server 的形式提供給 Claude.

另外兩個輔助工具

Worktrees
讓每個 session 擁有獨立的 git checkout, 使平行 session 不會編輯同一份檔案.
/batch
一個 skill, 讓 Claude 把一項大型變更拆成 5 到 30 個以 worktree 隔離的 subagent, 各自開一個 pull request.

其他容易混淆的功能

background bash
在不阻塞對話的情況下執行一個 shell 指令, 不會產生代理.
forked subagent
繼承你完整對話內容的 subagent, 屬於產生 subagent 的一種方式.
routine
在 Anthropic 雲端依排程執行的 session, 而非在你的機器上平行執行.

同時執行多個 session 或 subagent 會使 token 用量倍增, 詳見 Costs 文件中的用量與速率限制說明.

選擇合適的做法

合適的做法取決於誰在協調工作, 工作者之間是否需要溝通, 以及是否會編輯同一份檔案.

誰協調工作?
Claude 在同一對話中委派並收集結果: subagents. 你交辦獨立任務並之後回來查看: agent view. Claude 規劃, 指派並監督一組工作者: agent teams (實驗性, 預設關閉). 由腳本持有計畫而非 Claude 逐輪判斷: dynamic workflows.
工作者需要互相溝通嗎?
Subagent 只會把結果回報給產生它的對話, agent view 的 session 只回報給你. Agent team 的隊員共用任務清單並直接互相傳訊.
任務是否會碰到相同檔案?
用 worktrees 隔離工作. Subagent 與你自己執行的 session 都可各自使用獨立 worktree. Agent team 不會自動隔離隊員, 需自行拆分工作範圍.

查看執行中的工作

檢查執行中工作所用的指令, 依你所採用的做法而不同.

claude agents
開啟 agent view, 顯示每個背景 session, 其狀態, 以及哪些需要你輸入.
/agents
開啟面板, 內含列出執行中 subagent 的 Running 分頁, 以及建立與編輯自訂 subagent 的 Library 分頁.
/tasks
列出目前 session 中背景執行的每個項目, 可查看, 附加或停止它們.
/workflows
列出執行中與已完成的 dynamic workflow, 各自所在階段, 以及已完成的代理數量.

進一步了解

以下每份指南涵蓋一種做法的設定與配置.

Create custom subagents
定義可重複使用的專家角色, 並控制它們能使用哪些工具.
Manage agents with agent view
派送 session, 觀察其狀態, 並在需要時附加進去.
Orchestrate agent teams
設置團隊領導與隊員, 指派任務並審查其成果.
Orchestrate dynamic workflows
執行預先包裝好的 workflow, 或讓 Claude 撰寫一個能執行多個 subagent 並互相驗證結果的 workflow.
Run parallel sessions with worktrees
在隔離的 checkout 中啟動 Claude, 控制要複製進去的內容, 並在事後清理.
