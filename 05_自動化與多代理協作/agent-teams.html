Orchestrate teams of Claude Code sessions

協調多個 Claude Code 實例一起工作: 共用任務清單, 代理間傳訊, 以及集中管理.

什麼時候該用 Agent teams

WARNING

Agent teams 是實驗性功能, 預設關閉. 需在 settings.json 或環境變數中加入 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 才會啟用.

Agent teams 讓你協調多個 Claude Code 實例一起工作. 其中一個 session 擔任團隊領導, 負責協調工作, 指派任務, 並整合結果. 隊員各自獨立工作, 擁有自己的 context window, 並能直接互相溝通.

與 subagents 不同, subagents 只能在單一 session 內運作, 只能回報給主代理; agent teams 中你可以直接與個別隊員互動, 不必透過領導者.

最適合的情境

研究與審查
多名隊員可同時調查問題的不同面向, 再互相分享並挑戰彼此的發現.
新模組或功能
隊員各自負責獨立的一塊, 不會互相干擾.
以競爭假設除錯
隊員平行測試不同理論, 更快收斂到答案.
跨層協調
橫跨前端, 後端與測試的變更, 各自由不同隊員負責.

與 Subagents 比較

Subagents

Context: 擁有自己的 context window, 結果回傳給呼叫者

溝通: 只回報給主代理

協調: 由主代理管理所有工作

最適合: 只在意結果的專注型任務

Token 成本: 較低, 結果會摘要回主 context

Agent teams

Context: 擁有自己的 context window, 完全獨立

溝通: 隊員之間直接傳訊

協調: 共用任務清單, 自我協調

最適合: 需要討論與協作的複雜工作

Token 成本: 較高, 每個隊員都是獨立的 Claude 實例

啟用 Agent teams

在 settings.json 或 shell 環境中將 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 設為 1.

{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}

啟動你的第一個 Agent team

啟用後, 以自然語言描述任務與想要的隊員, Claude 會依你的提示產生隊員並協調工作.

// 這個範例效果好, 因為三個角色互相獨立, 不需等待彼此
I'm designing a CLI tool that helps developers track TODO comments across
their codebase. Spawn three teammates to explore this from different angles:
one on UX, one on technical architecture, one playing devil's advocate.

之後 Claude 會建立共用任務清單, 為每個角度產生隊員, 讓他們探索問題, 並在完成後整合發現.

領導者面板操作

↑ / ↓
選擇隊員
Enter
開啟所選隊員的對話紀錄並直接傳訊
Escape
中斷所選隊員目前的回合
NOTE

v2.1.181 起, 閒置隊員的列會在 30 秒後隱藏, 並在其下一回合重新出現; 隱藏期間該隊員仍在執行且可被傳訊.

控制你的 Agent team

選擇顯示模式

切換模式:
In-process
Split panes
說明
所有隊員都在你的主終端機內執行, 用上下鍵在面板中選取隊員, 按 Enter 檢視並輸入訊息傳給它. 任何終端機都可用, 不需額外設定.
需求
無, 這是預設模式.

指定隊員與模型

// Claude 會依任務決定隊員數量, 也可以明確指定
Spawn 4 teammates to refactor these modules in parallel. Use Sonnet for
each teammate.

隊員預設不會繼承領導者的 /model 選擇, 需在 /config 中設定 Default teammate model 才能改變預設行為.

要求隊員先規劃再執行

// 對於複雜或高風險任務, 可要求隊員先規劃
Spawn an architect teammate to refactor the authentication module.
Require plan approval before they make any changes.

隊員在唯讀的規劃模式中工作, 直到領導者核准其做法為止. 若被拒絕, 隊員會停留在規劃模式, 依回饋修訂後重新提交.

任務指派與領取

領導者指派
告訴領導者要把哪個任務交給哪位隊員.
自我領取
隊員完成一項任務後, 自行領取下一個未指派且未被阻擋的任務.

結束隊員與品質關卡

TeammateIdle
隊員即將閒置前執行, 以結束碼 2 傳送回饋讓隊員繼續工作.
TaskCreated
任務建立時執行, 以結束碼 2 阻止建立並傳送回饋.
TaskCompleted
任務標記完成時執行, 以結束碼 2 阻止完成並傳送回饋.

Agent teams 如何運作

架構

Team lead
產生隊員並協調工作的主要 Claude Code session.
Teammates
各自負責被指派任務的獨立 Claude Code 實例.
Task list
隊員領取與完成的共用工作項目清單.
Mailbox
代理之間互相溝通的訊息系統.

團隊與任務以來自 session 的名稱儲存在本機: 團隊設定在 ~/.claude/teams/{team-name}/config.json, 任務清單在 ~/.claude/tasks/{team-name}/.

使用 Subagent 定義作為隊員

Spawn a teammate using the security-reviewer agent type to audit the auth module.

隊員會遵循該定義的 tools 允許清單與 model, 定義內文會附加到隊員的系統提示中作為額外指示.

權限與情境溝通

隊員以領導者的權限設定啟動. 每個隊員擁有自己的 context window, 產生時會載入與一般 session 相同的專案情境: CLAUDE.md, MCP servers 與 skills, 但不會繼承領導者的對話歷史.

自動訊息投遞
隊員傳訊時會自動送達收件者, 領導者不需輪詢更新.
閒置通知
隊員完成並停止時會自動通知領導者.
共用任務清單
所有代理都能看到任務狀態並領取可用工作.

Agent teams 使用的 token 遠多於單一 session, 每位隊員都有自己的 context window, 用量會隨隊員數量增加. 對研究, 審查與新功能開發而言通常值得, 但例行工作用單一 session 更划算.

使用情境範例

平行程式碼審查

Spawn three teammates to review PR #142:
- One focused on security implications
- One checking performance impact
- One validating test coverage
Have them each review and report findings.

每位審查者以同一份 PR 為基礎, 但套用不同的過濾角度; 三者完成後由領導者整合發現.

以競爭假設調查問題

Users report the app exits after one message instead of staying connected.
Spawn 5 agent teammates to investigate different hypotheses. Have them talk to
each other to try to disprove each other's theories, like a scientific
debate. Update the findings doc with whatever consensus emerges.

辯論結構是這裡的關鍵機制: 多個獨立調查者互相嘗試推翻彼此理論時, 存活下來的理論更可能就是真正的根因.

最佳實務

給予足夠情境
隊員不會繼承領導者的對話歷史, 在產生提示中納入任務相關細節.
選擇適當團隊規模
大多數工作流從 3 到 5 位隊員開始, 每位隊員 5 到 6 個任務可維持生產力.
合理拆分任務大小
太小會讓協調成本超過效益, 太大會讓隊員長時間無回報, 增加浪費風險.
等待隊員完成
若領導者自行動手而非等待隊員, 明確告訴它等隊員完成任務再繼續.
從研究與審查開始
初次使用時, 從邊界清楚且不需寫程式的任務開始, 例如審查 PR 或調查錯誤.
避免檔案衝突
兩位隊員編輯同一檔案會導致覆寫, 需拆分工作讓每位隊員負責不同檔案集合.

疑難排解

隊員沒有出現
確認任務是否足夠複雜以值得組建團隊, 並檢查 in-process 面板或 tmux/iTerm2 設定.
權限提示過多
隊員的權限請求會上呈給領導者, 事先在權限設定中核准常見操作可減少中斷.
隊員因錯誤而停止
在面板中選取隊員並檢視輸出, 給予額外指示或產生替代隊員接手.
領導者過早結束
告訴它任務尚未完成, 請繼續進行.
遺留的 tmux session
用 tmux ls 列出並以 tmux kill-session 結束團隊建立的 session.

限制

無法還原 session
/resume 與 /rewind 不會還原 in-process 隊員.
任務狀態可能延遲
隊員有時未能標記任務完成, 導致依賴任務被阻擋.
關閉可能較慢
隊員會先完成目前請求或工具呼叫才關閉.
每個 session 僅一個團隊
無法建立額外的命名團隊或跨 session 共用團隊.
不支援巢狀團隊
隊員不能產生自己的隊員, 只有領導者能管理團隊.
領導者固定
主 session 在整個生命週期中都是領導者, 無法轉移領導權.

CLAUDE.md 仍正常運作: 隊員會從其工作目錄讀取 CLAUDE.md 檔案, 可用來對所有隊員提供專案層級的指引.
