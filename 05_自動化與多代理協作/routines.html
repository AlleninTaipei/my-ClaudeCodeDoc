用 Routines 自動化工作

把 Claude Code 交給自動駕駛: 定義在排程, API 呼叫, 或 GitHub 事件觸發下, 於 Anthropic 代管雲端基礎設施執行的例程。

範例使用情境

每個範例都配對一種觸發類型與適合無人值守, 可重複, 且有明確結果的工作。

選擇情境
待辦維護
警報分診
客製審查
部署驗證
文件漂移

排程觸發每個工作夜晚透過連接器讀取議題追蹤系統, 為自上次執行後開啟的議題貼標籤, 依程式碼區域指派負責人, 並把摘要貼到 Slack。

監控工具在錯誤門檻被超過時呼叫例程的 API endpoint, 傳入警報內容作為 text, 例程拉出堆疊追蹤, 與近期提交做關聯, 並開啟含修復建議的草稿 PR。

GitHub 觸發在 pull_request.opened 時執行, 套用團隊自己的審查清單, 為安全性, 效能, 風格問題留下行內註解, 並加上摘要留言。

CD pipeline 在每次生產部署後呼叫例程的 API endpoint, 執行冒煙測試, 掃描錯誤日誌找回歸, 在部署視窗關閉前貼出 go 或 no-go。

排程觸發每週掃描已合併 PR, 標記引用已變更 API 的文件, 對文件儲存庫開啟更新 PR 供編輯審閱。

建立一個 Routine

可在網頁, Desktop App, 或 CLI 建立, 三者都寫入同一個雲端帳號。

1 · 名稱與提示詞
2 · 選擇儲存庫
3 · 選擇環境
4 · 選擇觸發
5 · 連接器與權限

提示詞是最重要的部分, 因為例程自主執行, 提示詞必須自成一體並明確說明要做什麼與成功的樣子。

新增一個或多個 GitHub 儲存庫供 Claude 工作, 每次執行都會複製預設分支, Claude 建立 claude/ 前綴的分支。

Default 環境提供 Trusted 網路存取, 允許套件註冊表, 雲端供應商 API, 容器註冊表等預設清單, 其餘一律阻擋。

可選擇 Schedule, GitHub event, 或 API 其中一種或多種組合, 見下方觸發設定章節。

已連接的 MCP 連接器預設全部包含, 移除不需要的以限縮 Claude 能觸及的工具, 並在 Permissions 開啟允許不受限分支推送。

Step 1 of 5

設定觸發器

一個 routine 啟動於其中一個觸發器匹配時, 可同時附加排程, API, 與 GitHub 觸發。

Schedule 排程

依固定頻率執行或一次性排程, 時間以本地時區輸入自動轉換, 最短間隔一小時, 可用 /schedule update 設定自訂 cron。

API 觸發

給予專屬 HTTP endpoint, 用 bearer token POST 即可啟動新 session。

GitHub 觸發

訂閱 Pull request 或 Release 事件, 可用作者, 標題, 分支, 標籤等欄位篩選。

組合觸發

一個 routine 可同時每晚排程, 由部署腳本觸發, 也對每個新 PR 反應。

curl -X POST https://api.anthropic.com/v1/claude_code/routines/trig_01ABC.../fire \
  -H "Authorization: Bearer sk-ant-oat01-xxxxx" \
  -d '{"text": "Sentry alert SEN-4521 fired in prod."}'

管理 Routines

Run now
立即啟動一次執行
Repeats 開關
暫停或恢復排程, 暫停不會刪除設定
Edit routine
修改名稱, 提示詞, 儲存庫, 環境, 連接器或觸發器
Delete
移除 routine, 過去建立的 session 仍保留在列表中
注意

綠色狀態只代表 session 啟動並正常結束, 不代表提示詞裡的任務成功, 打開執行紀錄確認 Claude 實際做了什麼。

使用量與限制

Routines 與互動 session 一樣消耗訂閱額度, 額外還有每日執行次數上限。一次性執行不計入每日 routine 上限。

開啟 usage credits 可在達到上限後以計量方式繼續執行 routine, 否則額外執行會被拒絕直到視窗重置。
