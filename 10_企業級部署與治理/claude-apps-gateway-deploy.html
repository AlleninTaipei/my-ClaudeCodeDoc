Claude Apps Gateway 部署與維運

在 IdP 註冊, 建置容器, 部署到 Kubernetes 或 Cloud Run, 並涵蓋健康檢查, 密鑰輪替, 升級與安全性

身分提供者設定

註冊一個機密的 OAuth/OIDC web 應用程式, redirect URI 為 https://<gateway>/oauth/callback, 並指派給應有存取權的使用者或群組。

選擇 IdP: Okta Microsoft Entra ID Google Workspace

組織授權伺服器 https://example.okta.com 回傳的 id_token 缺少 email 與 groups, 需設定 oidc.userinfo_fallback: true。groups 只有在 scopes 中要求 groups 且應用程式的宣告過濾器允許時才會發出。

issuer 為 https://login.microsoftonline.com/<tenant-id>/v2.0。Entra 發出群組 Object ID 而非名稱, 在 managed.policies.match.groups 用 GUID, 或改用 App Roles 取得可讀名稱。

issuer 為 https://accounts.google.com。Google 的 id_token 不帶群組, 需設定 oidc.google_groups 透過 Admin SDK Directory API 查詢, 或改用 email_domain 比對。

部署決策

閘道是單一 Linux 二進位檔, 因為 replica 無狀態且 Postgres 是共享協調層, 所以能水平擴展。

成本
閘道無獨立授權費用, 內含於 claude 執行檔中, 只需支付推論與容器運算成本
繞過
閘道不強制唯一路徑, 需靠網路政策封鎖直接對外連線
多閘道
每個閘道是獨立部署與設定, CLI 依主機名稱各自保存憑證
無伺服器
Cloud Run 可用, 設 min-instances:1 避免冷啟動; Lambda 不適用, 因為閘道是長駐 HTTP 伺服器

容器映像檔與平台

平台: 容器映像 Kubernetes Cloud Run

圍繞原生 claude 執行檔建置映像, 需要 glibc-based 映像, 可寫入狀態目錄, 以及容器指令 claude gateway --config /etc/claude/gateway.yaml。

以 Deployment 執行, 從 ConfigMap 掛載設定, 從 Secret 掛載機密, 在 Ingress 終止 TLS, readiness 探針指向 GET /readyz, liveness 指向 GET /healthz。

listen.port 保留預設 8080, 設定 public_url 為對外可達來源, 將設定掛載為機密磁碟區, 並設 min-instances: 1 避免冷啟動 OIDC discovery。

維運

日誌審計事件是單行 JSON, 涵蓋 session.mint, auth.denied, inference 等; 操作日誌是人類可讀的 [gateway] 前綴
健康檢查GET /healthz 為 liveness, GET /readyz 驗證儲存體是否可連線, 兩者豁免 access_control
中斷行為Postgres 中斷時既有 session 仍可運作, 新登入失敗; 花費強制預設 fail-open
JWT 密鑰輪替前置新密鑰, 滾動部署, 等待 ttl_hours 加緩衝後移除舊密鑰
升級replica 無狀態, 隨時可安全滾動重啟; 遷移是附加式, 回滾到舊版本是安全的

Postgres 資料表

kv裝置授權 (10 分鐘 TTL) 與速率限制計數器
spend每個 principal 期間至今的花費計數器, 以分計
spend_limits已設定的花費上限
admin_auditAdmin API 異動軌跡
principal_emails每位 principal 最後所見的 email, 顯示名稱與 IdP 群組, 含 PII

安全性

閘道位於網路邊界內, 但個別開發者筆電並非受信任端點。設計上以三種方式因應: 短期 JWT 取代原始上游金鑰, 裝置驗證頁面強制同源 POST 與每 IP 速率限制, 以及對外請求經過 SSRF 防護。

受信任的閘道能推送在開發者機器上執行指令的設定, 因此掌控閘道設定等同於掌控你的 MDM。閘道主機的安全是你自己基礎設施的責任範疇。

疑難排解

/login 顯示標準帳號選擇器forceLoginMethod 或 forceLoginGatewayUrl 未在該機器的 managed settings 中設定
主機解析到公開位址閘道主機名稱必須只解析到私有位址, 檢查雙堆疊名稱與 AWS 內部負載平衡器
開機退出於 Postgres 驗證錯誤未設定 store.postgres_url 或角色缺少 CREATE TABLE 權限
IdP 錯誤: unknown scope設定 oidc.scopes 為 IdP 實際接受的清單, 且必須包含 openid
