Claude Code 搭配 Claude Platform on AWS

用 AWS 認證與 IAM 存取控制, 透過 AWS Marketplace 計費, 直接呼叫 Anthropic-operated 的 Claude API

事前準備

AWS Marketplace 訂閱已啟用的 Claude Platform on AWS 訂閱
WorkspaceAWS 連結的 Anthropic 組織中已建立 workspace, 並取得 workspace ID
IAM 權限或 API key具備呼叫 Anthropic service 權限的 IAM principal, 或已限定 workspace 的 API key
AWS 憑證環境變數, ~/.aws/credentials, 或已附加的 IAM role; 只有 SSO 登入流程才需要 AWS CLI
注意

透過 AWS Marketplace 訂閱會建立一個綁定 AWS 帳號的全新 Anthropic 組織, 與你既有的 Anthropic 組織彼此獨立, 憑證不互通。請使用 AWS 連結組織的 workspace ID 與 API key, 而不是既有 Claude Console 帳號的憑證。

設定步驟

1 · 設定 AWS 憑證
2 · 設定 Claude Code
3 · 固定模型版本

Claude Code 支援兩種 Claude Platform on AWS 的認證方式, 依團隊管理存取的方式挑選其一。

方式
選項 A: AWS 憑證 + SigV4
選項 B: Workspace API key

Claude Code 用 AWS 標準憑證鏈 (環境變數, ~/.aws/credentials, IAM roles, AWS SSO sessions 等) 以 SigV4 簽署請求。

aws sso login --profile my-profile
export AWS_PROFILE=my-profile

CI 與自動化情境, 給 runner 一個具備呼叫 Anthropic service 權限的 IAM role, 並設定 AWS_REGION, 憑證鏈會自動取用。

若 SSO 憑證在 session 中途過期, 可設定 awsAuthRefresh 讓 Claude Code 自動重新執行登入指令並重試:

{
  "awsAuthRefresh": "aws sso login --profile my-profile"
}
TIP

設定 awsAuthRefresh 後, /login 會出現 "Claude Platform on AWS · refresh credentials" 選項, 執行設定的指令並重新讀取 AWS 憑證, 不需要重新啟動 Claude Code。

Workspace API key 是長效密鑰, 適合不想管理聯合 AWS 憑證的情境。在 AWS Console 的 Claude Platform on AWS → API keys 產生, 並設定為 ANTHROPIC_AWS_API_KEY:

export ANTHROPIC_AWS_API_KEY=sk-ant-xxxxx

此金鑰以 x-api-key 送出, 優先於 SigV4, 因此環境中任何 AWS 憑證都會被忽略。來自其他 Claude Console 組織的 API key 在這裡無法使用。

注意

/login 與 /logout 不會登入 Claude Platform on AWS 的 claude.ai 訂閱, 認證只透過 AWS 憑證或 workspace API key 進行, 唯一例外是設定 awsAuthRefresh 後出現的 refresh credentials 選項。

設定環境變數, 把 Claude Code 導向 Claude Platform on AWS 而非預設的 Anthropic API。

export CLAUDE_CODE_USE_ANTHROPIC_AWS=1
export ANTHROPIC_AWS_WORKSPACE_ID=wrkspc_01ABCDEFGHIJKLMN
export AWS_REGION=us-east-1
ANTHROPIC_AWS_WORKSPACE_ID
必填, 會在每個請求中以 anthropic-workspace-id 標頭送出
ANTHROPIC_AWS_BASE_URL
選填, 直接覆寫由 AWS_REGION 計算出的基底網址
注意

Claude Platform on AWS 即使環境中存在 AWS 憑證也是選用性質。Bedrock 與 Foundry 在供應商路由上優先權更高, 若已設定 CLAUDE_CODE_USE_BEDROCK 或 CLAUDE_CODE_USE_FOUNDRY 需先取消設定。

Claude Platform on AWS 使用與直接 Claude API 相同的模型 ID。預設別名 fable, opus, sonnet, haiku 會解析到 Claude Code 內建的預設值, 可能落後最新版本。

若要部署給團隊使用, 建議明確固定模型 ID, 避免新版本一次影響所有人:

export ANTHROPIC_DEFAULT_FABLE_MODEL=claude-fable-5
export ANTHROPIC_DEFAULT_OPUS_MODEL=claude-opus-4-7
export ANTHROPIC_DEFAULT_SONNET_MODEL=claude-sonnet-5
export ANTHROPIC_DEFAULT_HAIKU_MODEL=claude-haiku-4-5
TIP

Prompt caching 會自動啟用。要改用 1 小時快取 TTL 而非預設的 5 分鐘, 設定 ENABLE_PROMPT_CACHING_1H=1, 但 API 對 1 小時快取寫入收取較高費率。

Step 1 of 3

搭配 Agent SDK 使用

Agent SDK 讀取與 CLI 相同的環境變數, 任何會產生 Claude Code 子行程的程式, 都能在呼叫前匯出 CLAUDE_CODE_USE_ANTHROPIC_AWS, ANTHROPIC_AWS_WORKSPACE_ID, 以及 ANTHROPIC_AWS_API_KEY 或 AWS 憑證, 導向 Claude Platform on AWS。

import { query } from "@anthropic-ai/claude-agent-sdk";

process.env.CLAUDE_CODE_USE_ANTHROPIC_AWS = "1";
process.env.ANTHROPIC_AWS_WORKSPACE_ID = "wrkspc_01ABCDEFGHIJKLMN";
process.env.AWS_REGION = "us-east-1";

for await (const msg of query({ prompt: "What's in this repo?" })) {
  console.log(msg);
}
說明

此範例依賴環境中既有的 AWS 憑證鏈進行 SigV4 簽署。若改用 workspace API key 認證, 同樣設定 ANTHROPIC_AWS_API_KEY 即可。

透過企業 Proxy 路由

Proxy 或 LLM Gateway 轉發不簽章

設定 ANTHROPIC_AWS_BASE_URL 為 proxy 位址, Claude Code 會用相同的 workspace 與認證標頭送出請求。

export CLAUDE_CODE_USE_ANTHROPIC_AWS=1
export ANTHROPIC_AWS_WORKSPACE_ID=wrkspc_01ABCDEFGHIJKLMN
export ANTHROPIC_AWS_BASE_URL=https://anthropic-proxy.example.com
Gateway 自行簽章

若 Gateway 會自己簽署請求, 設定 CLAUDE_CODE_SKIP_ANTHROPIC_AWS_AUTH=1 讓 Claude Code 送出未簽章請求, 由 Gateway 加上 SigV4 標頭後轉發。

export CLAUDE_CODE_USE_ANTHROPIC_AWS=1
export CLAUDE_CODE_SKIP_ANTHROPIC_AWS_AUTH=1
export ANTHROPIC_AWS_WORKSPACE_ID=wrkspc_01ABCDEFGHIJKLMN
export ANTHROPIC_AWS_BASE_URL=https://anthropic-proxy.example.com

疑難排解

先執行 /status 檢視目前解析到的供應商, 以及明確設定的 workspace ID, 地區, base URL 覆寫與 auth-skip 設定, 這是確認 Claude Code 是否真的指向 Claude Platform on AWS 最快的方法。

症狀
403 Forbidden / AccessDenied
缺少 workspace 錯誤
請求仍打到 api.anthropic.com
可能原因
解析出的 IAM principal 缺少呼叫 workspace 內 Anthropic service 的權限
處理方式
檢查附加在 AWS profile 或啟動 Claude Code 的 runner 上的角色, 確認具備 IAM action reference 文件中列出的 aws-external-anthropic 動作; 若設定了 ANTHROPIC_AWS_API_KEY, 過期的金鑰也會產生相同錯誤, 需要重新產生或取消設定
可能原因
ANTHROPIC_AWS_WORKSPACE_ID 未設定或為空; workspace ID 不會從 AWS 憑證推斷
處理方式
在 AWS Console 的 Workspaces 頁面找到 ID, 於啟動 Claude Code 前匯出該變數
可能原因
CLAUDE_CODE_USE_ANTHROPIC_AWS 未設定或值無法解析為 truthy
處理方式
設定為 1 並執行 /status 確認解析到的供應商; 若同時設定了 CLAUDE_CODE_USE_BEDROCK 或 CLAUDE_CODE_USE_FOUNDRY, 這兩者的優先權高於 Claude Platform on AWS
