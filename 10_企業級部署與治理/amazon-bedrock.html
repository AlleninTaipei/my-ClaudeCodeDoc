Claude Code on Amazon Bedrock

透過 Amazon Bedrock 設定, 部署與排錯 Claude Code, 涵蓋登入精靈, IAM 權限, 模型版本鎖定與 Mantle 端點

前置需求

在透過 Bedrock 設定 Claude Code 之前, 你需要準備以下項目。若只是個人使用, 走登入精靈即可; 若要對整個團隊推行, 建議用手動設定並先鎖定模型版本。

AWS 帳號
已啟用 Bedrock 存取權限的帳號
模型存取
在 Bedrock 中已取得目標 Claude 模型 (例如 Claude Sonnet 4.6) 的存取權
AWS CLI
選用, 只有在沒有其他取得憑證機制時才需要安裝並設定
IAM 權限
具備呼叫 Bedrock 模型所需的權限
路徑選擇

個人使用者用自己的 Bedrock 憑證, 走「登入精靈」流程即可; 若要對團隊推行, 使用「手動設定」並在推行前先鎖定模型版本。

登入 Bedrock 精靈流程

1 · 啟用模型
2 · 啟動並選擇
3 · 依精靈指示

在 Amazon Bedrock 主控台的 Model catalog 中, 選擇一個 Anthropic 模型並送出使用情境表單。送出後即可立即取得存取權。

執行 claude, 在登入提示中選擇 3rd-party platform, 再選擇 Amazon Bedrock。

選擇你要如何驗證 AWS 身分: 從 ~/.aws 偵測到的設定檔, Bedrock API 金鑰, access key 和 secret, 或環境中既有的憑證。精靈會自動偵測區域, 確認帳號可用的模型並讓你鎖定版本, 結果會寫入使用者設定檔的 env 區塊。

Step 1 of 3

登入完成後, 隨時執行 /setup-bedrock 即可重新開啟精靈, 變更憑證, 區域或模型鎖定。

手動設定 (適用 CI 或腳本化部署)

選擇步驟: 1. 提交使用情境 2. 設定憑證 3. 設定 Claude Code 4. 鎖定模型版本

首次使用 Anthropic 模型前, 每個 AWS 帳號都需要提交一次使用情境表單。若使用 AWS Organizations, 可從管理帳號透過 PutUseCaseForModelAccess API 一次提交, 核准會自動延伸到子帳號。

Claude Code 使用預設的 AWS SDK 憑證鏈, 可用以下任一方式設定:

# Option A: AWS CLI 設定
aws configure

# Option B: 環境變數 (access key)
export AWS_ACCESS_KEY_ID=your-access-key-id
export AWS_SECRET_ACCESS_KEY=your-secret-access-key
export AWS_SESSION_TOKEN=your-session-token

# Option E: Bedrock API 金鑰
export AWS_BEARER_TOKEN_BEDROCK=your-bedrock-api-key

進階設定可加入 awsAuthRefresh (偵測到憑證過期時自動重試) 與 awsCredentialExport (每次憑證重新載入時執行, 需輸出 JSON 格式憑證)。

# 啟用 Bedrock 整合
export CLAUDE_CODE_USE_BEDROCK=1
export AWS_REGION=us-east-1  # 若設定檔已有區域則為選用

使用 Bedrock 時, /logout 不可用 (驗證透過 AWS 憑證處理), 且 WebSearch 工具在 Bedrock 上不可用。

export ANTHROPIC_DEFAULT_OPUS_MODEL='us.anthropic.claude-opus-4-8'
export ANTHROPIC_DEFAULT_SONNET_MODEL='us.anthropic.claude-sonnet-4-6'
export ANTHROPIC_DEFAULT_HAIKU_MODEL='us.anthropic.claude-haiku-4-5-20251001-v1:0'
為何重要

不鎖定版本時, sonnet, opus 等別名會解析到 Claude Code 內建的 Bedrock 預設值, 可能落後最新版本。鎖定版本才能控制使用者何時切換到新模型。

啟動時的模型檢查

Claude Code 啟動並設定 Bedrock 時, 會驗證所要使用的模型在帳號中是否可存取 (需要 Claude Code v2.1.94 以上)。

已鎖定較舊版本若帳號可呼叫更新版本, Claude Code 會提示更新鎖定, 接受後寫入使用者設定檔並重啟
未鎖定且預設不可用Claude Code 於當次 session 回退到前一版本並顯示提示, 此回退不會被保存
推論設定檔 ARN指向 application inference profile ARN 的鎖定會被跳過, 因為由管理員管理

IAM 設定

建立含以下權限的 IAM 政策, 讓 Claude Code 可呼叫模型與推論設定檔:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowModelAndInferenceProfileAccess",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream",
        "bedrock:ListInferenceProfiles",
        "bedrock:GetInferenceProfile"
      ],
      "Resource": [
        "arn:aws:bedrock:*:*:inference-profile/*",
        "arn:aws:bedrock:*:*:application-inference-profile/*",
        "arn:aws:bedrock:*:*:foundation-model/*"
      ]
    }
  ]
}
提醒

bedrock:GetInferenceProfile 讓 Claude Code 解析 application inference profile ARN 對應的底層模型。若權杖缺少此權限, Claude Code 會自動重試一次, 但每個新模型都會多一次往返延遲。

1M token 上下文視窗

Claude Sonnet 5, Opus 4.6 以上以及 Sonnet 4.6 在 Amazon Bedrock 上支援 1M token 上下文視窗。Sonnet 5 透過 Mantle 端點提供服務, 且一律以 1M 視窗執行, 不需選擇 [1m] 變體。

設定精靈在鎖定模型時會提供 1M 上下文選項。手動鎖定模型時, 在模型 ID 後加上 [1m] 即可啟用。

服務層級

Amazon Bedrock 服務層級讓你在成本與延遲之間取捨。設定 ANTHROPIC_BEDROCK_SERVICE_TIER 為 default, flex 或 priority:

export ANTHROPIC_BEDROCK_SERVICE_TIER=priority

層級可用性依模型與區域而異。保留容量則使用 provisioned throughput ARN 作為模型 ID, 取代這個設定。

AWS Guardrails

Amazon Bedrock Guardrails 讓你為 Claude Code 實作內容過濾。在主控台建立 Guardrail, 發布版本, 再將 Guardrail 標頭加入設定檔:

{
  "env": {
    "ANTHROPIC_CUSTOM_HEADERS": "X-Amzn-Bedrock-GuardrailIdentifier: your-guardrail-id\nX-Amzn-Bedrock-GuardrailVersion: 1"
  }
}

使用 Mantle 端點

Mantle 是透過原生 Anthropic API 格式服務 Claude 模型的 Bedrock 端點, 而非 Bedrock Invoke API。它使用與上方相同的 AWS 憑證與 IAM 權限。

主題: 啟用 Mantle 選擇模型 與 Invoke API 並行 透過閘道路由 
export CLAUDE_CODE_USE_MANTLE=1
export AWS_REGION=us-east-1

執行 /status 確認, provider 顯示 Amazon Bedrock (Mantle) 即代表 Mantle 已啟用 (需 Claude Code v2.1.94 以上)。

Mantle 使用以 anthropic. 為前綴且無版本後綴的模型 ID, 例如 anthropic.claude-sonnet-5。

claude --model anthropic.claude-haiku-4-5
export CLAUDE_CODE_USE_BEDROCK=1
export CLAUDE_CODE_USE_MANTLE=1

兩者同時設定時, Mantle 格式的模型 ID 路由到 Mantle, 其餘則走 Bedrock Invoke API。

export CLAUDE_CODE_USE_MANTLE=1
export CLAUDE_CODE_SKIP_MANTLE_AUTH=1
export ANTHROPIC_BEDROCK_MANTLE_BASE_URL=https://your-gateway.example.com

若組織透過集中式 LLM 閘道注入 AWS 憑證, 停用用戶端驗證, 讓 Claude Code 傳送不含 SigV4 簽章的請求。

CLAUDE_CODE_USE_MANTLE
啟用 Mantle 端點
ANTHROPIC_BEDROCK_MANTLE_BASE_URL
覆寫預設 Mantle 端點網址
CLAUDE_CODE_SKIP_MANTLE_AUTH
代理設定時跳過用戶端驗證
ANTHROPIC_SMALL_FAST_MODEL_AWS_REGION
覆寫 Haiku 類模型的 AWS 區域

疑難排解

SSO 驗證迴圈企業 VPN 或 TLS 檢查代理中斷 SSO 瀏覽器流程時, 移除 awsAuthRefresh 設定, 改用手動 aws sso login
區域問題用 aws bedrock list-inference-profiles 檢查可用模型, 或改用推論設定檔 ID
/context 顯示 0 tokenv2.1.196 之前的版本, Bedrock 拒絕工具結構描述請求, 更新版本即可修正
Mantle 端點錯誤403 代表帳號未取得模型存取權; 400 代表該模型未在 Mantle 上提供服務
