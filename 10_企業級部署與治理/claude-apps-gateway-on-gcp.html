在 Google Cloud 部署 Claude apps gateway

以 Cloud Run 或 GKE, Cloud SQL for PostgreSQL, Secret Manager 與服務帳號驗證 Agent Platform 的完整範例

你將建置什麼

此範例以 Google Cloud 的 Agent Platform 作為模型上游, 用 Cloud Run 或 GKE 其中一種運算方式部署 Claude apps gateway, 並以 Google Workspace 作為範例身分提供者 (IdP), 但任何符合 OpenID Connect (OIDC) 的 IdP 都可以使用。

Cloud Run / GKE
執行 Gateway 容器的服務或 Deployment
Artifact Registry
存放 Gateway 映像檔的 repository
Cloud SQL for PostgreSQL
僅限私有 IP, 作為 Gateway 的 store
Secret Manager
存放 gateway.yaml, JWT 簽章金鑰, OIDC client secret 與 Postgres URL
服務帳號
具備 roles/aiplatform.user, 在 Cloud Run 上直接附加, 在 GKE 上透過 Workload Identity 綁定
內部負載平衡器
Cloud Run 用內部 Application Load Balancer, GKE 用 class 為 gce-internal 的內部 Ingress

事前準備

GCP 專案已啟用計費, 且具備建立上述資源的權限
CLI 工具已用 gcloud auth login 認證的 gcloud CLI, 以及本機安裝的 Docker
GKE 路線額外需要 kubectl, 以及建立在 Cloud SQL 所在 VPC 上的 GKE 叢集
Model Garden在會發佈這些模型的地區, 具備所需 Claude 模型的存取權
OAuth ClientGoogle Workspace OAuth 2.0 web-application client, redirect URI 為 https://<gateway-host>/oauth/callback
TLS 主機名稱Gateway 的網域, 通常是指向負載平衡器的內部 DNS 名稱

Terraform 參考資源

官方參考部署套件會自動化 Cloud Run 路線, 其中的設定與映像檔資產同時適用於兩種路線。

setup.sh
冪等的 gcloud 佈建腳本, 從啟用 API 到第一次部署走完整條 Cloud Run 路線
terraform/
用基礎設施即程式碼實作相同部署, 適合全新環境
gateway.yaml.example / Dockerfile
distroless 執行期映像檔的設定範例
注意

套件預設把 Cloud Run ingress 設為 internal, 不需要負載平衡器; 若要對齊本頁以 ALB 部署到生產環境的做法, 執行 setup.sh 時加上 INGRESS=internal-and-cloud-load-balancing, 或把 Terraform 變數 ingress 設為 INGRESS_TRAFFIC_INTERNAL_LOAD_BALANCER。這些資產是可運作的範例, 並非受支援的正式產物, 使用前請自行檢視並調整。

疑難排解

Cloud Run 回傳 403
invoker IAM 檢查仍然啟用, 用 --no-invoker-iam-check 部署, 或用 --allow-unauthenticated 授予 allUsers run.invoker
--no-invoker-iam-check 被拒
受 constraints/run.managed.requireInvokerIam 限制, 改用 --allow-unauthenticated, 若組織的網域限制共用也擋下這個選項, 改走 GKE 路線
映像檔架構不符
映像檔是在非 amd64 主機建置, 或 buildx 產出 OCI image index, 需用 --platform=linux/amd64 --provenance=false 重新建置
Postgres 連線逾時
服務未連上 VPC, 或 Cloud SQL 在該 VPC 上沒有私有 IP, 需用 --network 與 --subnet 部署並以 --no-assign-ip 建立 Cloud SQL 實例
Agent Platform 回傳 403
執行環境未使用 claude-gateway 服務帳號, 或該地區的 Model Garden 未啟用此模型
串流回應被截斷
前端請求逾時: GKE Ingress 背後的負載平衡器預設 30 秒, Cloud Run 預設 300 秒, 分別用 BackendConfig 或 --timeout=3600 調整
