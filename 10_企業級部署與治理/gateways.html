透過 Gateway 執行 Claude Code

把 Claude Code 導向自建的 Gateway, 集中管理憑證, 用量追蹤與成本控管

Gateway 如何運作

Gateway 是組織自行架設在 Claude Code 與模型供應商之間的代理伺服器。Claude Code 把 API 流量送到 Gateway, 而不是直接送到供應商, 再由 Gateway 用組織持有的憑證轉發出去。開發者只需向 Gateway 認證, 不必持有供應商憑證, 認證, 用量追蹤, 預算與稽核紀錄因此集中在你可控管的一個地方。

1. 開發者機器Claude Code CLI 或 VS Code 擴充功能, 用每位開發者專屬憑證送出請求
2. 你的基礎設施Gateway 負責認證, 用量追蹤, 預算與路由決策
3. 模型供應商Gateway 用組織的供應商憑證轉發請求, 目的地可設為 Anthropic API, Amazon Bedrock, Google Cloud 或 Microsoft Foundry
Developer credential
每位開發者各自持有, 由 Gateway 發出, 用於向 Gateway 認證並在用量追蹤中識別身分
Provider credential
Gateway 持有一份供應商帳號憑證, 由所有轉發流量共用

選擇 Gateway

Claude Code 可搭配 Anthropic 自家的 Gateway, 或組織已經在用的 Gateway。

選擇方案
Claude apps gateway
其他 Gateway
內建方式
Anthropic 自建的 Gateway, 內含在 claude 執行檔中, 上游可路由至 Amazon Bedrock, Google Cloud, Microsoft Foundry 或 Anthropic API
登入方式
開發者透過 /login 用企業身分提供者 (IdP) 登入, Gateway 依 IdP 群組套用模型存取與 managed settings
遙測
會發送 OpenTelemetry Protocol (OTLP) 用量指標到你自己的觀測平台
維護優勢
與每次 Claude Code 版本一起發佈, 自動轉發最新的標頭與請求欄位, 不需要像自維護 Gateway 一樣手動更新轉發規則
限制
登入是瀏覽器 SSO 流程, 沒有 service-token 流程, 因此無人核准登入的 CI 管線無法透過它認證
適用情境
組織已經在營運自己的 LLM Gateway 或 API Gateway 時可以直接沿用
Anthropic 立場
不背書, 不維護, 也不稽核其他 Gateway 產品, 也不支援透過任何 Gateway 把 Claude Code 導向非 Claude 模型
TIP

Gateway 的設定決定實際轉發到哪個供應商, 使用 Claude apps gateway 或任何暴露單一 Anthropic 格式端點的 Gateway, 更換供應商時不需要改動開發者的機器設定。

訂閱與 Gateway 的關係

開發者透過帶有 Gateway 憑證的連線登入時, 用量會依 API 費率計入組織的供應商帳號, claude.ai 訂閱不會被使用或收費。

會停用訂閱登入

設定 ANTHROPIC_AUTH_TOKEN 給自建 Gateway, 或用 /login 登入 Claude apps gateway, 都會關閉該次 session 的訂閱登入。

該憑證下轉發的每一筆請求都會計費到 Gateway 供應商憑證背後的帳號。

例外: 只設定 ANTHROPIC_BASE_URL

不搭配 Gateway 憑證時, 請求仍會經過 Gateway, 但已儲存的 claude.ai 登入仍是有效憑證。

這種情況下訂閱的用量限制與帳單規則仍然適用。

哪些設定不屬於 Gateway 管轄

Gateway 負責路由模型 API 請求, 但有幾件你可能以為它會處理的事其實是分開設定的。

選擇模型
用 /model 指令或模型環境變數挑選, Gateway 只決定請求送去哪裡, 不決定開發者選哪個模型; Claude apps gateway 可用 availableModels 白名單限縮選項
其他網路流量
版本檢查與下載會直接送往 Anthropic, 與 Gateway 路徑分開; 選用的用戶端遙測是否啟用則依供應商而定
企業 HTTP Proxy
HTTPS_PROXY 會介於 Claude Code 與它連線的每一台伺服器之間, 包含 Gateway 本身, 需要額外設定; Claude apps gateway 登入會檢查 Proxy 主機是否也在私有網路上
