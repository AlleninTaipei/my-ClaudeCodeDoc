Enterprise deployment overview

How Claude Code integrates with third-party services and infrastructure to meet enterprise deployment requirements.

OVERVIEW

Organizations can deploy Claude Code through Anthropic directly or through a cloud provider. For most organizations, Claude for Teams or Claude for Enterprise provides the best experience: a single subscription covering both Claude Code and Claude on the web, centralized billing, and no infrastructure setup. Claude for Teams is self-service with collaboration features and billing management, best for smaller teams. Claude for Enterprise adds SSO, domain capture, role-based permissions, compliance API access, and managed org-wide policy — best for larger organizations with security and compliance requirements.

Configure proxies and gateways

Most organizations can use a cloud provider directly. Configure a corporate proxy or LLM gateway only if your organization has specific network or management requirements — the two can be combined.

Corporate proxy

Routes traffic through an HTTP/HTTPS proxy. Use for security monitoring, compliance, or network policy enforcement. Configure with HTTPS_PROXY or HTTP_PROXY.

LLM Gateway

Sits between Claude Code and the cloud provider for auth and routing. Use for centralized usage tracking, custom rate limiting/budgets, or centralized auth. Configure with ANTHROPIC_BASE_URL and provider-specific variants.

Select a provider, then a configuration style, to see the environment variables to set in your shell profile (.bashrc, .zshrc).

Best practices for organizations

Invest in documentation and memory

Deploy CLAUDE.md files at multiple levels: organization-wide in system directories for company-wide standards, and repository-level checked into source control so all users benefit.

Simplify deployment

If you have a custom development environment, a "one click" way to install Claude Code is key to growing adoption across an organization.

Start with guided usage

Encourage new users to try Claude Code for codebase Q&A or smaller bug fixes. Ask it to make a plan, check its suggestions, and give feedback if it's off-track before letting it run more agentically.

Pin model versions for cloud providers

On Bedrock, Vertex, Foundry, or Claude Platform on AWS, pin versions with ANTHROPIC_DEFAULT_*_MODEL. Without pinning, aliases resolve to Claude Code's built-in default, which can lag the newest release.

Configure security policies

Security teams can configure managed permissions for what Claude Code is and is not allowed to do, which cannot be overwritten by local configuration.

Leverage MCP for integrations

Connect to ticket systems or error logs. One central team should configure MCP servers and check a .mcp.json into the codebase so all users benefit.

Next steps

Once you've chosen a deployment option and configured access for your team, work through these three steps.

1Roll out to your team — share installation instructions and have team members install Claude Code and authenticate with their credentials.
2Set up shared configuration — create a CLAUDE.md file in your repositories to help Claude Code understand your codebase and coding standards.
3Configure permissions — review security settings to define what Claude Code can and cannot do in your environment.
