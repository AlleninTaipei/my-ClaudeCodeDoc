Claude Apps Gateway 設定參考

gateway.yaml 每個欄位: 監聽與 TLS, OIDC, session, Postgres, 上游, 模型路由, managed 政策與遙測

檔案結構

五個區段是必要的, 其餘為選用並採用預設值。未知的欄位會導致開機失敗, 因此打錯字會出現明確的錯誤而非被靜默忽略。

必要區段

listen, oidc, session, store, upstreams

選用區段

admin, enforcement, models, managed, telemetry, access_control / limits / timeouts / rate_limits

機密展開

不要把 client_secret, jwt_secret, postgres_url 直接寫在 gateway.yaml 中, 改用 ${VAR} (環境變數) 或 ${file:/path} (檔案內容, 適用 Kubernetes Secret 或 Vault)。

listen 與 oidc

區段: listen oidc
host / port
預設 0.0.0.0 / 8080
public_url
對外可見的 https 來源, 用於 IdP redirect_uri 與 discovery, 在 TLS 終止代理後方為必要
tls.cert / tls.key
若閘道自行終止 TLS 則需要的 PEM 路徑
trusted_proxies
前方負載平衡器的 CIDR, 用於信任 X-Forwarded-For 並記錄真實客戶端 IP
issuer
OIDC discovery 基底, 必須提供 /.well-known/openid-configuration
client_id / client_secret
來自 OAuth 用戶端註冊
allowed_email_domains
拒絕 email 網域不符的 id_token
allowed_groups
限制只有特定 IdP 群組成員可登入
userinfo_fallback
id_token 缺少 email 或 groups 時改用 /userinfo 補齊
use_pkce
預設 true, 傳送 PKCE 挑戰

session 與 store

session:
  jwt_secret: ${GATEWAY_JWT_SECRET}   # openssl rand -base64 32
  ttl_hours: 1                        # 也界定撤銷延遲

store:
  postgres_url: ${GATEWAY_POSTGRES_URL}
  max_connections: 5
輪替 JWT 密鑰

jwt_secret 接受單一字串或陣列, 索引 0 用來簽章, 全部項目都能驗證。要輪替時先加入新密鑰, 等 ttl_hours 之後再移除舊密鑰。

upstreams 上游

upstreams 是有序清單, 閘道轉發推論給第一個能解析所需模型的上游。5xx, 429 或逾時會容錯移轉到下一個。

選擇上游: Anthropic API Amazon Bedrock Google Agent Platform Microsoft Foundry 
upstreams:
  - provider: anthropic
    auth:
      api_key: ${ANTHROPIC_API_KEY}
upstreams:
  - provider: bedrock
    region: us-east-1
    auth: {}  # AWS 預設憑證鏈
upstreams:
  - provider: vertex
    region: us-east5
    project_id: example-prod
    auth: {}  # Application Default Credentials
upstreams:
  - provider: foundry
    resource: example-foundry
    auth: { use_azure_ad: true }

同一 provider 可搭配不同 name: 出現多次, 用於不同區域, 帳號, provisioned throughput 與跨 provider 容錯移轉。

admin 與 enforcement

啟用 admin: 區塊後, 閘道會提供 /v1/organizations/spend_limits 與每位開發者的即時花費強制執行。

write_keys / read_keys
具名的靜態 API 金鑰, 分別對應寫入與唯讀權限
admin_groups
IdP 群組中屬於此列表者透過一般閘道 JWT 取得完整管理權限
fail_closed_on_error
Postgres 無法連線時, 預設 fail-open, 設 true 改為 fail-closed

managed 政策

managed 區塊依 IdP 群組或 email 網域定義以角色為基礎的存取政策, 依序評估, 第一個相符者套用, 再與 match: {} 兜底層合併。

managed:
  policies:
    - match: { groups: [eng-contractors] }
      cli:
        availableModels: [claude-sonnet-4-6]
        permissions: { deny: ["WebFetch", "WebSearch"] }
    - match: {}
      cli:
        availableModels: [claude-opus-4-8, claude-sonnet-4-6, claude-haiku-4-5]
Allow-listsavailableModels 與 permissions.allow, 特定政策的清單會完全取代基底
Deny-lists / hooks取基底與政策的聯集, 避免組織層級規則被意外移除
Record 型別env, modelOverrides, skillOverrides 採淺層合併

telemetry 遙測

telemetry:
  forward_to:
    - url: https://otel-collector.internal.example.com
      headers:
        Authorization: ${OTLP_TOKEN}
      metrics: true
      logs: false
      traces: false
敏感度

Metrics 是彙總計數, Logs 與 Traces 可能包含完整的 bash 指令與檔案路徑, 只在具備存取控制與保留政策的目的地開啟後兩者。

完整範例與用戶端設定

把以下兩個鍵設在每台裝置的 managed-settings.json 中, 讓 /login 直接開啟 Cloud gateway 畫面:

{
  "forceLoginMethod": "gateway",
  "forceLoginGatewayUrl": "https://claude-gateway.internal.example.com"
}
macOS/Library/Application Support/ClaudeCode/managed-settings.json
Linux / WSL/etc/claude-code/managed-settings.json
WindowsC:\Program Files\ClaudeCode\managed-settings.json 或 HKLM 登錄
