Roll Out an LLM Gateway for Your Organization

部署 gateway 產品: 設定轉發, 核發開發者憑證, 透過 managed settings 分發, 並驗證導入結果

Gateway 需求

不論選擇哪一款產品, gateway 都必須符合以下要求.

接受支援的 API 格式
預設走 Anthropic Messages API 的 POST /v1/messages
串流回應
即時轉發 server-sent events, 不緩衝整個回應
路由模型名稱
把每個開發者使用的名稱對應到上游模型
原樣轉發表頭與主體
anthropic-beta, anthropic-version 與請求主體雙向轉發
不修改上游錯誤
自動復原機制依錯誤字句比對, 包裝錯誤會破壞復原路徑
豁免 WAF 主體檢查
Claude Code 提示含原始碼與 XML 標籤, 易誤觸 XSS 規則

導入五步驟

1 · 確認路由
2 · 核發憑證
3 · 測試 Claude Code
4 · 分發設定
5 · 驗證導入
curl -X POST "https://llm-gateway.example.com/v1/messages" \
  -H "Authorization: Bearer <gateway-key>" \
  -d '{"model": "claude-sonnet-4-6", "max_tokens": 1, "messages": [...]}'

檢查點: 200 且有 content 欄位代表 gateway 能連到 provider, 404 代表該名稱未路由, 401 代表 provider 憑證錯誤. 對每個模型名稱重複測試.

每位開發者需要自己的 gateway 金鑰. 用同樣的請求測試新核發的金鑰, 確保能通過驗證.

檢查點: 200 代表開發者金鑰生效; 401 代表金鑰錯誤或尚未在 gateway 生效.

export ANTHROPIC_BASE_URL=https://llm-gateway.example.com
export ANTHROPIC_AUTH_TOKEN="<developer-key>"
claude -p "Reply with one word: connected"

檢查點: 提示回傳結果, 且 gateway 日誌出現對 /v1/messages 的 POST 且狀態 200.

{
  "env": { "ANTHROPIC_BASE_URL": "https://llm-gateway.example.com" },
  "apiKeyHelper": "/usr/local/bin/get-gateway-key"
}

透過 managed settings 的 env 區塊分發, 讓 managed ANTHROPIC_BASE_URL 無法被開發者的 shell export 覆蓋.

在開發者機器而非 gateway 主機上測試, 涵蓋開發者實際使用的網路路徑. 送出串流請求, 一次確認端點, 串流轉發與模型路由.

檢查點: claude 啟動不顯示登入畫面, /status 顯示 gateway 位址且 Setting sources 包含 managed settings.

Step 1 of 5

要分發的設定項目

ANTHROPIC_BASE_URL一定要有, 把請求送到 gateway 而非 api.anthropic.com
憑證變數或 apiKeyHelper一定要有其中一種, 用來驗證每個請求
ANTHROPIC_CUSTOM_HEADERSgateway 要求每個請求都帶租戶或路由表頭時加入
CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERYgateway 提供 /v1/models 且想讓選單自動填入時加入
CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETASgateway 轉發到不接受 beta 欄位的上游時加入
WARNING

不要在 managed settings 中加入 forceLoginMethod 或 forceLoginOrgUUID 與 gateway 憑證並存, 這會讓開發者卡在需要第一方登入的錯誤訊息.

維護 Gateway

導入後有三種變化會持續影響 gateway, 各自有對應的觀察指標與行動.

新版 Claude Code 發布

症狀: 開發者更新後回報命名新欄位的 400

行動: 原樣轉發 anthropic-* 表頭與主體, 而非用白名單

新模型上線

症狀: 選擇新模型名稱得到 404, /model 選單未列出

行動: 在 gateway 路由設定加入模型名稱, 重新執行路由檢查

設定每組金鑰的速率限制時, 記得客戶端會對暫時性失敗與 429 重試最多 10 次, 並遵守 Retry-After.
