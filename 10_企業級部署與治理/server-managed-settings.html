Configure Server-Managed Settings

學習如何透過伺服器交付的設定, 不需裝置管理基礎設施就能集中設定整個組織的 Claude Code。

Choose between server-managed and endpoint-managed settings

Server-managed settings

適合: 沒有 MDM 的組織, 或使用非受管裝置的使用者

安全模型: 在驗證時從 Anthropic 伺服器交付設定

Endpoint-managed settings

適合: 已有 MDM 或端點管理方案的組織

安全模型: 透過 MDM 設定檔, 登錄檔政策或 managed settings 檔案部署到裝置

NOTE

若裝置已加入 MDM, endpoint-managed settings 能提供更強的安全保證, 因為設定檔可在作業系統層級防止使用者修改。Endpoint-managed settings 無法送達雲端 session, 因此使用 Claude Code on the web 的組織應同時設定 server-managed settings。

Configure server-managed settings

1 · 開啟管理主控台
2 · 定義設定
3 · 儲存與部署

在 claude.ai 主控台前往 Admin Settings > Claude Code > Managed settings。若連結導向不同頁面, 表示帳戶沒有所需角色, 請洽組織中的 Owner 或 Primary Owner。

以 JSON 新增設定。settings.json 支援的設定幾乎都可用 (除受限於 OS 層級政策交付的少數例外)。以下範例強制權限拒絕清單並限制權限規則只能來自 managed settings:

{
  "permissions": {
    "deny": [
      "Bash(curl *)",
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)"
    ],
    "disableBypassPermissionsMode": "disable"
  },
  "allowManagedPermissionRulesOnly": true
}

Hooks 使用與 settings.json 相同的格式, 以下範例在每次編輯後執行稽核腳本:

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "/usr/local/bin/audit-edit.sh" }
        ]
      }
    ]
  }
}

儲存變更後, Claude Code 客戶端會在下次啟動或每小時輪詢週期收到更新後的設定。

Verify settings delivery

請使用者重新啟動 Claude Code 以確認設定已套用; 若設定會觸發安全核准對話框, 使用者會在啟動時看到說明提示。也可請使用者執行 /permissions 檢視生效中的權限規則。

Server-managed 與 endpoint-managed settings 都位於 Claude Code 設定階層的最高層級, 任何其他層級 (含命令列參數) 都無法覆蓋。設定了 policyHelper 時, 它的輸出會凌駕所有其他 managed 來源。否則, server-managed settings 會先被檢查, 再檢查 endpoint-managed settings, 兩者不會合併: 只要 server-managed 交付任何鍵, 其餘 endpoint-managed 設定就會被忽略。

首次啟動 (無快取)非同步擷取設定, 失敗則繼續執行, 期間有短暫的未強制執行窗口
後續啟動 (有快取)快取設定立即套用, 背景重新擷取最新設定, 網路失敗時快取設定持續生效

交付的內容以與其他 managed 來源相同的規則寬鬆解析: 驗證失敗的項目會被移除, 系統顯示驗證錯誤, 其餘有效設定照常套用。快取存放於 ~/.claude/remote-settings.json, 只儲存去除無效項目後的內容, 原始無效內容不會被保留。

設定 forceRemoteSettingsRefresh: true 後, CLI 會在啟動時阻塞直到成功取得最新的遠端設定, 取得失敗則直接結束而非繼續執行。此設定具自我延續性, 一旦從伺服器交付過, 就會快取在本機, 讓之後的啟動即使尚未成功擷取新 session 的設定, 也會強制執行相同行為。

{
  "forceRemoteSettingsRefresh": true
}

Platform availability 平台可用性

Server-managed settings 需要直接連線到 api.anthropic.com, 且需以組織 OAuth 登入或直接設定的 API key 進行驗證。以下第三方模型提供者不支援 server-managed settings:

Amazon Bedrock不支援
Google Vertex AI不支援
Microsoft Foundry不支援
Claude Platform on AWS不支援
自訂 API 端點 / 第三方 LLM gateway不支援
TIP

對於 Bedrock, Vertex AI, Foundry 部署, 自架的 Claude apps gateway 可提供對等的遠端 managed settings 交付機制。

Audit logging 稽核紀錄

設定變更的稽核紀錄事件可透過 compliance API 或稽核紀錄匯出取得, 包含操作類型, 執行的帳戶與裝置, 以及新舊值的參照。請聯絡 Anthropic 帳戶團隊以取得存取權限。

Security considerations 安全考量

Server-managed settings 提供集中化政策強制執行, 但它是用戶端控制, 而非安全邊界。在非受管裝置上, 使用者不需要管理員權限就能繞過它。

使用者編輯快取設定檔竄改後的檔案會在啟動時套用, 但下次伺服器擷取後會還原正確設定
使用者刪除快取設定檔視為首次啟動, 非同步擷取設定, 期間有短暫未強制執行窗口
使用者執行修改過的執行檔能執行修改版客戶端的使用者可繞過任何用戶端控制
使用者執行舊版 Claude Code早於 server-managed settings 支援的版本不會擷取或套用設定
API 無法連線若有快取設定則套用, 否則直到下次成功擷取前不強制執行
使用者以其他組織驗證受管組織以外的帳戶不會收到設定
使用者改用第三方模型提供者Server-managed settings 會被略過
網路流量遭攔截或重導向停用 TLS 驗證或攔截流量可能改變用戶端收到的設定內容
