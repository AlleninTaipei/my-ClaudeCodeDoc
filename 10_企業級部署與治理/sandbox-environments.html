Choose a Sandbox Environment

比較 Claude Code 的沙盒選項: 內建的 sandboxed Bash 工具, sandbox runtime, dev container, Docker 與虛擬機, 依威脅模型選出合適的隔離方式。

Compare sandboxing approaches

下表前兩種方式運行在主機作業系統上, 不使用容器; 其餘方式則將 Claude Code 放進容器或虛擬機中。

Sandboxed Bash tool
隔離: Bash 指令與子行程 / 需要 Docker: 否 / 設定難度: macOS 極低, Linux/WSL2 低
Sandbox runtime
隔離: 整個 Claude Code 行程 (含檔案工具, MCP, hooks) / 需要 Docker: 否 / 設定難度: 低
Dev container
隔離: 完整開發環境 / 需要 Docker: 是 / 設定難度: 中
Custom container
隔離: 完整開發環境 / 需要 Docker: 是 / 設定難度: 中至高
Virtual machine
隔離: 完整作業系統 / 需要 Docker: 否 / 設定難度: 高
Claude Code on the web
隔離: 完整作業系統, 由 Anthropic 代管 / 需要 Docker: 否 / 設定難度: 無, 需訂閱與 GitHub
WARNING

沙盒隔離能降低外洩的影響範圍, 但不能完全消除風險。任何允許網路對外連線的方式仍可能外洩資料, 任何以可寫方式掛載專案目錄的方式仍可能修改程式碼。隔離也不會改變傳送給模型的內容, 你的提示與 Claude 讀取的檔案一律會傳送給 Anthropic API 或你設定的提供者。

How isolation relates to permission modes

Permission modes

決定工具呼叫是否執行, 以及是否要先詢問你。

Isolation

限制指令執行後能存取到什麼。兩者互補: 當權限模式允許動作不經詢問就執行時, 隔離邊界限制了這些動作能觸及的範圍。

NOTE

--dangerously-skip-permissions 移除了除明確 ask 規則外的逐項審查, 因此隔離邊界是唯一能限制 Claude 行為的機制, 務必搭配容器, VM 或 sandbox runtime 使用。Auto mode 則用分類器取代提示, 屬於逐項控制而非隔離邊界。

Sandboxed Bash tool

Sandboxed Bash tool 內建於 Claude Code, 使用作業系統原生機制限制每個 Bash 指令的檔案系統與網路存取: macOS 用 Seatbelt, Linux 與 WSL2 用 bubblewrap。預設允許寫入工作目錄, 且第一次需要新網路網域時會提示核准。

Read / Edit / WebFetch在 Claude Code 行程內執行, 不會產生任意程式碼, 改由路徑或網域的權限規則把關
MCP 伺服器與 hooks是獨立行程, 在主機上不受限制執行

若要把內建工具, MCP 伺服器與 hooks 都納入同一個 OS 邊界, 需要使用 sandbox runtime, dev container 或 custom container。

Sandbox runtime

@anthropic-ai/sandbox-runtime 套件將整個行程包在與內建 Bash 沙盒相同的 Seatbelt 或 bubblewrap 隔離中。透過它執行 Claude Code 會限制該 session 中的每個工具, hook 與 MCP 伺服器, 而不只是 Bash。此 runtime 為 beta 研究預覽版。

npx @anthropic-ai/sandbox-runtime claude
NOTE

Runtime 預設拒絕所有寫入與網路存取, 需先在 ~/.srt-settings.json 中設定允許寫入專案目錄與 ~/.claude, ~/.claude.json, 以及允許 session 所需的網路網域。

Dev containers

Dev container 透過 VS Code 或相容編輯器管理的 Docker 容器執行 Claude Code, 並掛載你的專案。你可以在儲存庫中用 .devcontainer/ 目錄定義自己的環境。

claude-code 儲存庫發佈了一個內含預設拒絕 iptables 防火牆的範例 dev container, 可作為起點複製進你的儲存庫, 並調整防火牆允許清單, 基底映像與 Claude Code 版本。因為防火牆會封鎖未核准的對外流量, 這種設定足以支援以 --dangerously-skip-permissions 進行無人值守工作。

Custom container

你可以在任何 Docker 或 OCI 容器映像中執行 Claude Code, 搭配自訂的網路政策, 掛載磁區與 seccomp profile。這是擁有既有容器基礎設施或 CI runner 的組織最常見的做法。

檢查清單與其他容器方式相同: 檢視哪些磁區以可寫方式掛載, 容器內能存取到哪些憑證與 token, 以及網路對外政策允許什麼。你也可以在容器內再疊加內建 Bash 沙盒做逐指令限制。

Virtual machine

專屬虛擬機提供最強的隔離, 擁有自己的核心, 在雲端或 microVM 部署中甚至有自己的虛擬化硬體。選項包含雲端執行個體, 本地 hypervisor, 以及 Firecracker 等 microVM。

適用情境: 評估不受信任的程式碼, 安全政策要求核心層級的隔離, 或沒有任何主機層級方式能滿足合規需求時。Docker Desktop 的 sandboxes 功能提供含獨立 Docker daemon 與工作區同步的 microVM。

Claude Code on the web

Claude Code on the web 讓每個 session 在隔離的, 由 Anthropic 代管的虛擬機中執行。網路代理伺服器強制執行預設允許清單, 另一個代理伺服器則將你的 GitHub token 保存在沙盒之外, 只在沙盒內發放範圍受限的憑證。

適用情境: 想要完整 VM 隔離但不想自行建置基礎設施, 或是從沒有本地開發環境的裝置委派任務時。需要 Claude 訂閱與已連接的 GitHub 帳戶。

Enforce isolation across an organization

個別開發者可以自行選擇上述任一方式, 而組織能強制的範圍與工具則依方式而異:

內建 Bash 沙盒
Claude Code 自身唯一能強制執行的方式, 透過 managed settings 或 MDM 交付 sandbox 設定鍵
Dev containers
將範例 dev container 提交到儲存庫以標準化團隊環境, 屬於慣例而非強制邊界
Custom containers 與 VM
透過核准的映像散布 Claude Code, 並用組織的裝置管理或軟體允許清單工具防止在外部安裝
