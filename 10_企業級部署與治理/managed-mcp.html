任何地方都不會載入伺服器. 設定方式: managed-mcp.json 帶空的伺服器對映.

每位使用者拿到相同的伺服器組合, 且無法新增其他伺服器. 設定方式: managed-mcp.json 帶想要的伺服器.

發布核准清單, 使用者自行加入想要的伺服器, 其餘一律封鎖. 設定方式: allowedMcpServers 搭配 allowManagedMcpServersOnly: true.

伺服器只能來自 plugin, 使用者無法自行新增. 設定方式: strictPluginOnlyCustomization 中加入 mcp.

強制執行允許清單, 但使用者可以在自己的設定中擴大範圍. 設定方式: allowedMcpServers, 不加 allowManagedMcpServersOnly.

封鎖已知不良的伺服器, 其餘全部放行. 設定方式: deniedMcpServers.

用 managed-mcp.json 完全控制

部署此檔案後, Claude Code 只會載入檔案中定義的伺服器, 使用者無法新增, 修改或使用任何其他伺服器, 包含 plugin 提供的伺服器.

macOS
/Library/Application Support/ClaudeCode/managed-mcp.json
Linux 與 WSL
/etc/claude-code/managed-mcp.json
Windows
C:\Program Files\ClaudeCode\managed-mcp.json
格式
與專案層級 .mcp.json 相同的 mcpServers 結構
{
  "mcpServers": {
    "github": { "type": "http", "url": "https://api.githubcopilot.com/mcp/" }
  }
}
SECURITY

這個檔案任何使用者都能讀取, 不要在 env 區塊存放 API 金鑰. 改用 ${VAR} 展開, OAuth 或 headersHelper 傳遞每人各自的憑證.

如何評估一個伺服器

載入任何伺服器前, Claude Code 依序執行三個檢查.

1 · 合併清單
2 · 檢查封鎖清單
3 · 檢查允許清單

來自每個設定來源的允許清單與封鎖清單項目合併成一個允許清單與一個封鎖清單. allowManagedMcpServersOnly 為 true 時只保留 managed 的允許清單.

符合任何封鎖清單項目的伺服器會被封鎖, 沒有任何東西能覆蓋封鎖清單的判定.

若未設定 allowedMcpServers, 通過封鎖清單的伺服器都會載入; 若有設定, 遠端伺服器要符合 serverUrl, stdio 伺服器要符合 serverCommand.

Step 1 of 3

比對方式: URL, 指令或名稱

serverUrl

比對遠端伺服器 URL, 支援 * 萬用字元, 主機名稱不分大小寫

serverCommand

比對啟動 stdio 伺服器的完整指令與參數, 每個參數都要完全一致

WARNING

serverName 不是安全控制, 使用者可以把任何伺服器命名為 github. 要真正管控實際運行的伺服器, 加入 serverCommand 或 serverUrl 項目.

限制發生時使用者看到什麼

managed-mcp.json 存在時新增伺服器Cannot add MCP server: enterprise MCP configuration is active
伺服器在封鎖清單上Cannot add MCP server: server is explicitly blocked by enterprise policy
伺服器不在允許清單上Cannot add MCP server: not allowed by enterprise policy
既有伺服器被新政策封鎖伺服器從 /mcp 與 claude mcp list 中悄悄消失, 沒有警告

在最後一種情境中使用者不會收到任何政策原因的訊號, 部署新限制前務必告知受影響的使用者哪些伺服器被封鎖.
