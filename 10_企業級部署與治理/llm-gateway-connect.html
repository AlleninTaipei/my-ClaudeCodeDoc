檢查是否已經有現成設定

管理員可能已經透過 managed settings, 裝置管理或 apiKeyHelper 分發了 gateway 位址與憑證, 這樣 Claude Code 啟動時就會自動套用.

自行設定 Claude Code

點選下方主題查看對應設定方式.

主題:
憑證變數
設定 Base URL
驗證連線
憑證對應表頭
與現有登入的衝突
ANTHROPIC_AUTH_TOKEN
gateway 團隊說是 bearer token 或 Authorization header 時使用
ANTHROPIC_API_KEY
gateway 團隊說是 API key 或 x-api-key 時使用
apiKeyHelper
憑證會輪替或來自 vault 時使用
TIP

不確定用哪一種時, 先用 ANTHROPIC_AUTH_TOKEN, 驗證請求會告訴你是否要換一個.

export ANTHROPIC_BASE_URL=https://llm-gateway.example.com
export ANTHROPIC_AUTH_TOKEN=sk-gateway-key

也可以寫進 settings 檔案的 env 區塊, 讓設定套用到 Claude Code 執行的每個地方. 專案的 .claude/settings.json 會被提交並分享給所有 clone 者, 千萬不要把憑證放進去.

curl -X POST "$ANTHROPIC_BASE_URL/v1/messages" \
  -H "Authorization: Bearer $ANTHROPIC_AUTH_TOKEN" \
  -H "anthropic-version: 2023-06-01" \
  -d '{"model": "claude-sonnet-4-6", "max_tokens": 1, "messages": [...]}'

回傳以 {"id":"msg_ 開頭的 JSON 代表 gateway 可連線且憑證有效. 401 代表憑證被拒絕, 換另一個變數再試一次.

ANTHROPIC_AUTH_TOKEN送進 Authorization: Bearer 表頭
ANTHROPIC_API_KEY送進 x-api-key 表頭
apiKeyHelper同時送進兩個表頭

gateway 憑證變數優先於已儲存的 claude.ai 登入或 Console key. ANTHROPIC_AUTH_TOKEN 會立即生效, ANTHROPIC_API_KEY 則會在互動模式下提示核准一次.

執行 /status 確認目前啟用的憑證來源, 執行 /logout 可清除已儲存登入, 只留下 gateway 憑證.

設定各個介面

CLI 會讀取環境變數與 settings 檔案, 其他介面的設定方式各不相同.

介面:
VS Code
Desktop
GitHub Actions
Agent SDK
Slack / Web / Remote Control
{
  "claudeCode.environmentVariables": [
    { "name": "ANTHROPIC_BASE_URL", "value": "https://llm-gateway.example.com" },
    { "name": "ANTHROPIC_AUTH_TOKEN", "value": "sk-gateway-key" }
  ]
}

擴充套件會在啟動前先從這個設定檢查憑證, 是放置 gateway 憑證最可靠的位置.

桌面應用程式只從管理員分發的設定讀取 gateway 路由, 不會讀 ANTHROPIC_BASE_URL 或 settings.json. 若組織已分發設定, 桌面 session 會自動經由 gateway; 若沒有, 改用終端機 CLI 或 VS Code 擴充套件.

env:
  ANTHROPIC_BASE_URL: https://llm-gateway.example.com

steps:
  - uses: anthropics/claude-code-action@v1
    with:
      anthropic_api_key: ${{ secrets.GATEWAY_API_KEY }}

x-api-key 型 gateway 用上面方式; bearer-token 型 gateway 需要同一組密鑰同時放進 anthropic_api_key 輸入與 env 中的 ANTHROPIC_AUTH_TOKEN.

// TypeScript: 需展開 process.env 才能保留 gateway 變數
const result = query({
  options: { env: { ...process.env, ANTHROPIC_BASE_URL: "..." } }
})

Python 的 ClaudeAgentOptions(env=...) 會疊加在繼承的環境變數之上, 不需要展開.

Claude Code in Slack 與 Claude Code on the web 是 Anthropic 代管產品, 一律使用 Anthropic API, 不屬於 gateway 部署的一部分, cloud session 設定的 gateway 變數不會生效.

NOTE

Remote Control 與 voice dictation 都依賴 claude.ai 身份, 在 ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN 或 apiKeyHelper 生效時會無法使用.

其他設定項目

以下設定僅在管理員或疑難排解表明確指示時才需要設定.

項目:
額外表頭
Model discovery
apiKeyHelper 輪替
路由到雲端 provider
export ANTHROPIC_CUSTOM_HEADERS="X-Org-Route: prod"

某些 gateway 會用額外表頭做路由或標記, 例如租戶識別或路由鍵.

啟動時查詢 gateway 的模型清單, 加入 /model 選單. 設定 CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1 即可啟用, 需要 Claude Code v2.1.129 以上.

當憑證會定期過期, 來自 vault 或 SSO 指令時使用. Helper 是任何會把目前憑證印到 stdout 的 shell 指令, 預設快取 5 分鐘, 遇到 401 會重新執行.

Amazon BedrockANTHROPIC_BEDROCK_BASE_URL + CLAUDE_CODE_SKIP_BEDROCK_AUTH=1
Agent PlatformANTHROPIC_VERTEX_BASE_URL + CLAUDE_CODE_SKIP_VERTEX_AUTH=1
Microsoft FoundryANTHROPIC_FOUNDRY_BASE_URL + ANTHROPIC_FOUNDRY_API_KEY
Claude Platform on AWSANTHROPIC_AWS_BASE_URL + ANTHROPIC_AWS_WORKSPACE_ID

疑難排解 Gateway 錯誤

401 無效憑證憑證不是 gateway 核發的, 或送到 gateway 不讀取的表頭, 確認變數對應是否正確
ConnectionRefusedbase URL 位址錯誤, 或 VPN 與防火牆阻擋路徑
200 但回應為空或格式錯誤gateway 或中介 proxy 回傳非 API 回應, 常見是 HTML 錯誤頁
400 context_management 相關上游拒絕不認得的欄位, 可設定 CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1
模型未列在 /model 選單gateway 的模型名稱不在內建清單, 啟用 model discovery 或手動加入
TLS/憑證錯誤執行環境未信任同一憑證機構, 設定 NODE_EXTRA_CA_CERTS
