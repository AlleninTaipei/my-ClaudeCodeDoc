Claude Apps Gateway

透過自架閘道在 Amazon Bedrock, Google Cloud 或 Microsoft Foundry 上執行 Claude Code, 具備 SSO 登入, 依群組控管模型存取與 OTLP 遙測

為何選擇 Claude Apps Gateway

Claude apps gateway 是內建在 claude 執行檔中的 Anthropic 自架閘道, 隨每次 Claude Code 發布一起測試, 因此能正確轉發 CLI 傳送的標頭與請求欄位。

憑證
上游 API 金鑰或雲端憑證只存在你的基礎設施, 開發者以企業 SSO 驗證並取得短期權杖
存取控制
IdP 群組對應模型允許清單與 managed settings 政策, 由伺服器端強制執行
設定分發
閘道直接將 managed settings 送達已登入的用戶端
遙測
每個設定的目的地都會收到含 token 數, 模型, 使用者身分與延遲的 OTLP 指標
上游路由
用戶端說 Anthropic Messages API, 閘道轉譯給 Bedrock, Agent Platform, Foundry 或 Anthropic API, 並支援容錯移轉

快速入門

最小路徑: 在 IdP 註冊 OAuth 用戶端, 撰寫 gateway.yaml, 用 Docker Compose 執行閘道與 Postgres, 再驗證登入全流程。

1 · 註冊 OAuth
2 · 建立 Postgres
3 · 撰寫 gateway.yaml
4 · 執行
5 · 驗證登入

決定閘道主機名稱, 建立 OIDC web 應用程式, 將 redirect URI 設為 https://claude-gateway.<domain>/oauth/callback, 記下 client_id 與 client_secret。

任何 Postgres 14 以上均可, 包含最小的受管方案。閘道在啟動時會自行執行結構遷移, 所以資料庫使用者需要 CREATE TABLE 權限。

listen:
  host: 0.0.0.0
  port: 8080
  public_url: https://claude-gateway.internal.example.com

oidc:
  issuer: https://login.example.com
  client_id: 0oa1example2
  client_secret: ${OIDC_CLIENT_SECRET}
  allowed_email_domains: [example.com]

session:
  jwt_secret: ${GATEWAY_JWT_SECRET}
  ttl_hours: 1

store:
  postgres_url: ${GATEWAY_POSTGRES_URL}

upstreams:
  - provider: bedrock
    region: us-east-1
    auth: {}

auto_include_builtin_models: true

用符合映像檔需求的容器包裝 claude 執行檔, 搭配 Postgres 一起執行。開機是 fail-closed 的: 設定檔, 5 秒逾時的 Postgres 連線, OIDC discovery 與上游用戶端建構都必須成功。

三項檢查確認閘道能驗證真實使用者: discovery 文件, 裝置授權請求, 以及在瀏覽器開啟驗證連結完成登入。

Step 1 of 5
私有網路

Claude Code 只會連接位址為私有的閘道, 這是安全防護, 因為受信任的閘道可以推送在開發者機器上執行指令的設定。把閘道放在內部負載平衡器或 VPN 後面。

連接開發者

開發者用自己的公司帳號完成一次瀏覽器登入, 不需要 claude.ai 帳號, API 金鑰或訂閱, 因為模型請求透過閘道用組織的上游憑證進行。

{
  "forceLoginMethod": "gateway",
  "forceLoginGatewayUrl": "https://claude-gateway.internal.example.com"
}
模型存取未授權的模型請求回傳 400, /model 選單過濾為政策允許清單
遙測目的地OTLP 匯出端點固定為閘道, 覆寫本機設定的 OTEL_* 變數
憑證閘道權杖是唯一憑證, 登入期間忽略 ANTHROPIC_API_KEY 等既有設定
解除授權IdP 中停用的使用者, 其 session 會在下次刷新失敗時於 ttl_hours 內過期

可用性與限制

可用

推論轉發, 依 IdP 群組的模型存取與 managed settings, OTLP 遙測扇出, 任何 OIDC 相容 IdP, 每使用者與每群組的花費上限, 標準 prompt caching

不可用

伺服器端 web search, 1 小時快取 TTL, 首方限定優化, OTLP/gRPC, SAML/LDAP, 多租戶 (多 OIDC issuer), Windows 伺服器, Helm chart, Admin UI

後續步驟

快速入門只留下最小設定, 接下來可以擴充 gateway.yaml 加入依群組 RBAC, 多上游容錯移轉或遙測目的地。

配置參考涵蓋 gateway.yaml 每個選項; 部署指南涵蓋依 IdP 設定, Kubernetes 與 Cloud Run 部署, 以及維運; 花費上限文件涵蓋 Admin API 與強制執行方式。
