Configure Auto Mode

告訴分類器哪些 repo, bucket 與網域是受信任的, 覆寫預設的封鎖與允許規則, 並檢視有效設定

分類器讀取設定的位置

分類器讀取與 Claude 本身相同的 CLAUDE.md 內容, 因此專案慣例同時導引 Claude 與分類器。跨專案規則則使用 autoMode 設定區塊。

~/.claude/settings.json單一開發者的個人受信任基礎設施
.claude/settings.local.json單一專案, 單一開發者的受信任 bucket 或服務
Managed settings組織層級, 分發給所有開發者的受信任基礎設施
--settings flag / Agent SDK單次呼叫的行內 JSON 覆寫
注意

分類器不會從共享的專案 .claude/settings.json 讀取 autoMode, 因此簽入版控的 repo 無法自行注入允許規則。分類器是在 permissions 系統之後執行的第二道關卡。

定義受信任基礎設施

autoMode.environment 是多數組織唯一需要設定的欄位, 用來告訴分類器哪些 repo, bucket 與網域屬於組織邊界內。

信任槽 Trust Slots

Trusted repo, Source control, Trusted internal domains, Trusted cloud buckets, Key internal services, Internal package registry

repo 與 source-control 預設為目前工作 repo 及其設定的遠端, 其餘預設 None configured

敏感度槽 Sensitivity Slots

PII / regulated-data locations, Sensitive remote targets, Protected IaC scopes

各自預設一個廣泛的啟發式規則, 例如名稱含 prod 的主機視為敏感遠端目標

{
  "autoMode": {
    "environment": [
      "$defaults",
      "Source control: github.example.com/acme-corp and all repos under it",
      "Trusted cloud buckets: s3://acme-build-artifacts, gs://acme-ml-datasets",
      "Trusted internal domains: *.corp.example.com, api.internal.example.com"
    ]
  }
}

條目是自然語言散文, 不是正則表達式。用你向新工程師描述基礎設施的方式撰寫即可, 逐步從預設值加上 source control 與關鍵內部服務開始。

覆寫封鎖與允許規則

三個欄位可替換分類器內建的規則清單, 依優先層級由高到低排列:

1 · hard_deny
2 · soft_deny
3 · allow
4 · 明確使用者意圖

無條件封鎖的安全邊界, 使用者意圖與 allow 例外都無法覆寫。

下一層封鎖的破壞性動作, 使用者意圖或 allow 例外可以覆寫。

對符合的 soft_deny 規則提供例外, 覆寫其封鎖行為。

當使用者訊息直接且明確描述 Claude 即將執行的確切動作時, 分類器允許執行, 即使符合某條 soft_deny 規則; 泛泛的請求不算明確意圖。

Step 1 of 4 
{
  "autoMode": {
    "allow": ["$defaults", "Deploying to staging is allowed: isolated and resets nightly"],
    "soft_deny": ["$defaults", "Never run database migrations outside the migrations CLI"],
    "hard_deny": ["$defaults", "Never send repository contents to third-party code-review APIs"]
  }
}
危險

設定 environment, allow, soft_deny 或 hard_deny 卻不含 "$defaults", 會整個取代該區段的預設清單, 等同捨棄所有內建規則, 包含 force push 與正式環境部署的保護。

讓所有 shell 指令都經過分類器

預設情況下, 狹窄的 Bash 與 PowerShell 允許規則 (例如 Bash(npm test)) 會延續到 auto mode 中, 並在分類器執行前先解析。

{
  "autoMode": {
    "classifyAllShell": true
  }
}

設為 true 會讓每個 Bash 與 PowerShell 允許規則在 auto mode 期間暫停, 分類器評估每一個 shell 指令, 以犧牲延遲換取涵蓋範圍 (需 Claude Code v2.1.193 以上)。

檢視預設值與有效設定

claude auto-mode defaults
以 JSON 印出內建的 environment, allow, soft_deny, hard_deny 規則
claude auto-mode config
印出分類器實際使用的設定, 套用你的設定並以預設值補足
claude auto-mode critique
針對自訂規則取得 AI 意見回饋, 標示模糊, 冗餘或易誤判的條目

檢視拒絕紀錄

當 auto mode 拒絕某個工具呼叫, 紀錄會出現在 /permissions 的 Recently denied 分頁。在被拒絕的動作上按下 r 可標記重試。

v2.1.193+分類器的拒絕原因會出現在對話紀錄, 拒絕通知與 Recently denied 分頁中
重複拒絕同一目的地通常代表分類器缺少情境, 將該目的地加入 autoMode.environment
程式化反應使用 PermissionDenied hook 對拒絕事件做出反應
