Development Containers 開發容器

在 dev container 中執行 Claude Code, 讓團隊擁有一致且隔離的開發環境

將 Claude Code 加入你的 dev container

Claude Code 透過 Claude Code Dev Container Feature 安裝進任何 dev container。以下步驟以 VS Code 為例, 其他支援 Dev Containers 規範的工具 (Codespaces, JetBrains) 也適用。

1 · 建立 devcontainer.json
2 · 重建容器
3 · 登入 Claude Code

將以下內容存為儲存庫中的 .devcontainer/devcontainer.json, 或將 features 區塊加入既有檔案。版本標籤 (如 :1.0) 只會固定安裝腳本版本, 不會固定 Claude Code 本身的版本, 因為 Claude Code 在容器內預設會自動更新。

// .devcontainer/devcontainer.json
{
  "image": "mcr.microsoft.com/devcontainers/base:ubuntu",
  "features": {
    "ghcr.io/anthropics/devcontainer-features/claude-code:1.0": {}
  }
}

開啟 VS Code 指令面板 (Mac: Cmd+Shift+P, Windows/Linux: Ctrl+Shift+P), 執行 Dev Containers: Rebuild Container。其他工具則依各自的重建動作操作 (Codespaces rebuild, Dev Containers CLI 等)。

在重建完成的容器中開啟終端機, 執行 claude, 依照驗證提示操作。驗證流程依供應商而異:

選擇供應商:
Anthropic
Bedrock / Vertex / Foundry

透過瀏覽器以 Claude 或 Anthropic Console 帳號登入。

Claude Code 直接使用雲端供應商憑證, 不會出現瀏覽器提示; 憑證應以環境變數 (containerEnv, Codespaces secret, 或工作負載身分) 傳入容器, 而非掛載主機上的憑證檔案。

跨重建保留驗證與設定

預設容器的家目錄在重建時會被捨棄, 工程師每次都要重新登入。Claude Code 將驗證 token, 使用者設定與 session 歷史存於 ~/.claude 下, 掛載具名 volume 到該路徑即可跨重建保留狀態:

// devcontainer.json
"mounts": [
  "source=claude-code-config,target=/home/node/.claude,type=volume"
]
隔離每個專案

在來源名稱中加入 ${devcontainerId} 變數即可讓每個專案有獨立狀態, 而非共用同一個 volume。在 GitHub Codespaces 中, ~/.claude 在停止與啟動 codespace 之間會保留, 但重建容器時仍會清除。

強制執行組織政策

Dev container 是套用組織政策的理想位置, 因為每位工程師的機器都執行相同映像與設定。Claude Code 在 Linux 上讀取 /etc/claude-code/managed-settings.json, 並以設定階層中最高優先權套用:

# Dockerfile
RUN mkdir -p /etc/claude-code
COPY managed-settings.json /etc/claude-code/managed-settings.json
更強的執行力

Dockerfile 存在儲存庫中, 任何有寫入權限的人都能變更或移除這個步驟。若需要工程師無法透過編輯儲存庫繞過的政策, 改用 server-managed settings 或 MDM 派送。

要為容器中每個 Claude Code session 套用環境變數, 加入 devcontainer.json 的 containerEnv:

// devcontainer.json
"containerEnv": {
  "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1",
  "DISABLE_AUTOUPDATER": "1"
}

限制網路對外流量

network-config
列出 Claude Code 需要的推論與驗證網域
data-usage
列出選用的遙測與錯誤回報連線, 以及如何停用
init-firewall.sh
參考容器內建的防火牆腳本, 封鎖除允許網域外的所有對外流量, 需要 NET_ADMIN 與 NET_RAW 權限
非必要

防火牆腳本與這些權限並非 Claude Code 本身運作所需, 可以省略並改用自己的網路控制。

不使用權限提示執行

因為容器以非 root 使用者執行 Claude Code, 且指令執行侷限在容器內, 可傳入 --dangerously-skip-permissions 進行無人值守操作。CLI 會拒絕以 root 啟動時使用此旗標, 請確認 remoteUser 設為非 root 帳號。

風險

跳過權限提示會移除你在工具呼叫執行前審查的機會。Claude 仍可修改掛載工作區中的任何檔案 (會直接顯示在主機上), 並可觸及容器網路政策允許的任何地方。搭配網路對外限制使用可降低風險範圍。

若想減少提示但不停用安全檢查, 可考慮改用 auto mode, 它會用分類器在動作執行前先行審查。若要完全防止工程師使用 --dangerously-skip-permissions, 在 managed settings 中將 permissions.disableBypassPermissionsMode 設為 "disable"。
