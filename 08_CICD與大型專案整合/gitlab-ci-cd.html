Claude Code GitLab CI/CD

把 Claude Code 整合進 GitLab CI/CD workflow, 目前為 Beta, 由 GitLab 維護

為什麼在 GitLab 使用 Claude Code

Instant MR creation
描述需求, Claude 提出完整 MR 含變更與說明
Automated implementation
一個指令或提及把 issue 轉成可運作程式碼
Project-aware
遵循 CLAUDE.md 準則與既有程式碼模式
Enterprise-ready
可選 Claude API, Amazon Bedrock 或 Google Vertex AI
維護方

此整合由 GitLab 維護, 建構於 Claude Code CLI 與 Agent SDK 之上, 支援問題回報於 GitLab issue #573776。

運作方式

1. 事件驅動編排GitLab 監聽你選擇的觸發條件, 例如 issue/MR 留言提及 @claude
2. Provider 抽象化可選 Claude API, Amazon Bedrock, 或 Google Vertex AI
3. 沙盒執行每次互動在容器中執行, 有嚴格網路與檔案系統規則, 變更透過 MR 讓審查者看到差異

快速設定

1 · 加入變數
2 · 加入 job

前往 Settings → CI/CD → Variables, 加入 ANTHROPIC_API_KEY (遮蔽, 依需求設為受保護)。

stages:
  - ai
claude:
  stage: ai
  image: node:24-alpine3.21
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
  script:
    - curl -fsSL https://claude.ai/install.sh | bash
    - >
      claude -p "${AI_FLOW_INPUT:-'Review this MR'}"
      --permission-mode acceptEdits

Amazon Bedrock 與 Google Vertex AI

Amazon Bedrock

AWS OIDC Identity Provider 設定

CI/CD 變數: AWS_ROLE_TO_ASSUME, AWS_REGION

用 GitLab job token 交換臨時 AWS 憑證

Google Vertex AI

Workload Identity Federation 信任 GitLab OIDC

CI/CD 變數: GCP_WORKLOAD_IDENTITY_PROVIDER, GCP_SERVICE_ACCOUNT

不需下載服務帳號金鑰

安全性與治理

隔離容器每個 job 在有限制網路存取的隔離容器中執行
MR 流程變更透過 MR 讓審查者看到每個差異
Workspace 範圍權限Claude Code 用 workspace-scoped 權限限制寫入
分支保護現有分支保護與核准規則同樣適用於 AI 產生的程式碼

絕不將 API 金鑰或雲端憑證提交到儲存庫, 永遠使用 GitLab CI/CD 遮蔽變數, 並優先使用 OIDC 而非長期靜態金鑰。

疑難排解

Claude 不回應 @claude確認 pipeline 有被觸發, CI/CD 變數存在且未被遮蔽阻擋, 留言含 @claude 而非 /claude
無法留言或開 MR確認 CI_JOB_TOKEN 權限足夠, 或改用具 api scope 的 Project Access Token
驗證錯誤Claude API 確認金鑰有效; Bedrock/Vertex 確認 OIDC/WIF 設定與角色模擬
