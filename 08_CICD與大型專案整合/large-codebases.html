在 Monorepo 或大型程式碼庫設定 Claude Code

用分層 CLAUDE.md, 稀疏 worktree, 程式碼智能與各目錄專屬 skills, 讓 Claude 聚焦於你正在處理的程式碼

本頁涵蓋的設定總覽

下表每一項設定都是獨立的, 彼此疊加而非互相取代, 依你的儲存庫需求挑選採用。

分層 CLAUDE.md
只載入你所觸碰程式碼的慣例, 而非一份涵蓋全部子系統的根檔案
claudeMdExcludes
排除你從不參與的套件的 CLAUDE.md
Read 拒絕規則
阻擋 Claude 開啟建置產物, 產生的程式碼與 vendored 相依套件
程式碼智能外掛
透過 language server 尋找定義與呼叫者, 而非掃描檔案
worktree.sparsePaths
建立 worktree 時只 checkout 任務需要的目錄
--add-dir
在同一個 session 中讀取編輯相鄰套件或另一個儲存庫

範例 Monorepo 結構

本頁所有範例都參照這個含三個套件的 monorepo, 相同模式也適用於大型單一樹狀結構的程式碼庫。

monorepo/
  CLAUDE.md                     # 根層級指示
  packages/
    api/
      CLAUDE.md                 # API 專屬指示
      .claude/skills/
      src/
    web/
      CLAUDE.md                 # 前端專屬指示
      .claude/skills/
      src/
    shared/
      CLAUDE.md                 # 共用函式庫指示
      src/

選擇從哪裡啟動 Claude

啟動 claude 的位置決定了可存取哪些檔案, 啟動時載入哪些 CLAUDE.md, 以及套用哪些專案設定。

啟動位置檔案存取啟動時載入的 CLAUDE.md適用時機
儲存庫根目錄每個檔案只有根層級, 子目錄檔案在讀取時按需載入任務跨越多個套件或子系統
子目錄只有該子樹, 除非授予更多權限該目錄與每個祖先目錄的檔案工作僅限於一個套件或子系統

依目錄分層 CLAUDE.md

常見的分層方式是兩層: 根層級 CLAUDE.md 涵蓋通用規則, 每個子目錄各自新增該領域堆疊的慣例。

根 CLAUDE.md
packages/api/CLAUDE.md
This is a monorepo with three packages under packages/:

- packages/api: Node.js REST API with Express, TypeScript, PostgreSQL
- packages/web: React frontend with Vite, TypeScript, TailwindCSS
- packages/shared: shared TypeScript utilities

Run commands from the package directory, not the monorepo root.
This package is the REST API server.

- Run tests: npm test (uses Vitest)
- Run dev server: npm run dev (port 3001)

API routes are in src/routes/. Database queries use Knex in src/db/.
Never write raw SQL strings in route handlers.

維護技巧

在 PR 中審查 CLAUDE.md 變更; 模型升級後重新檢視是否有過時的變通指示; 用 Stop hook 在 session 結束後提議更新。

減少 Claude 的讀取量

阻擋產生的與 vendored 程式碼在 permissions.deny 加入 Read 拒絕規則, 阻擋開啟已提交的建置產物
程式碼智能外掛連接 language server, 直接跳到定義, 找到參照, 呈現型別錯誤
{
  "permissions": {
    "deny": [
      "Read(./**/dist/**)",
      "Read(./**/build/**)",
      "Read(./vendor/**)"
    ]
  }
}

Worktree 與跨目錄存取範圍

worktree.sparsePaths

用 git sparse-checkout 只寫入列出的目錄加上根層級檔案

對 subagent worktree 隔離特別有幫助

搭配 symlinkDirectories 避免重複 node_modules

additionalDirectories

從子目錄啟動時, 授予存取相鄰套件或另一個儲存庫

也可在啟動時傳入 --add-dir

CLAUDE.md 與 skills 是否載入依新增方式而異

各目錄專屬 skills

任何子目錄都能定義專屬於自己技術堆疊的 skills, 只在 Claude 判斷相關時才載入。

packages/api/.claude/skills/api-testing/SKILL.md

---
name: api-testing
description: Testing patterns for the API package.
---

## Test structure
Tests are in src/__tests__/ mirroring the src/ directory structure.
從子目錄啟動該目錄, 每個祖先目錄, 加上使用者與企業層級的 skills
從儲存庫根目錄啟動Claude 接觸到的每個子目錄的 skills, 可能累積到數百個

當分層方式不再擴展時

隨程式碼庫成長, 每個目錄各自的 CLAUDE.md 可能難以治理。把慣例移到按需載入的機制中。

Skills
只在任務相關時才載入的參考資料
Plugins
平台團隊集中維護的版本化 skills, hooks, commands 套件
MCP servers
把既有的程式碼搜尋或 RAG 索引暴露成 MCP 工具

跨套件的變更, 把整個變更與所有呼叫端一次交給 Claude 保持決策一致; 並先把計畫存成檔案, 因為長 session 沿途會壓縮上下文, 但存檔的計畫會留存。
