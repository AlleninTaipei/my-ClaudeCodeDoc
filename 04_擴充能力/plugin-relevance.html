Recommend plugins for your org

Add a relevance block to marketplace plugin entries so Claude Code suggests them when a user's work matches.

How it works

Each plugin entry in marketplace.json can carry a relevance object naming a topic and one or more signals. A signal is a pattern Claude Code tests against the current session, such as the working directory or files Claude has read. Signal matching happens locally on the user's machine — it adds no network traffic and reports nothing to Anthropic or the marketplace operator.

When a signal matches and the plugin is not already installed, Claude Code shows the plugin in three places:

Spinner tip"Working with topic? Install the plugin plugin" appears below the spinner while Claude responds.
Session-start suggestionIf the cwd signal matches, a one-line notification appears before the first turn (v2.1.153+).
/plugin Discover tabThe plugin is pinned to the top of the Discover list with an annotation such as "suggested for this directory" (v2.1.154+).
NOTE

Suggestions are opt-in per marketplace through managed settings. No marketplace's declarations produce suggestions until an administrator adds it to the allowlist — including the official Anthropic marketplace. Claude Code never installs a plugin automatically; the user always confirms.

Add relevance to a plugin entry

Add a relevance object to the plugin's entry in your marketplace.json. This example declares that terraform-helpers is relevant when Claude reads a .tf file or runs terraform:

{
  "name": "acme-corp-plugins",
  "owner": { "name": "Acme Platform Team" },
  "plugins": [
    {
      "name": "terraform-helpers",
      "source": "./plugins/terraform-helpers",
      "description": "Acme conventions and helpers for Terraform",
      "relevance": {
        "topic": "Terraform",
        "signals": {
          "cli": ["terraform"],
          "filesRead": ["**/*.tf"]
        }
      }
    }
  ]
}

A plugin with a relevance block but no matching signal behaves like any other marketplace entry — it appears in the Discover list in its normal position and never surfaces as a spinner tip.

Field reference

relevance

topic
Optional string. Fills "Working with topic?" in the spinner tip. Defaults to the plugin name with each hyphen segment capitalized. Max 64 characters. The session-start notification does not use this value.
signals
Object of matchers that determine when the plugin is relevant. At least one signal is required for the plugin to be suggestible.

relevance.signals

Claude Code records one command name per shell invocation: the first token after any leading env-var assignments and sudo. Compound commands contribute only their leading command — cd infra && terraform plan records cd, not terraform. Exact match.

array of strings

Glob patterns matched against paths of files Claude has read this session, e.g. ["**/*.tf"]. Forward-slash normalized, case-insensitive.

type
array of objects
matches
Dependencies declared in package manifests Claude has read this session. Each entry is { "file": "...", "pattern": "..." }.
detail
file is a regex matched against the manifest's path (anchor at the end, e.g. [/\\]package\.json$, since a start-anchored pattern never matches an absolute path); paths are not separator-normalized, so Windows paths use backslashes. pattern is a regex matched against file contents, case-sensitive.   "name": "stripe-helpers",
  "source": "./plugins/stripe-helpers",
  "relevance": {
    "topic": "Stripe",
    "signals": {
      "manifestDeps": [
        {
          "file": "[/\\\\]package\\.json$",
          "pattern": "\"stripe\"\\s*:"
        }
      ]
    }
  }
}
NOTE

Unknown fields under relevance and relevance.signals are ignored at load time so older Claude Code clients keep loading your marketplace. Run claude plugin validate to surface them as warnings. Only cwd can match at session start; cli, hosts, filesRead, and manifestDeps need session history, so they can only match on the spinner tip and the Discover tab.

Enable suggestions in managed settings

Declaring relevance in marketplace.json is not enough on its own. An administrator must allowlist the marketplace in managed settings before its suggestions appear to users. Add the marketplace name to pluginSuggestionMarketplaces. For any marketplace other than the official one, also declare the marketplace source, either in extraKnownMarketplaces or strictKnownMarketplaces — otherwise the allowlisted name is ignored.

Org marketplace
{
  "extraKnownMarketplaces": {
    "acme-corp-plugins": {
      "source": {
        "source": "github",
        "repo": "acme-corp/claude-plugins"
      }
    }
  },
  "pluginSuggestionMarketplaces": ["acme-corp-plugins"]
}
Official marketplace
{
  "pluginSuggestionMarketplaces": ["claude-plugins-official"]
}

Exempt from the source-declaration requirement because its name can only register from the official Anthropic source.

What the user sees

When a signal matches during a session, the spinner tip reads:

Working with Terraform? Install the terraform-helpers plugin:
/plugin install terraform-helpers@acme-corp-plugins

At session start, a matching cwd signal surfaces the one-line notification:

plugin suggestion: terraform-helpers@acme-corp-plugins · /plugin

A given plugin's suggestion appears at most once every three sessions across the spinner tip and the session-start notification combined, and neither repeats once the plugin is installed. The session-start notification additionally stops appearing after being shown twice. In the Discover tab, the plugin is pinned above other results once, with an annotation naming the matching signal (v2.1.154+; on v2.1.152 only the spinner tip appears, v2.1.153 adds the session-start notification).

Validate your marketplace

Run claude plugin validate against your marketplace directory to check the relevance block before publishing:

claude plugin validate ./my-marketplace
CHECKS

The validator reports unknown keys under relevance and relevance.signals as warnings, flags a relevance value that is not an object, and rejects a signals.hosts entry that includes a scheme, port, or path.
