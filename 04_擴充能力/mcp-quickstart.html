Connect to MCP servers

Add an MCP server to Claude Code, verify the connection, and find the configuration on disk.

Before you begin

Model Context Protocol (MCP) lets Claude Code use tools beyond its built-in set, such as searching an issue tracker, querying a database, or controlling a web browser. These tools come from MCP servers, which run on your machine or as hosted services.

Claude Code
Installed and authenticated
Terminal
Open in a project directory, any directory works, including an empty one

Add and verify a server

The example connects to the Claude Code documentation MCP server, a hosted server with full-text search over the Claude Code docs. The steps are the same for any server: add it, check the connection status, then use it in a session, with an optional cleanup step at the end.

1 · Add
2 · Check status
3 · Use
4 · Remove

Register the server with Claude Code. Run this in your terminal, not inside a claude session.

claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp

claude mcp add registers a server. --transport http means the server is hosted at a URL. claude-code-docs is a name you make up, used to label the server's tools and to refer to it in commands like claude mcp remove. By default the server is registered at local scope: private to you, active only in the current project.

Confirm the server appears in your server list and check its status:

claude mcp list
✓ ConnectedReady to use
! tools fetch failedConnected but couldn't list tools, run claude mcp get <name>
! Needs authenticationReachable but needs a browser sign-in or a token
✗ Failed to connectServer didn't respond
✗ Connection errorThe connection attempt threw an error
⏸ Pending approvalA project-scoped server you haven't approved yet

Start a session and ask Claude to use the new server by name:

claude
# in the session
Use the claude-code-docs server to look up what MCP_TIMEOUT does
INFO

You don't normally need to name a server in your prompt, since Claude chooses relevant tools on its own. The first time Claude calls the server, it asks for permission. The tool call in Claude's output is labeled with the server name.

Optional. When you're done experimenting, remove the server:

claude mcp remove claude-code-docs
NOTE

Each connected server takes some space in Claude's context window because its tool names and server instructions load into every session. Removing servers you no longer use keeps that space free.

Step 1 of 4

Where servers are saved

The claude mcp add command writes the server's details to a configuration file, depending on the --scope flag.

local
~/.claude.json, under the entry for this project. Only you, only this project. The default.
project
.mcp.json in your project root. Everyone who clones the project.
user
~/.claude.json, under the top-level mcpServers key. Only you, all projects.

On Windows, ~/.claude.json resolves to %USERPROFILE%\.claude.json. Run claude mcp get claude-code-docs to see which scope holds a server's definition.

Change server scope

A server's scope is fixed when you add it, so changing scope means removing the entry and re-adding it at the new one.

claude mcp remove claude-code-docs --scope local
Use in all your projects
claude mcp add --scope user --transport http claude-code-docs https://code.claude.com/docs/mcp

Active in every project you open, still private to you.

Share with your team
claude mcp add --scope project --transport http claude-code-docs https://code.claude.com/docs/mcp

Writes to .mcp.json in the project root. Commit it so teammates get a prompt to approve the server.

Additional MCP server examples

Beyond a hosted server with no sign-in, two other common shapes exist, with the same add, check, use flow.

Server type:
Local (stdio)
Requires sign-in

A local stdio server is a program Claude Code starts as a subprocess on your machine. The Playwright MCP server gives Claude a browser it can navigate, click, and read, and runs through npx.

claude mcp add playwright -- npx -y @playwright/mcp@latest

No --transport flag, because local servers use the default stdio transport. Everything after -- is the command Claude Code runs to start the server.

claude mcp list
# may show "Failed to connect" while npx downloads the package
Use playwright to open https://example.com and tell me the page title

Hosted services like Sentry, Linear, and Notion run their MCP servers behind OAuth: add the server's URL, then sign in through your browser.

claude mcp add --transport http sentry https://mcp.sentry.dev/mcp
# claude mcp list shows "! Needs authentication"
# inside a session
/mcp
# select sentry, press Enter, choose Authenticate

Servers that authenticate with a static token instead of OAuth take the token at add time with --header "Authorization: Bearer <token>".

Edit .mcp.json directly

Every scope uses the same JSON format for server entries. Editing .mcp.json directly is worth it because it's checked into the repository, doubling as configuration-as-code for your team.

{
  "mcpServers": {
    "claude-code-docs": {
      "type": "http",
      "url": "https://code.claude.com/docs/mcp"
    },
    "playwright": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}
url
For HTTP servers, the endpoint Claude Code connects to
command / args
For stdio servers, the program it runs

The first time Claude Code sees a project-scoped server, it asks you to approve it, so a repository you clone can't launch processes without your consent.

Troubleshooting

Symptom:
No servers configured
Failed / Connection error
Timed out at startup
Already exists

Claude Code didn't find any servers for the current directory. Local-scoped servers are tied to the project where you added them. Re-add the server from the project you're in now, or add it with --scope user. Correct files are ~/.claude.json and <project>/.mcp.json.

The server didn't start or the URL didn't respond. Confirm the URL is reachable:

curl -I https://mcp.sentry.dev/mcp
404 / 405
Server is up, many endpoints answer only POST
401 / 403
Server is up, needs authentication

For stdio servers, run the configured command directly in your terminal to see the underlying error.

The server took longer than the default 30-second startup timeout. Increase the limit with MCP_TIMEOUT, in milliseconds:

MCP_TIMEOUT=60000 claude

You've already added a server with that name at the same scope. Remove the existing entry first or choose a different name:

claude mcp remove claude-code-docs --scope local
