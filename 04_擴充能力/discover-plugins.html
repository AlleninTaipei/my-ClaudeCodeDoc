Discover and install prebuilt plugins

Find and install plugins from marketplaces to extend Claude Code with new skills, agents, and capabilities.

How marketplaces work

A marketplace is a catalog of plugins that someone else has created and shared. Using a marketplace is a two-step process:

1 · Add the marketplace
2 · Install individual plugins

This registers the catalog with Claude Code so you can browse what's available. No plugins are installed yet.

Browse the catalog and install the plugins you want.

Step 1 of 2

Think of it like adding an app store: adding the store gives you access to browse its collection, but you still choose which apps to download individually.

Official Anthropic marketplace

The official Anthropic marketplace (claude-plugins-official) is automatically available when you start Claude Code. Run /plugin and go to the Discover tab to browse what's available, or view the catalog at claude.com/plugins.

/plugin install github@claude-plugins-official
NOTE

The official marketplace is curated by Anthropic, and inclusion is at Anthropic's discretion. The in-app submission forms add plugins to the community marketplace, not the official one. If Claude Code reports a plugin as not found, run /plugin marketplace update claude-plugins-official to refresh it, or add it first with /plugin marketplace add anthropics/claude-plugins-official.

GAINS

Automatic diagnostics: after every edit, the language server reports errors and warnings back automatically — Claude sees type errors and missing imports without running a compiler. Press Ctrl+O to see diagnostics inline.

Code navigation: jump to definitions, find references, get type info on hover, list symbols, find implementations, and trace call hierarchies — more precise than grep-based search.

Community marketplace

The community marketplace at anthropics/claude-plugins-community hosts third-party plugins that have passed Anthropic's automated validation and safety screening. Each plugin is pinned to a specific commit SHA in the catalog. Unlike the official marketplace, you add it manually:

/plugin marketplace add anthropics/claude-plugins-community

Then install plugins from it using the claude-community marketplace name:

/plugin install <plugin-name>@claude-community

Try it: add the demo marketplace

Anthropic also maintains a demo plugins marketplace (claude-code-plugins) with example plugins that show what's possible with the plugin system. Unlike the official marketplace, you need to add this one manually.

Run the plugin marketplace add command for the anthropics/claude-code marketplace. This downloads the catalog and makes its plugins available to you.

/plugin marketplace add anthropics/claude-code

Run /plugin to open the plugin manager — a tabbed interface with four tabs cycled with Tab / Shift+Tab:

  • Discover: browse available plugins from all your marketplaces
  • Installed: view and manage your installed plugins
  • Marketplaces: add, remove, or update your added marketplaces
  • Errors: view any plugin loading errors

When an administrator has allowlisted the marketplace via pluginSuggestionMarketplaces, plugins relevant to your working directory are pinned at the top with a "suggested for this directory" label (v2.1.154+).

Select a plugin to view its details: a Context cost estimate (v2.1.143+), the plugin's Last updated date (v2.1.144+), and a Will install section listing its commands, agents, skills, hooks, and MCP/LSP servers (v2.1.145+).

Choose a scope — User (yourself, all projects), Project (all collaborators), or Local (yourself, this repo only) — or install directly:

/plugin install commit-commands@claude-code-plugins

After installing, run /reload-plugins to activate it. Plugin skills are namespaced by plugin name:

/reload-plugins
/commit-commands:commit

This stages your changes, generates a commit message, and creates the commit. Each plugin works differently — check its details in the Discover tab or its homepage for usage guidance.

Step 1 of 4

Add marketplaces

Use /plugin marketplace add to add marketplaces from different sources. Shortcuts: /plugin market instead of /plugin marketplace, and rm instead of remove.

選擇來源:
GitHub
Other Git hosts
Local paths
Remote URLs

Add a GitHub repository containing a .claude-plugin/marketplace.json file, using owner/repo format:

/plugin marketplace add anthropics/claude-code

Add any git repository by its full URL — works with GitLab, Bitbucket, and self-hosted servers. Include the .git suffix and the https:// prefix (v2.1.196+ rejects a bare host as an invalid GitHub shorthand).

# HTTPS
/plugin marketplace add https://gitlab.com/company/plugins.git

# SSH
/plugin marketplace add git@gitlab.com:company/plugins.git

# Specific branch or tag
/plugin marketplace add https://gitlab.com/company/plugins.git#v1.0.0

Add a local directory containing a .claude-plugin/marketplace.json file, or a direct path to that file:

/plugin marketplace add ./my-marketplace
/plugin marketplace add ./path/to/marketplace.json

Add a remote marketplace.json file via URL:

/plugin marketplace add https://example.com/marketplace.json
LIMITATION

URL-based marketplaces have limitations compared to Git-based ones. "Path not found" errors when installing plugins usually mean relative-path resolution failed for a URL-based marketplace.

Install plugins

Once you've added marketplaces, install plugins directly:

/plugin install plugin-name@marketplace-name

The command opens the plugin's details, where you choose an installation scope — the same choice you see running /plugin, going to Discover, and pressing Enter:

User scope (default)
Install for yourself across all projects.
Project scope
Install for all collaborators on this repository, added to .claude/settings.json.
Local scope
Install for yourself in this repository only, not shared with collaborators.
Managed scope
Installed by administrators via managed settings, and can't be modified by users.

To install without an interactive step, use the claude plugin install shell command, which installs to user scope unless you pass --scope.

WARNING

Make sure you trust a plugin before installing it. Anthropic doesn't control what MCP servers, files, or other software are included in plugins and can't verify that they work as intended. Check each plugin's homepage first.

Manage installed plugins

Run /plugin and go to the Installed tab to view, enable, disable, or uninstall your plugins. The list is grouped by scope: load errors and unresolved dependencies first, then favorites, with disabled plugins folded behind a collapsed header at the bottom.

fFavorite or unfavorite the selected plugin.
type to filterFilter by plugin name or description.
EnterOpen a plugin's detail view to enable, disable, or uninstall it.

Uninstalling a plugin that a project's .claude/settings.json enables asks which scope you mean: disable it for you alone (writes to .claude/settings.local.json, keeps it installed for the project) or uninstall it for everyone, removing it from the shared settings file (v2.1.203+; earlier versions offer only the local disable).

The Installed tab also flags marketplace plugins you installed yourself but haven't used in at least two weeks across 10+ sessions, under a Not used recently header, with a Last used line in the detail view (v2.1.187+). Never listed as unused: org-managed plugins, plugins loaded with --plugin-dir, and plugins contributing only a theme, output style, monitor, or workflow.

Apply plugin changes without restarting

/reload-plugins
COST

Reloading has a token cost on the next request: newly loaded components announce themselves in appended content, while existing history still reads from the prompt cache. A plugin providing MCP servers costs more when its tools aren't deferred by tool search — the change invalidates the cache and the next request re-reads the entire conversation. v2.1.163+ warns and skips the reload in that case; pass --force to apply anyway.

# Direct commands
/plugin list            # supports --enabled / --disabled
/plugin disable plugin-name@marketplace-name
/plugin enable plugin-name@marketplace-name
/plugin uninstall plugin-name@marketplace-name

claude plugin install formatter@your-org --scope project
claude plugin uninstall formatter@your-org --scope project

As of v2.1.195, Enable/Disable work for plugins whose marketplace-entry name differs from their plugin.json name, and both commands accept either name.

Auto-updates

Run /plugin and go to the Marketplaces tab to view all added marketplaces with their sources and status, add new ones, refresh listings, or remove marketplaces you no longer need.

/plugin marketplace list
/plugin marketplace update marketplace-name
/plugin marketplace remove marketplace-name
WARNING

Removing a marketplace will uninstall any plugins you installed from it.

Claude Code can automatically update marketplaces and their installed plugins at startup, refreshing marketplace data and updating plugins to their latest versions, with a notification prompting /reload-plugins.

Toggle per marketplace: run /plugin → Marketplaces → choose a marketplace → Enable auto-update / Disable auto-update. Official Anthropic marketplaces default to enabled; third-party and local development marketplaces default to disabled. Administrators can set "autoUpdate": true on an extraKnownMarketplaces entry to enable it org-wide without per-user toggling.

# Disable all automatic updates (Claude Code + plugins)
export DISABLE_AUTOUPDATER=1

# Keep plugin auto-updates while disabling Claude Code auto-updates
export DISABLE_AUTOUPDATER=1
export FORCE_AUTOUPDATE_PLUGINS=1

Configure team marketplaces

Team admins can set up automatic marketplace installation for projects by adding marketplace configuration to .claude/settings.json. When team members trust the repository folder, Claude Code prompts them to install these marketplaces and plugins.

{
  "extraKnownMarketplaces": {
    "my-team-tools": {
      "source": {
        "source": "github",
        "repo": "your-org/claude-plugins"
      }
    }
  }
}
v2.1.195+

This install step applies on every path that loads plugins. A plugin that only the project's settings.json enables, and that comes from an external source, doesn't load until the team member installs it — Claude Code reports it as not installed and shows the install command to run.

Security

HIGH TRUST

Plugins and marketplaces are highly trusted components that can execute arbitrary code on your machine with your user privileges. Only install plugins and add marketplaces from sources you trust. Organizations can restrict which marketplaces users are allowed to add using managed marketplace restrictions.

Troubleshooting

問題類型:
/plugin not recognized
Common issues
Code intelligence
  1. Run claude --version to check what's installed.
  2. Update: Homebrew brew upgrade claude-code; npm npm install -g @anthropic-ai/claude-code@latest; or re-run the native installer.
  3. Restart your terminal and run claude again.
  • Marketplace not loading: verify the URL is accessible and .claude-plugin/marketplace.json exists at the path.
  • Plugin installation failures: check plugin source URLs are accessible and repositories are public or you have access.
  • Files not found after installation: plugins are copied to a cache, so paths referencing files outside the plugin directory won't work.
  • Plugin skills not appearing: clear the cache with rm -rf ~/.claude/plugins/cache, restart Claude Code, and reinstall.
  • Language server not starting: verify the binary is installed and on your $PATH. Check the /plugin Errors tab.
  • High memory usage: servers like rust-analyzer and pyright can consume significant memory on large projects — disable with /plugin disable <plugin-name> and rely on Claude's built-in search instead.
  • False positive diagnostics in monorepos: language servers may report unresolved import errors for internal packages if the workspace isn't configured correctly. These don't affect Claude's ability to edit code.
