擴充 Claude 的 Skills

建立一個 SKILL.md 檔案寫上指示, Claude 就會把它加進工具箱。與 CLAUDE.md 不同, skill 內容只在被使用時才載入, 所以長篇參考資料幾乎不佔額外成本。

Bundled Skills 與建立第一個 Skill

Claude Code 內建一組 bundled skills, 在每個 session 中都可使用, 這些是以提示為基礎的元件, 給 Claude 詳細指示再讓它用工具自行完成工作。

/run · /verify
啟動並操作你的應用程式, 針對正在執行的程式確認變更是否生效
/run-skill-generator
教會 /run 與 /verify 如何建置與啟動你的專案, 記錄成專屬 skill
/code-review · /debug · /loop
程式碼審查, 除錯與週期性任務等常見 bundled skills
/claude-api
Claude API 與 Anthropic SDK 使用參考

建立第一個 Skill: 摘要未提交的變更

1 · 建立目錄
2 · 撰寫 SKILL.md
3 · 測試

在個人 skills 資料夾建立目錄, 個人 skills 適用於所有專案:

mkdir -p ~/.claude/skills/summarize-changes

每個 skill 都需要一個 SKILL.md, 包含 YAML frontmatter 與 markdown 指示內容。!`git diff HEAD` 這行會在 Claude 看到之前先執行指令, 把輸出直接內嵌進提示:

---
description: Summarizes uncommitted changes and flags anything risky.
---

## Current changes
!`git diff HEAD`

## Instructions
Summarize the changes above in two or three bullet points...

可以讓 Claude 自動判斷觸發 (問「我改了什麼」), 或直接輸入 /summarize-changes 明確呼叫。兩種方式都會得到你這次修改的摘要與風險列表。

Skills 存放位置與探索規則

Skill 存放的位置決定誰可以使用它。當多個層級有相同名稱, 企業層級優先於個人, 個人優先於專案。

Enterprise組織內所有使用者, 透過 managed settings 部署
Personal ~/.claude/skills/你所有的專案
Project .claude/skills/僅限這個專案
Plugin skills/plugin 啟用時可用
巢狀 skills

Project skills 也會從巢狀的 .claude/skills/ 目錄載入, 這讓 monorepo 中每個套件都能提供自己的 skills。若巢狀 skill 與其他層級同名, 會以目錄限定名稱呈現, 例如 apps/web:deploy, 兩者同時保留可用。

Frontmatter 設定參考

除了 markdown 內容, 可以透過 SKILL.md 頂端 YAML frontmatter 設定 skill 行為, 只有 description 是建議必填。

description
Claude 依此判斷何時使用這個 skill, 建議把關鍵使用情境放在最前面
disable-model-invocation
設為 true 只能由你手動呼叫, 適合有副作用的工作流程
user-invocable
設為 false 只能由 Claude 呼叫, 從 / 選單隱藏
allowed-tools
此 skill 啟用時 Claude 不需詢問即可使用的工具
context: fork
在獨立的子代理人情境中執行這個 skill
model / effort
此 skill 啟用期間覆寫模型或推理強度

可用字串替換

$ARGUMENTS呼叫 skill 時傳入的完整參數字串
$N / $ARGUMENTS[N]依位置索引存取單一參數, 例如 $0 是第一個
${CLAUDE_SESSION_ID}目前的 session ID, 適合用來記錄或關聯輸出
${CLAUDE_SKILL_DIR}此 skill 所在目錄, 用來參照隨附的腳本或檔案

控制誰能呼叫 Skill

預設情況下你與 Claude 都能呼叫任何 skill。兩個 frontmatter 欄位可以限制這個行為。

disable-model-invocation: true

只有你能呼叫。適合有副作用或需要你控制時機的工作流程, 例如 /commit, /deploy, /send-slack-message。

Description 不會進入上下文, 只有在你呼叫時才載入完整 skill 內容。

user-invocable: false

只有 Claude 能呼叫。適合不是可執行動作的背景知識, 例如描述舊系統如何運作的 skill。

Description 仍會進入上下文, 讓 Claude 知道何時該用它, 但使用者無法直接輸入指令觸發。

進階模式

選擇下方標籤查看兩種進階能力: 動態上下文注入, 以及在子代理人中執行 skill。

動態上下文注入
在子代理人中執行

!`<command>` 語法會在 skill 內容送給 Claude 之前先執行 shell 指令, 指令輸出會取代該行, 讓 Claude 收到實際資料而不是指令本身。這是預先處理, 不是 Claude 自己執行的動作。

---
name: pr-summary
context: fork
agent: Explore
---

## Pull request context
- PR diff: !`gh pr diff`
- Changed files: !`gh pr diff --name-only`

在 frontmatter 加上 context: fork, skill 內容會變成驅動子代理人的提示, 不會存取你的對話歷史。內建的 Explore 與 Plan 代理人會略過 CLAUDE.md 與 git status, 讓上下文保持精簡。

這與「子代理人預先載入 skills」是相反方向: 一個是把 skill 內容變成子代理人的任務, 另一個是子代理人把 skill 當成參考資料預先載入。

疑難排解

Skill 沒有觸發檢查 description 是否包含使用者會自然說出的關鍵字, 或直接用 /skill-name 呼叫
Skill 太常觸發讓 description 更具體, 或加上 disable-model-invocation: true
Description 被截斷skill 數量多時 description 會被縮短, 用 /doctor 查看被縮減或捨棄的 skill

把常常重複貼上的指示, 檢查清單或多步驟程序做成 skill。內容保持精簡, 因為一旦載入就會留在上下文中一整個 session, 每一行都是重複出現的 token 成本。
