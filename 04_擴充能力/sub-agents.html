快速上手: 建立你的第一個子代理人

用 /agents 指令建立使用者層級的子代理人, 例如一個程式碼審查代理人。

1 · 開啟介面
2 · 選擇範圍
3 · 用 Claude 生成
4 · 選擇工具與模型
5 · 儲存並試用

在 Claude Code 執行 /agents 開啟子代理人管理介面。

切換到 Library 分頁, 選擇 Create new agent, 再選 Personal, 存到 ~/.claude/agents/ 讓所有專案都能使用。

選擇 Generate with Claude, 描述這個代理人要做什麼, Claude 會自動產生識別碼, description 與系統提示。

只保留 Read-only tools 給唯讀審查者, 再選擇 Sonnet 這種兼顧能力與速度的模型。

確認設定摘要, 按 s 或 Enter 儲存。之後在任何專案輸入「用 code-improver 代理人檢查這個專案」即可委派。

Step 1 of 5

設定子代理人

子代理人是含有 YAML frontmatter 的 Markdown 檔案, 存放位置決定範圍與優先順序。

Managed settings組織層級, 優先權最高
--agents CLI flag僅限當次 session
.claude/agents/目前專案
~/.claude/agents/你所有的專案
Plugin agents/plugin 啟用時可用, 優先權最低

常用 Frontmatter 欄位

name / description
唯一識別碼與 Claude 判斷何時委派的依據, 皆為必填
tools / disallowedTools
允許或排除的工具清單, 省略則繼承全部工具
model
sonnet, opus, haiku, fable, 完整模型 ID, 或 inherit
permissionMode
default, acceptEdits, auto, dontAsk, bypassPermissions, plan
skills
啟動時預先載入到上下文的 skill 完整內容
memory
user, project, 或 local, 啟用跨 session 的持久記憶
isolation: worktree
在暫時的 git worktree 中執行, 取得獨立的程式碼副本
background
設為 true 讓這個子代理人一律以背景任務執行

使用子代理人的常見模式

隔離高輸出量操作
平行研究
串連多個子代理人
前景與背景執行

把會產生大量輸出的操作 (跑測試, 抓文件, 處理 log 檔) 委派給子代理人, 詳細輸出留在子代理人上下文中, 只有相關摘要回到主對話。

針對彼此獨立的調查, 同時派出多個子代理人平行工作, 各自探索所屬領域, 再由 Claude 綜合各方發現。

多步驟工作流程可以要求 Claude 依序使用子代理人, 每個完成任務後把結果交給 Claude, 再傳遞相關上下文給下一個子代理人。

前景子代理人會阻塞主對話直到完成, 權限提示會直接傳給你; 背景子代理人則讓你可以繼續工作, 遇到需要權限的工具呼叫時會在主 session 中提示, 並標明是哪個子代理人在詢問。

Fork 現在的對話

Fork 是一種會繼承整個對話歷史的子代理人, 而不是從頭開始。它看到與主 session 相同的系統提示, 工具, 模型與訊息紀錄, 因此可以在不重新解釋情境的狀況下交辦旁支任務。

Fork

完整對話歷史, 與主 session 相同的系統提示與工具

共用 prompt cache, 第一次請求就能重用主 session 的快取, 比重新產生子代理人更便宜

具名子代理人

全新上下文, 只帶著你傳入的提示

系統提示與工具來自子代理人自己的定義檔, 各自擁有獨立的 cache

限制

Fork 無法再產生新的 fork, 但可以產生其他類型的子代理人, 且那些子代理人仍計入巢狀深度限制。

當一個具名子代理人需要太多背景資訊才有用, 或想從同一個起點同時嘗試多種做法時, 選擇 fork; 當任務會產生大量你不需要保留的輸出, 或需要限制特定工具與權限時, 選擇具名子代理人。
