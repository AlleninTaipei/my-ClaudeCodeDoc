Hooks 參考手冊

Hooks 是在 Claude Code 生命週期特定時間點自動執行的使用者自訂命令, HTTP 端點或 LLM 提示。本課程拆解生命週期, 設定結構, 輸入輸出與事件總覽。

Hook 生命週期

Hooks 在特定時間點觸發, 分成三種頻率: 每個 session 一次, 每個 turn 一次, 以及在 agentic loop 中每次工具呼叫都觸發。

Hook 如何解析: 阻擋危險 rm 指令的範例

1 · 事件觸發
2 · Matcher 檢查
3 · If 條件檢查
4 · Hook 執行
5 · Claude Code 採取行動

PreToolUse 事件觸發, Claude Code 把工具輸入以 JSON 形式透過 stdin 傳給 hook:

{ "tool_name": "Bash", "tool_input": { "command": "rm -rf /tmp/build" }, ... }

matcher "Bash" 符合工具名稱, 這個 hook 群組被啟動。若省略 matcher 或使用 "*", 則每次事件都會啟動。

if 條件 "Bash(rm *)" 符合, 因為 rm -rf /tmp/build 是符合 rm * 的子指令, 所以這個 handler 會被觸發。若指令是 npm test, if 檢查會失敗, block-rm.sh 就不會執行。

腳本檢查完整指令並發現 rm -rf, 於是印出決策到 stdout:

{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "Destructive command blocked by hook"
  }
}

Claude Code 讀取 JSON 決策, 阻擋這次工具呼叫, 並把原因顯示給 Claude 看。

Step 1 of 5

設定與參數

Hooks 定義在 JSON 設定檔中, 設定有三層巢狀結構: 選擇 hook 事件, 加上 matcher 群組過濾, 再定義一或多個 hook handler。

設定位置與作用範圍

~/.claude/settings.json套用到你所有的專案, 僅存在於本機, 無法分享
.claude/settings.json單一專案, 可以提交到 repo 分享給團隊
.claude/settings.local.json單一專案, Claude Code 建立時會自動加入 gitignore
Managed policy settings組織層級, 由管理員控制
Plugin hooks/hooks.jsonplugin 啟用時生效, 隨 plugin 一起分享
Skill / agent frontmatter元件啟用期間生效, 定義在元件檔案內

五種 Hook Handler 類型

command
執行 shell 指令, 透過 stdin 接收 JSON 輸入, 用 exit code 與 stdout 回報結果
http
把 JSON 輸入以 POST 傳送到 URL, 用同樣的 JSON 格式回傳結果
mcp_tool
呼叫已連線 MCP server 上的工具, 文字輸出視同 stdout 處理
prompt
送出提示給 Claude 模型做單輪評估, 回傳 yes/no 決策
agent
產生一個可使用工具驗證條件的子代理人, 屬於實驗性功能
matcher 語法

只有字母, 數字, 底線, 連字號, 空格, 逗號與 | 時視為精確字串比對; 包含其他字元則視為未錨定的 JavaScript 正規表達式。"*", "" 或省略代表全部符合。

輸入輸出與退出碼

Command hooks 透過 stdin 收到 JSON, 透過 exit code, stdout, stderr 回報結果。退出碼決定 Claude Code 接下來要繼續, 阻擋, 還是忽略這次行動。

Exit 0 · 成功

Claude Code 解析 stdout 中的 JSON 輸出欄位。多數事件下 stdout 只會寫入除錯紀錄, 不會顯示在 transcript。

Exit 2 · 阻擋錯誤

Claude Code 忽略 stdout 與其中任何 JSON, 改把 stderr 文字回饋給 Claude 作為錯誤訊息。效果依事件而異, 例如 PreToolUse 會阻擋工具呼叫。

範例: 阻擋危險 Bash 指令的腳本

#!/bin/bash
# 從 stdin 讀取 JSON 輸入, 檢查指令
command=$(jq -r '.tool_input.command' < /dev/stdin)

if [[ "$command" == rm* ]]; then
  echo "Blocked: rm commands are not allowed" >&2
  exit 2  # 阻擋錯誤: 工具呼叫被阻止
fi

exit 0  # 沒有決策: 走正常權限流程

JSON 輸出常用欄位

continue若為 false, Claude 在 hook 執行後完全停止處理
stopReasoncontinue 為 false 時顯示給使用者的訊息
systemMessage顯示給使用者的警告訊息
hookSpecificOutput巢狀物件, 給需要更精細控制的事件使用, 需要 hookEventName 欄位
additionalContext把字串插入 Claude 的上下文視窗, 以 system reminder 形式呈現

只能擇一使用: 要嘛用 exit code 單純傳達阻擋或放行, 要嘛 exit 0 並印出 JSON 做結構化控制。Claude Code 只在 exit 0 時處理 JSON, exit 2 時任何 JSON 都會被忽略。

Hook 事件總覽

完整事件清單依作用分成不同群組, 點選下方類別查看該群組包含哪些事件, 以及 exit code 2 時能否阻擋動作。

選擇群組:
可被 exit 2 阻擋
exit 2 無法阻擋
PreToolUse阻擋工具呼叫
PermissionRequest拒絕權限請求
UserPromptSubmit阻擋提示處理並清除提示內容
Stop / SubagentStop阻止 Claude 或子代理人停止, 繼續對話
TaskCreated / TaskCompleted回滾任務建立, 或阻止任務被標記完成

WorktreeCreate任何非零退出碼都會讓 worktree 建立失敗
PostToolUse / PostToolUseFailure把 stderr 顯示給 Claude, 但工具已經執行過了
Notification / SessionStart / SessionEnd只把 stderr 顯示給使用者, 執行照常繼續
StopFailure輸出與退出碼一律被忽略
