Plugins reference

Complete technical reference for the Claude Code plugin system: schemas, CLI commands, and component specifications.

Plugin components reference

A plugin is a self-contained directory of components that extends Claude Code. Components include skills, agents, hooks, MCP servers, LSP servers, and monitors.

Location: skills/ or commands/, or a single SKILL.md at the plugin root. Skills are directories with SKILL.md; commands are flat markdown files.

skills/
├── pdf-processor/
│   ├── SKILL.md
│   ├── reference.md (optional)
│   └── scripts/ (optional)
└── code-reviewer/
    └── SKILL.md

Auto-discovered on install; Claude invokes them based on task context. If no skills/ dir and no manifest field, a root SKILL.md loads as a single skill — set frontmatter name to control the invocation name.

Location: agents/ directory. Markdown files with frontmatter: name, description, model, effort, maxTurns, tools, disallowedTools, skills, memory, background, isolation (only valid value "worktree").

---
name: agent-name
description: What this agent specializes in
model: sonnet
effort: medium
maxTurns: 20
disallowedTools: Write, Edit
---
Detailed system prompt...

For security, hooks, mcpServers, and permissionMode are not supported for plugin-shipped agents. Appear in @-mention typeahead as my-plugin:code-reviewer.

Location: hooks/hooks.json or inline in plugin.json.

{
  "hooks": { "PostToolUse": [{ "matcher": "Write|Edit",
    "hooks": [{ "type": "command", "command": "\"${CLAUDE_PLUGIN_ROOT}\"/scripts/format-code.sh" }] }] }
}

Hook types: command, http, mcp_tool, prompt, agent. Lifecycle events include SessionStart, Setup, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse, PostToolUseFailure, PostToolBatch, Notification, SubagentStart/Stop, TaskCreated/Completed, Stop, TeammateIdle, InstructionsLoaded, ConfigChange, CwdChanged, FileChanged, WorktreeCreate/Remove, PreCompact/PostCompact, Elicitation(Result), SessionEnd, and more.

NOTE

Hooks targeting a plugin's own bundled MCP server must use scoped tool names: mcp__plugin_<plugin-name>_<server-name>__<tool>. A matcher against the bare server key never fires.

Location: .mcp.json at plugin root, or inline in plugin.json.

{
  "mcpServers": {
    "plugin-database": {
      "command": "${CLAUDE_PLUGIN_ROOT}/servers/db-server",
      "args": ["--config", "${CLAUDE_PLUGIN_ROOT}/config.json"]
    }
  }
}

Start automatically when the plugin is enabled; appear as standard MCP tools alongside user-configured servers.

Location: .lsp.json at plugin root, or inline. Provides go-to-definition, find references, hover info, and instant diagnostics.

{ "go": { "command": "gopls", "args": ["serve"], "extensionToLanguage": { ".go": "go" } } }
commandrequired
LSP binary to execute (must be in PATH)
extensionToLanguagerequired
Maps file extensions to language identifiers
restartOnCrash / shutdownTimeoutoptional
Restart behavior; require v2.1.205+
diagnosticsoptional
Push diagnostics after edits (default true)

When multiple enabled servers claim the same extension, the first registered wins. A server missing required fields is skipped and doesn't claim its extensions (v2.1.205+). You must install the language server binary yourself.

Location: monitors/monitors.json, or experimental.monitors in plugin.json. Requires v2.1.105+. Runs a shell command for the session lifetime, delivering stdout lines as notifications. Runs only in interactive CLI sessions, unsandboxed at hook trust level.

[
  { "name": "deploy-status", "command": "\"${CLAUDE_PLUGIN_ROOT}\"/scripts/poll-deploy.sh", "description": "Deployment status changes" },
  { "name": "error-log", "command": "tail -F ./logs/error.log", "description": "Application error log", "when": "on-skill-invoke:debug" }
]

when: "always" (default, starts at session start/reload) or "on-skill-invoke:<skill-name>". Disabling a plugin mid-session doesn't stop already-running monitors.

Ship color themes appearing in /theme alongside built-ins. JSON file in themes/ with a base preset and sparse overrides map.

{ "name": "Dracula", "base": "dark", "overrides": { "claude": "#bd93f9", "error": "#ff5555" } }

Selecting persists custom:<plugin-name>:<slug>. Plugin themes are read-only; Ctrl+E copies into ~/.claude/themes/ for editing.

Skills-directory plugins

A folder under a skills directory containing .claude-plugin/plugin.json loads as <name>@skills-dir next session, with no marketplace or install step. Scaffold with plugin init.

foo/SKILL.md, no manifestA plain skill named foo
foo/.claude-plugin/plugin.jsonA plugin foo@skills-dir
plugin/skills/bar/SKILL.mdA skill bar packaged inside a plugin
~/.claude/skills/ (personal)

Loads in every project — the location is yours alone.

<cwd>/.claude/skills/ (project)

Loads only after accepting the trust dialog. MCP servers get per-server approval, LSP servers need trust, background monitors don't load.

WARNING

Project-scope @skills-dir plugins load only from the .claude/skills/ of the launch directory — they don't walk up to the repo root. Launch from the repo root or run /reload-plugins after changing directories.

Skill.md edits apply immediately; other component changes (hooks/, .mcp.json, agents/, output-styles/) need /reload-plugins or a restart. Disable with claude plugin disable my-tool@skills-dir; no uninstall step exists.

Plugin manifest schema

.claude-plugin/plugin.json defines metadata and configuration. Optional overall — if omitted, components auto-discover from default locations and the name derives from the directory.

{
  "name": "plugin-name", "displayName": "Plugin Name", "version": "1.2.0",
  "description": "Brief plugin description",
  "author": { "name": "Author Name", "email": "author@example.com" },
  "skills": "./custom/skills/", "commands": ["./custom/commands/special.md"],
  "hooks": "./config/hooks.json", "mcpServers": "./mcp-config.json",
  "experimental": { "themes": "./themes/", "monitors": "./monitors.json" },
  "dependencies": ["helper-lib", { "name": "secrets-vault", "version": "~2.1.0" }]
}

name is the only required field if a manifest is included. Unrecognized top-level fields are ignored (reported as warnings by claude plugin validate, or errors with --strict), which lets one manifest double as a VS Code/Cursor/npm/MCPB manifest.

User configuration

{
  "userConfig": {
    "api_endpoint": { "type": "string", "title": "API endpoint", "description": "Your team's API endpoint" },
    "api_token": { "type": "string", "title": "API token", "description": "API auth token", "sensitive": true }
  }
}

Fields per option: type (string/number/boolean/directory/file), title, description (required); sensitive, required, default, multiple, min/max (optional). Available as ${user_config.KEY}; non-sensitive values in settings.json, sensitive values in the system keychain (~2 KB limit).

Environment variables

${CLAUDE_PLUGIN_ROOT}
Absolute path to install directory. Changes on update; previous version stays ~7 days, treat as ephemeral
${CLAUDE_PLUGIN_DATA}
Persistent dir for state surviving updates: node_modules, venvs, caches
${CLAUDE_PROJECT_DIR}
Project root, same as hooks receive

${CLAUDE_PLUGIN_DATA} resolves to ~/.claude/plugins/data/{id}/. Common pattern: a SessionStart hook diffs a bundled manifest against a stored copy and reinstalls dependencies when they differ.

Plugin caching and file resolution

Marketplace plugins are copied to ~/.claude/plugins/cache rather than used in place, for security and verification. Each installed version is a separate cache directory; the previous version is marked orphaned and auto-removed 7 days after an update, giving concurrent sessions a grace period. Glob/Grep skip orphaned directories.

Path traversal limitations

Paths that traverse outside the plugin root (../shared-utils) don't work after install because those files aren't copied.

Share files with symlinks

Within own directoryPreserved as a relative symlink in the cache
Elsewhere in same marketplaceDereferenced — target content copied in its place
Outside the marketplaceSkipped for security

CLI commands reference

init
install
uninstall
prune
enable / disable
update / list
details / tag
claude plugin init <name> [--description] [--author] [--with skills agents hooks mcp lsp output-style channel] [-f]

Scaffolds at ~/.claude/skills/<name>/, loads as <name>@skills-dir next session. Alias: new. Admins can block via strictKnownMarketplaces or blockedMarketplaces.

claude plugin install <plugin> [-s user|project|local]

claude plugin install formatter@my-marketplace --scope project
claude plugin uninstall <plugin> [-s scope] [--keep-data] [--prune] [-y]

Aliases: remove, rm. Uninstalling from the last scope deletes ${CLAUDE_PLUGIN_DATA} unless --keep-data.

claude plugin prune [-s scope] [--dry-run] [-y]

Alias: autoremove. Removes auto-installed dependencies no plugin needs anymore. Requires v2.1.121+.

claude plugin enable <plugin> [-s scope]
claude plugin disable <plugin> [-s scope]

Enable transitively enables dependencies. Disable fails if another enabled plugin depends on the target — the error names a chained disable command.

claude plugin update <plugin> [-s user|project|local|managed]
claude plugin list [--json] [--available]

/plugin list works inline in a session; accepts --enabled/--disabled and ls shorthand.

claude plugin details <name>
claude plugin tag [--push] [--dry-run] [-f]

details shows component inventory and projected token cost (always-on vs on-invoke). tag creates a release git tag for the plugin in the current directory.

Distribution and versioning reference

Version resolves from: plugin.json version → marketplace entry version → git commit SHA (git-based sources) → unknown (npm/non-git local).

Explicit version

Set "version" in plugin.json. Users get updates only when you bump it. Best for published plugins with stable releases.

Commit-SHA version

Omit version entirely. Users get updates on every new commit. Best for internal/actively-developed plugins.

Follow semantic versioning (MAJOR.MINOR.PATCH) for explicit versions and document changes in CHANGELOG.md.
