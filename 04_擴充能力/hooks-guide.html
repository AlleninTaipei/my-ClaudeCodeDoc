用 Hooks 自動化操作

Hooks 是使用者自訂的 shell 指令, 在 Claude Code 生命週期特定時間點自動執行, 提供確定性的控制, 而不是仰賴 LLM 自行選擇是否執行。

建立你的第一個 Hook

這個範例建立一個桌面通知 hook, 當 Claude 在等你輸入時提醒你, 不必一直盯著終端機。

1 · 新增設定
2 · 驗證設定
3 · 測試 Hook

開啟 ~/.claude/settings.json 加入 Notification hook:

{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification ...'"
          }
        ]
      }
    ]
  }
}

輸入 /hooks 開啟 hooks 瀏覽器, 選擇 Notification 確認新 hook 出現在清單中, 選取後會顯示事件, matcher, 類型, 來源檔案與指令。

按 Esc 回到 CLI, 請 Claude 做一件需要權限的事, 然後切換離開終端機, 應該會收到桌面通知。

你能自動化什麼

Hooks 讓你在關鍵時間點執行程式碼: 編輯後格式化檔案, 執行前阻擋指令, 需要輸入時發送通知, session 開始時注入上下文等等。點選下方查看各種常見模式。

編輯後自動格式化
保護敏感檔案
壓縮後重新注入上下文
稽核設定變更
目錄切換時重新載入環境
自動核准特定權限

用 PostToolUse 事件搭配 Edit|Write matcher, 只在檔案編輯工具之後執行, 自動對 Claude 編輯過的檔案跑 Prettier。

{
  "hooks": { "PostToolUse": [{
    "matcher": "Edit|Write",
    "hooks": [{ "type": "command",
      "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write" }]
  }] }
}

用 PreToolUse hook 檢查目標檔案路徑是否符合保護清單 (如 .env, package-lock.json, .git/), 符合就以 exit code 2 阻擋編輯, Claude 會收到說明並調整做法。

用 SessionStart hook 搭配 compact matcher, 在每次壓縮之後重新提醒 Claude 專案慣例與最近的工作內容, 因為壓縮可能會遺失重要細節。

ConfigChange 事件在外部程式或編輯器修改設定檔時觸發, 可以把每次變更寫入稽核紀錄, 或用 exit code 2 阻擋未經授權的修改。

SessionStart 搭配 CwdChanged hook, 在 Claude 執行 cd 切換目錄時自動重新載入該目錄的環境變數, 適合搭配 direnv 等工具使用。

PermissionRequest hook 可以自動回答 "behavior": "allow" 略過核准對話框, 例如自動核准 ExitPlanMode, 但要把 matcher 限縮到最小範圍, 避免不小心核准所有工具呼叫。

Hooks 如何運作

事件觸發時, 所有符合的 hooks 會平行執行, 相同的 hook 指令會自動去重複。

合併多個結果

當多個 hook 符合同一個事件, 每個 hook 的指令都會執行完畢, Claude Code 才會合併結果。一個 hook 回傳 deny 不會阻止其他 hook 的副作用繼續執行。對於 PreToolUse 權限決策, 最嚴格的答案會勝出, 順序是 deny, defer, ask, allow。

過濾 hooks 用的 matcher

PreToolUse 等依工具名稱過濾, 例如 Bash, Edit|Write, mcp__.*
SessionStart依 session 啟動方式過濾, startup, resume, clear, compact
SubagentStart / Stop依代理人類型過濾, 例如 general-purpose, Explore
FileChanged依要監控的檔名字面值過濾, 例如 .envrc|.env

用 if 欄位做更精準的過濾

if 欄位使用權限規則語法, 同時比對工具名稱與參數, 只有比對成功時 hook 程序才會被產生。

{
  "hooks": { "PreToolUse": [{
    "matcher": "Bash",
    "hooks": [{ "type": "command",
      "if": "Bash(git *)",
      "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/check-git-policy.sh" }]
  }] }
}

Prompt-based 與 Agent-based Hooks

對於需要判斷力而非固定規則的決策, 可以改用 Claude 模型評估條件, 而不是執行固定的 shell 指令。

type: "prompt"

送出提示與輸入資料給模型 (預設 Haiku) 做單輪評估。

回傳 "ok": true 表示放行, "ok": false 依事件而定, 效果如把 reason 回饋給 Claude 繼續工作。

type: "agent"

產生一個可以讀檔, 搜尋程式碼並使用工具的子代理人, 在做出決策前先驗證實際狀態。

預設 timeout 60 秒, 最多 50 輪工具使用, 目前屬於實驗性功能。

{
  "hooks": { "Stop": [{ "hooks": [{
    "type": "prompt",
    "prompt": "Check if all tasks are complete. If not, respond with {\"ok\": false, \"reason\": \"...\"}."
  }] }] }
}

疑難排解

Hook 沒有觸發用 /hooks 確認事件下有正確列出, matcher 是否精確符合 (區分大小寫)
Hook error 訊息腳本以非零碼結束, 用絕對路徑或 ${CLAUDE_PROJECT_DIR} 參照, 或加上 chmod +x
Stop hook 卡在阻擋上限連續阻擋 8 次會被強制覆蓋, 檢查 stop_hook_active 欄位提早結束
JSON 驗證失敗shell profile 印出多餘文字混入 JSON, 把 echo 包在互動式判斷中

Hooks 提供確定性控制: 用 exit code 阻擋或放行最簡單直接, 需要更精細控制時改用 JSON 輸出, 需要判斷力則交給 prompt 或 agent 類型的 hook。
