Create and distribute a plugin marketplace

Build and host plugin marketplaces to distribute Claude Code extensions across teams and communities.

Overview

Creating and distributing a marketplace involves four stages: create the plugins you want to share, define a marketplace.json catalog, host it on a git provider, and let users add it with /plugin marketplace add.

1. Create pluginsBuild skills, agents, hooks, MCP servers, or LSP servers
2. Create the marketplace fileDefine a marketplace.json listing your plugins
3. Host the marketplacePush to GitHub, GitLab, or another git host
4. Share with usersUsers add it with /plugin marketplace add

Once live, update the marketplace by pushing changes to the repository. Users refresh with /plugin marketplace update.

This example builds a marketplace with one plugin, a quality-review skill for code reviews.

Create the directory structure for the marketplace, plugin, and skill.

mkdir -p my-marketplace/.claude-plugin
mkdir -p my-marketplace/plugins/quality-review-plugin/.claude-plugin
mkdir -p my-marketplace/plugins/quality-review-plugin/skills/quality-review

Create SKILL.md defining what the quality-review skill does.

---
description: Review code for bugs, security, and performance
---

Review the code I've selected or the recent changes for:
- Potential bugs or edge cases
- Security concerns
- Performance issues
- Readability improvements

Create plugin.json in .claude-plugin/ describing the plugin.

{
  "name": "quality-review-plugin",
  "description": "Adds a quality-review skill for quick code reviews",
  "version": "1.0.0"
}
NOTE

Setting version means users only receive updates when you change this field, so bump it on every release. If omitted and hosted in git, every commit counts as a new version.

Create the marketplace catalog that lists the plugin.

{
  "name": "my-plugins",
  "owner": { "name": "Your Name" },
  "plugins": [
    {
      "name": "quality-review-plugin",
      "source": "./plugins/quality-review-plugin",
      "description": "Adds a quality-review skill for quick code reviews"
    }
  ]
}

Add the marketplace and install the plugin.

/plugin marketplace add ./my-marketplace
/plugin install quality-review-plugin@my-plugins

Select code in your editor and run the new skill. Plugin skills are namespaced with the plugin name.

/quality-review-plugin:quality-review

HOW PLUGINS ARE INSTALLED

When users install a plugin, Claude Code copies the plugin directory to a cache location. Plugins can't reference files outside their directory using paths like ../shared-utils, because those files won't be copied. Use symlinks to share files across plugins.

Create the marketplace file

Create .claude-plugin/marketplace.json in your repository root. Each plugin entry needs at minimum a name and a source.

{
  "name": "company-tools",
  "owner": { "name": "DevTools Team", "email": "devtools@example.com" },
  "plugins": [
    {
      "name": "code-formatter",
      "source": "./plugins/formatter",
      "description": "Automatic code formatting on save",
      "version": "2.1.0",
      "author": { "name": "DevTools Team" }
    },
    {
      "name": "deployment-tools",
      "source": { "source": "github", "repo": "company/deploy-plugin" },
      "description": "Deployment automation tools"
    }
  ]
}

Marketplace schema

Required fields

Marketplace identifier (kebab-case). Public-facing, used as /plugin install my-tool@your-marketplace. Each user can register only one marketplace per name.

Marketplace maintainer info: name (required), email (optional)

List of available plugins
RESERVED NAMES

Names such as claude-code-marketplace, claude-code-plugins, anthropic-plugins, and similar are reserved for official Anthropic use and are re-checked on every load, not just when added. Names that impersonate official marketplaces are also blocked.

Plugin sources

Sources tell Claude Code where to fetch each plugin listed in the marketplace. After cloning or downloading, Claude Code copies the plugin into the local cache at ~/.claude/plugins/cache.

Source type:
Relative path
github
url (git)
git-subdir
npm
{ "name": "my-plugin", "source": "./plugins/my-plugin" }

Local directory within the marketplace repo. Must start with ./, resolved relative to the marketplace root (the directory containing .claude-plugin/), not the .claude-plugin/ directory itself. Don't use ../. Only works when the marketplace itself was added via git or a local directory, not a direct URL to marketplace.json.

{
  "name": "github-plugin",
  "source": { "source": "github", "repo": "owner/plugin-repo", "ref": "v2.0.0", "sha": "a1b2c3..." }
}

Fields: repo (required, owner/repo), ref (branch/tag, defaults to default branch), sha (40-char commit SHA). When both are set, sha is the effective pin.

{
  "name": "git-plugin",
  "source": { "source": "url", "url": "https://gitlab.com/team/plugin.git", "ref": "main" }
}

Fields: url (required, https:// or git@, .git suffix optional), ref, sha.

{
  "name": "my-plugin",
  "source": { "source": "git-subdir", "url": "https://github.com/acme-corp/monorepo.git", "path": "tools/claude-plugin" }
}

Uses a sparse, partial clone to fetch only the subdirectory, minimizing bandwidth for monorepos. Fields: url, path (required), ref, sha.

{
  "name": "my-npm-plugin",
  "source": { "source": "npm", "package": "@acme/claude-plugin", "version": "^2.0.0", "registry": "https://npm.example.com" }
}

Installed via npm install. Fields: package (required), version, registry (defaults to npmjs.org).

MARKETPLACE VS PLUGIN SOURCE

Marketplace source is where marketplace.json itself is fetched from (supports ref, not sha). Plugin source is where each listed plugin is fetched from (supports both ref and sha). They can point to different repositories, pinned independently.

Strict mode

strict: true (default)

plugin.json is the authority. Marketplace entry can supplement it with additional components; both merge.

strict: false

Marketplace entry is the entire definition. If the plugin also has a plugin.json declaring components, that's a conflict and it fails to load.

Configure .claude/settings.json so team members are prompted to install automatically once they trust the folder:

{
  "extraKnownMarketplaces": {
    "company-tools": { "source": { "source": "github", "repo": "your-org/claude-plugins" } }
  },
  "enabledPlugins": { "code-formatter@company-tools": true }
}

Pre-populate a plugins directory at build time via CLAUDE_CODE_PLUGIN_SEED_DIR so containers start with marketplaces/plugins available without runtime cloning. Layer multiple seeds with : (Unix) or ; (Windows).

CLAUDE_CODE_PLUGIN_CACHE_DIR=/opt/claude-seed claude plugin marketplace add your-org/plugins
CLAUDE_CODE_PLUGIN_CACHE_DIR=/opt/claude-seed claude plugin install my-tool@your-plugins

Administrators restrict which marketplaces users may add via strictKnownMarketplaces in managed settings; pair with disableSideloadFlags to also block CLI sideload flags.

UndefinedNo restrictions
Empty array []Complete lockdown, no new marketplaces

{
  "strictKnownMarketplaces": [
    { "source": "hostPattern", "hostPattern": "^github\\.example\\.com$" }

Checked before any network/filesystem operation, on add and on install/update/refresh/auto-update. Uses exact matching (no URL normalization); prefer hostPattern when a repo can be cloned by multiple URL forms.

Version resolution and release channels

Versions determine cache paths and update detection. Resolved from the first set of: plugin.json version → marketplace entry version → git commit SHA.

WARNING

Setting version pins the plugin — pushing commits without bumping it does nothing for existing users. Avoid setting version in both plugin.json and the marketplace entry; plugin.json always wins silently.

Set up release channels

Create two marketplaces pointing to different refs/SHAs of the same repo, then assign each to a user group via managed settings.

// stable-tools marketplace
{ "name": "code-formatter", "source": { "source": "github", "repo": "acme-corp/code-formatter", "ref": "stable" } }

// latest-tools marketplace
{ "name": "code-formatter", "source": { "source": "github", "repo": "acme-corp/code-formatter", "ref": "latest" } }

Each channel must resolve to a different version string or Claude Code treats them as identical.

Rename or remove a plugin

A plugin's name is its stable identifier; changing it breaks existing installs. To relabel without breaking installs, set displayName and keep name unchanged. To actually rename or remove, add a top-level renames map (requires v2.1.193+):

{
  "name": "acme-tools",
  "plugins": [ { "name": "code-formatter", "source": "./plugins/code-formatter" } ],
  "renames": { "formatter": "code-formatter", "legacy-linter": null }
}
Points to new nameLoads under new name, shows a one-line notice, rewrites settings keys
null entryOld key dropped, notice reports removal
Remote source renameReports plugin-cache-miss; user must /plugin install once under new name

Treat renames as append-only history — keep old entries even after users have migrated; Claude Code follows chains. Run claude plugin validate . to reject cycles or dangling chains.

Manage marketplaces from the CLI

Command:
add
list
remove
update
claude plugin marketplace add <source> [options]

claude plugin marketplace add acme-corp/claude-plugins
claude plugin marketplace add acme-corp/claude-plugins@v2.0
claude plugin marketplace add https://gitlab.example.com/team/plugins.git
claude plugin marketplace add ./my-marketplace --scope project
claude plugin marketplace add acme-corp/monorepo --sparse .claude-plugin plugins

Options: --scope <user|project|local> (default user), --sparse <paths...>. A bare host without a scheme is rejected as of v2.1.196.

claude plugin marketplace list [--json]

With --json, entries include name, source, and source-specific fields (repo, url, path, ref).

claude plugin marketplace remove <name> [--scope <scope>]

Alias: rm. Omitting --scope removes the declaration from every editable scope.

WARNING

Removing a marketplace from its last remaining scope also uninstalls plugins installed from it. Use update to refresh without losing plugins.

claude plugin marketplace update [name]

Omit name to update all marketplaces. Seed-managed marketplaces are read-only and skipped.

Troubleshooting

Marketplace not loadingVerify URL accessible, .claude-plugin/marketplace.json exists, JSON valid, private-repo permissions
Validation errorsclaude plugin validate . checks schema, duplicate names, path traversal; per-entry plugin.json checks too
Plugin install failuresCheck source URLs, required files, GitHub access, pinned commit still exists
Private repo auth failsVerify gh auth status, credential.helper config, or GITHUB_TOKEN for background updates
Updates fail offlineSet CLAUDE_CODE_PLUGIN_KEEP_MARKETPLACE_ON_FAILURE=1 to keep stale cache instead of wiping it
Git operations time outRaise CLAUDE_CODE_PLUGIN_GIT_TIMEOUT_MS (default 120s)
Relative paths fail in URL marketplacesURL-based marketplaces only download marketplace.json; use GitHub/npm/git-URL sources or a git-based marketplace instead
Files not found after installPlugins are copied to a cache dir; paths like ../shared-utils don't resolve — use symlinks
