Built-in output styles

Output styles change how Claude responds, not what Claude knows — they modify the system prompt to set role, tone, and output format.

Change your output style

Run /config and select Output style to pick from a menu. Saved to .claude/settings.local.json at the local project level.

{ "outputStyle": "Explanatory" }
NOTE

The standalone /output-style command was deprecated in v2.1.73 and removed in v2.1.91 (max-version 2.1.90). Use /config or edit the outputStyle setting directly.

Output style is part of the system prompt, read once at session start. Changes take effect after /clear or a new session.

Create a custom output style

A custom output style is a Markdown file: frontmatter for metadata, then instructions added to the system prompt.

Save at one of three levels; the file name becomes the style name unless name is set in frontmatter.

User~/.claude/output-styles
Project.claude/output-styles
Managed policy.claude/output-styles inside the managed settings directory

Project output styles load from every .claude/output-styles/ between the working directory and the repo root. As of v2.1.178, when multiple nested directories define the same style name, the one closest to the working directory wins.

Decide whether to keep Claude Code's software engineering instructions with keep-coding-instructions: true.

---
name: Diagrams first
description: Lead every explanation with a diagram
keep-coding-instructions: true
---

When explaining code, architecture, or data flow, start with a Mermaid diagram showing the structure, then explain in prose.

## Diagram conventions

Use `flowchart TD` for control flow and `sequenceDiagram` for request paths. Keep diagrams under 15 nodes.

Run /config and select your style under Output style. Takes effect after /clear or the next session.

Plugins can also ship output styles in an output-styles/ directory.

Style name if not the file name. Default: inherits from file name

Shown in the /config picker. Default: none

Keep built-in software engineering instructions. Default: false
force-for-plugin
Plugin output styles only: apply automatically when the plugin is enabled, overriding the user's setting. Default: false

How output styles work

  • Custom instructions are added to the end of the system prompt
  • All styles trigger reminders for Claude to adhere to the instructions during the conversation
  • Custom styles leave out the built-in software engineering instructions (scoping changes, comments, verification) unless keep-coding-instructions: true

Adding instructions increases input tokens, though prompt caching reduces this after the first request. Explanatory and Learning produce longer responses by design, increasing output tokens. For custom styles, output usage depends on your instructions.
