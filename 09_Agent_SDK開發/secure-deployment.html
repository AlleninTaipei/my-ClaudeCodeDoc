安全部署 AI Agent

以隔離, 憑證管理與網路控制, 保護 Claude Code 與 Agent SDK 的部署環境。

威脅模型

Agent 可能因為 prompt injection (內容中埋藏的指令) 或模型誤判而採取非預期行動。即使模型本身經過訓練以抵抗這類攻擊, 縱深防禦仍是良好實務: 例如當 agent 處理到惡意檔案並被誘導把客戶資料傳到外部伺服器時, 網路控制可以直接封鎖該請求。

安全部署不需要昂貴的專屬基礎設施, 隔離, 最小權限與縱深防禦這些適用於任何半信任程式碼的原則, 同樣適用於 agent。

內建安全功能

權限系統
每個工具與 bash 指令都可設定允許, 封鎖或詢問使用者, 支援萬用字元規則, 組織可設定跨使用者的統一政策。
指令解析
執行 bash 指令前先解析成 AST 並比對權限規則, 無法乾淨解析或不符合允許規則的指令需要明確核准, eval 等少數語法一律需要核准。
網頁搜尋摘要
搜尋結果會先摘要再放入 context, 而非直接傳入原始內容, 降低惡意網頁內容造成 prompt injection 的風險。
Sandbox 模式
bash 指令可在限制檔案系統與網路存取的沙盒環境中執行。

安全原則

需要在 Claude Code 預設值之外進一步強化時, 以下三個原則可作為選擇依據。

安全邊界
把敏感資源 (如憑證) 放在 agent 環境的邊界之外, 例如用外部 proxy 注入 API key, agent 本身永遠看不到憑證。
最小權限
檔案系統只掛載必要目錄並偏好唯讀, 網路透過 proxy 限制到特定端點, 憑證以 proxy 注入而非直接暴露, 容器中移除不必要的 Linux capabilities。
縱深防禦
疊加容器隔離, 網路限制, 檔案系統控制與 proxy 端請求驗證等多重控管, 依威脅模型與營運需求選擇組合。

憑證管理

推薦做法是在 agent 安全邊界之外執行一個 proxy, 由它把憑證注入到對外請求中。agent 傳送不含憑證的請求, proxy 負責加上憑證再轉發。

ANTHROPIC_BASE_URL

簡單但僅適用於 sampling API 請求, 讓 proxy 能檢視並修改明文請求。

export ANTHROPIC_BASE_URL="http://localhost:8080"
HTTP_PROXY / HTTPS_PROXY

系統層級設定, HTTPS 會建立加密 CONNECT 通道, 若不做 TLS 攔截則 proxy 看不到內容。

export HTTP_PROXY="http://localhost:8080"
export HTTPS_PROXY="http://localhost:8080"

proxy 實作選項

Envoy Proxy具備 credential_injector filter 的正式環境級 proxy
mitmproxy可終止 TLS 以檢視並修改 HTTPS 流量
Squid具備存取控制清單的快取型 proxy
LiteLLM具備憑證注入與流量限制的 LLM gateway

其他服務的憑證存取

兩種做法:
自訂工具
流量轉發

透過 MCP server 或自訂工具把請求轉送到邊界外的服務, 例如 git MCP server 把指令轉給 host 上的 git proxy 加上驗證後再連往遠端 repository, agent 永遠看不到憑證, 也不需要做 TLS 攔截。

對其他 HTTPS 服務 (GitHub, npm, 內部 API) 需要 TLS 終止型 proxy 解密, 檢視或修改流量後再重新加密轉發, 並在 agent 信任庫安裝 proxy 的 CA 憑證。注意並非所有程式都遵守 HTTP_PROXY, Node.js fetch() 預設會忽略, Node 24+ 可設定 NODE_USE_ENV_PROXY=1 啟用。

檔案系統設定

唯讀掛載程式碼

agent 只需要分析程式碼而不修改時, 以唯讀方式掛載目錄。

docker run -v /path/to/code:/workspace:ro agent-image
可寫入位置

需要暫時性工作區時使用 tmpfs, 容器停止即清除; 若要先審查再套用變更, 可用 overlay 檔案系統把變更存到獨立層。

--read-only --tmpfs /tmp:rw,noexec,size=100m
警告

即使是唯讀存取程式碼目錄, 也可能暴露憑證。常見高風險檔案包括 .env, ~/.git-credentials, ~/.aws/credentials, ~/.config/gcloud, ~/.kube/config, .npmrc, *-service-account.json, *.pem 等, 掛載前應排除或先行清理。
