從 Agent 取得結構化輸出

用 JSON Schema, Zod 或 Pydantic 定義輸出形狀, 讓多輪工具使用後的結果變成經過驗證的型別安全資料.

為什麼需要結構化輸出?

Agent 預設回傳自由格式文字, 適合聊天但不適合程式化使用. 結構化輸出讓你取得可直接傳給應用程式邏輯, 資料庫或 UI 元件的型別化資料.

比較:
沒有結構化輸出
有結構化輸出
Here's a classic chocolate chip cookie recipe! **Chocolate Chip Cookies** Prep time: 15 minutes | Cook time: 10 minutes Ingredients: - 2 1/4 cups all-purpose flour - 1 cup butter, softened ...
{ "name": "Chocolate Chip Cookies", "prep_time_minutes": 15, "cook_time_minutes": 10, "ingredients": [ { "item": "all-purpose flour", "amount": 2.25, "unit": "cups" } ], "steps": ["Preheat oven to 375°F", "Cream butter and sugar"] }
差異

沒有結構化輸出時, 你得自己解析標題, 把 "15 minutes" 轉成數字, 拆分食材與步驟, 並處理不一致的格式. 有結構化輸出時, 你定義好想要的形狀, 就能直接在應用程式中使用型別化資料.

快速上手

定義描述你要的資料形狀的 JSON Schema, 再透過 query() 的 outputFormat (TypeScript) 或 output_format (Python) 選項傳入. Agent 完成後, 結果訊息會包含符合你 schema 的 structured_output 欄位.

選擇語言:
TypeScript
Python
import { query } from "@anthropic-ai/claude-agent-sdk"; const schema = { type: "object", properties: { company_name: { type: "string" }, founded_year: { type: "number" }, headquarters: { type: "string" } }, required: ["company_name"] }; for await (const message of query({ prompt: "Research Anthropic and provide key company information", options: { outputFormat: { type: "json_schema", schema: schema } } })) { if (message.type === "result" && message.subtype === "success" && message.structured_output) { console.log(message.structured_output); // { company_name: "Anthropic", founded_year: 2021, headquarters: "San Francisco, CA" } } }
import asyncio from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage schema = { "type": "object", "properties": { "company_name": {"type": "string"}, "founded_year": {"type": "number"}, "headquarters": {"type": "string"}, }, "required": ["company_name"], } async def main(): async for message in query( prompt="Research Anthropic and provide key company information", options=ClaudeAgentOptions(output_format={"type": "json_schema", "schema": schema}), ): if isinstance(message, ResultMessage) and message.structured_output: print(message.structured_output) asyncio.run(main())

用 Zod 與 Pydantic 建立型別安全 Schema

不用手寫 JSON Schema, 可改用 Zod (TypeScript) 或 Pydantic (Python) 定義 schema. 這些函式庫會自動產生 JSON Schema, 並讓你將回應解析為具有自動完成與型別檢查的完整型別物件.

選擇語言:
TypeScript (Zod)
Python (Pydantic)
import { z } from "zod"; import { query } from "@anthropic-ai/claude-agent-sdk"; const FeaturePlan = z.object({ feature_name: z.string(), summary: z.string(), steps: z.array(z.object({ step_number: z.number(), description: z.string(), estimated_complexity: z.enum(["low", "medium", "high"]) })), risks: z.array(z.string()) }); const schema = z.toJSONSchema(FeaturePlan); for await (const message of query({ prompt: "Plan how to add dark mode support to a React app.", options: { outputFormat: { type: "json_schema", schema: schema } } })) { if (message.type === "result" && message.structured_output) { const parsed = FeaturePlan.safeParse(message.structured_output); if (parsed.success) { console.log(parsed.data.feature_name); } } }
from pydantic import BaseModel from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage class Step(BaseModel): step_number: int description: str estimated_complexity: str class FeaturePlan(BaseModel): feature_name: str summary: str steps: list[Step] risks: list[str] async def main(): async for message in query( prompt="Plan how to add dark mode support to a React app.", options=ClaudeAgentOptions(output_format={"type": "json_schema", "schema": FeaturePlan.model_json_schema()}), ): if isinstance(message, ResultMessage) and message.structured_output: plan = FeaturePlan.model_validate(message.structured_output) print(plan.feature_name)

輸出格式設定

type
設為 "json_schema" 以啟用結構化輸出
schema
定義輸出結構的 JSON Schema 物件, 可用 z.toJSONSchema() 或 .model_json_schema() 產生

SDK 支援標準 JSON Schema 功能, 包含所有基本型別 (object, array, string, number, boolean, null), enum, const, required, 巢狀物件以及 $ref 定義.

範例: TODO 追蹤 Agent

此範例展示結構化輸出如何搭配多步驟工具使用. Agent 需要在程式碼庫中尋找 TODO 註解, 再對每一筆查詢 git blame 資訊, 自主決定要用哪些工具 (Grep 搜尋, Bash 執行 git 指令), 並把結果整合成單一結構化回應.

todo_schema = { "type": "object", "properties": { "todos": { "type": "array", "items": { "type": "object", "properties": { "text": {"type": "string"}, "file": {"type": "string"}, "line": {"type": "number"}, "author": {"type": "string"}, "date": {"type": "string"} }, "required": ["text", "file", "line"] } }, "total_count": {"type": "number"} }, "required": ["todos", "total_count"] }
設計重點

schema 中的 author 與 date 為選填欄位, 因為並非每個檔案都能取得 git blame 資訊. Agent 會填入能找到的內容, 其餘欄位省略.

錯誤處理

當 schema 過於複雜, 任務本身模糊不清, 或 agent 達到重試上限時, 結構化輸出可能失敗. 也可能在沒有驗證失敗的情況下發生: 模型 fallback 可能會在串流中途撤回已完成的輸出, 若沒有重試補上就會以相同錯誤結束.

success
輸出已成功產生並通過驗證
error_max_structured_output_retries
多次嘗試後仍無有效輸出 (驗證失敗, 或模型 fallback 撤回且無成功重試)

避免錯誤的技巧: 保持 schema 精簡, 深度巢狀且必填欄位過多的 schema 較難滿足; 讓 schema 貼合任務, 若任務可能缺少某些資訊就把該欄位設為選填; 使用清楚的 prompt, 模糊的 prompt 會讓 agent 更難判斷該產出什麼.
