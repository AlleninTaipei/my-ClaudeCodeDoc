Tool Search 大規模工具搜尋

透過依需要動態發現與載入工具, 讓 agent 能擴充運用成百上千個工具, 而不必把所有定義都塞進 context window。

範圍圖例 UNIVERSAL 各平台皆適用 TOOL-SPECIFIC 依平台 / 代理環境而異

為什麼需要 Tool SearchUNIVERSAL

Tool search 讓 agent 能運用數百甚至數千個工具, 做法是依需要動態發現並載入工具, 而不是一開始就把所有工具定義都載入 context window, 只搜尋並載入真正需要的工具。

隨著工具庫規模增加, 這個做法解決了兩個挑戰:

Context 效率
工具定義可能佔用大量 context window, 50 個工具可能耗用 10 到 20K tokens, 壓縮實際工作可用的空間
工具選擇準確度
同時載入超過 30 到 50 個工具時, 工具選擇準確度會下降
預設行為

Tool search 預設為開啟狀態。除 Haiku 以外的每個 Claude 模型都支援 Tool search。

運作原理

當 Tool search 啟用時, 工具定義不會出現在 context window 中, agent 只會收到可用工具的摘要, 需要時再搜尋相關工具。

工具定義保留工具定義不會提前放入 context window
收到摘要agent 收到可用工具的摘要, 當任務需要尚未載入的能力時進行搜尋
載入 3-5 個工具最相關的 3 到 5 個工具被載入 context, 供後續回合持續使用
壓縮後重新搜尋若對話夠長導致 SDK 壓縮先前訊息以釋放空間, 先前發現的工具可能被移除, agent 會依需要再次搜尋

Tool search 在 Claude 第一次發現工具時會增加一次額外的往返 (搜尋步驟), 但對於龐大工具集而言, 每個回合更小的 context 會抵銷這個成本。若工具數少於約 10 個, 一開始就全部載入通常反而更快。

設定 Tool SearchTOOL-SPECIFIC

Tool search 預設開啟。在 Vertex AI 上預設為關閉 (僅 Claude Sonnet 4.5 以上與 Claude Opus 4.5 以上支援), 當 ANTHROPIC_BASE_URL 指向非官方主機時也預設關閉, 因為多數代理伺服器不會轉發 tool_reference 區塊。可用 ENABLE_TOOL_SEARCH 環境變數覆寫預設值。

(未設定)
Tool search 開啟, 工具定義延後並依需要發現。在 Vertex AI 或非官方 ANTHROPIC_BASE_URL 時回退為提前載入
true
Tool search 永遠開啟, 即使在 Vertex AI 或透過代理伺服器也會送出 beta header, 若平台不支援會導致請求失敗
auto
比對所有工具定義的合併 token 數與模型 context window, 超過 10% 時啟用 tool search, 未超過則正常全部載入
auto:N
與 auto 相同, 但可自訂百分比, 例如 auto:5 在工具定義超過 5% 時啟用, 數值越低啟用越早
false
Tool search 關閉, 每個回合都載入所有工具定義

設定範例

連接一個暴露許多工具的遠端 MCP server, 用萬用字元預先核准全部工具, 並用 auto:5 讓工具定義超過 context window 的 5% 時才啟用 tool search:

語言: 
import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "Find and run the appropriate database query",
  options: {
    mcpServers: {
      "enterprise-tools": { type: "http", url: "https://tools.example.com/mcp" }
    },
    allowedTools: ["mcp__enterprise-tools__*"], // 萬用字元預先核准此 server 的所有工具
    env: { ENABLE_TOOL_SEARCH: "auto:5" } // 超過 context window 5% 時啟用
  }
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage

async def main():
    options = ClaudeAgentOptions(
        mcp_servers={"enterprise-tools": {"type": "http", "url": "https://tools.example.com/mcp"}},
        allowed_tools=["mcp__enterprise-tools__*"],
        env={"ENABLE_TOOL_SEARCH": "auto:5"},
    )
    async for message in query(prompt="Find and run the appropriate database query", options=options):
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)

asyncio.run(main())

將 ENABLE_TOOL_SEARCH 設為 "false" 會關閉 tool search 並在每個回合載入所有工具定義, 這會移除搜尋往返, 當工具數量少 (少於約 10 個) 且定義可以輕鬆放入 context window 時速度會更快。

優化工具發現

搜尋機制會將查詢與工具名稱及描述做比對, 名稱和描述取得越具體, 越容易被相關查詢命中。

較容易被搜尋到

名稱: search_slack_messages

描述: "Search Slack messages by keyword, channel, or date range"

較不容易被搜尋到

名稱: query_slack

描述: "Query Slack"

也可以在系統提示中加入一段列出可用工具分類的說明, 讓 agent 了解有哪些種類的工具可供搜尋:

You can search for tools to interact with Slack, GitHub, and Jira.
