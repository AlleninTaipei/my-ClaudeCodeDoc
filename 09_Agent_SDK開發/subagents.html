SDK 中的 Subagents

定義並呼叫 subagents 以隔離脈絡, 平行執行任務, 並在 Claude Agent SDK 應用中套用專門化指示.

概觀

Subagents 是主要 agent 可以產生出來處理特定子任務的獨立 agent 實例. 用它們來隔離脈絡, 平行執行多個分析, 並套用專門指示而不需增加主 agent prompt 的長度.

程式化定義
在 query() 選項中使用 agents 參數, SDK 應用建議採用此方式
檔案系統定義
在 .claude/agents/ 目錄中以 markdown 檔案定義
內建 general-purpose
Claude 可隨時透過 Agent 工具呼叫內建的 general-purpose subagent, 不需你額外定義
如何被觸發

定義 subagent 後, Claude 會根據每個 subagent 的 description 欄位判斷是否要呼叫它. 撰寫清楚的描述, Claude 就能自動把任務指派給合適的 subagent, 你也可以在 prompt 中直接指名要求使用某個 subagent.

使用 Subagents 的優點

脈絡隔離
每個 subagent 都在自己全新的對話中執行, 中間的工具呼叫與結果都留在 subagent 內, 只有最終訊息回傳給父層. 例如 research-assistant subagent 可以探索數十個檔案而不會讓內容累積到主對話中
平行化
多個 subagents 可以同時執行, 讓獨立子任務的完成時間等於最慢的那一個, 而不是全部加總. 例如程式碼審查時可同時執行 style-checker, security-scanner, test-coverage
專門化指示與知識
每個 subagent 都可以有量身打造的系統 prompt, 包含特定專業知識, 最佳實務與限制. 例如 database-migration subagent 可具備 SQL 最佳實務與回滾策略等專門知識
工具限制
Subagents 可被限制只能使用特定工具, 降低意外操作的風險. 例如 doc-reviewer subagent 只給 Read 和 Grep, 確保它只能分析而不會意外修改文件

建立 Subagents

用 agents 參數在程式碼中直接定義 subagents. 以下範例建立一個唯讀存取的程式碼審查者與一個可執行指令的測試執行者. Claude 透過 Agent 工具呼叫 subagents, 因此需將 Agent 加入 allowedTools 以自動核准呼叫.

選擇語言:
Python
TypeScript
from claude_agent_sdk import query, ClaudeAgentOptions, AgentDefinition async def main(): async for message in query( prompt="Review the authentication module for security issues", options=ClaudeAgentOptions( allowed_tools=["Read", "Grep", "Glob", "Agent"], agents={ "code-reviewer": AgentDefinition( description="Expert code review specialist.", prompt="You are a code review specialist...", tools=["Read", "Grep", "Glob"], model="sonnet", ), "test-runner": AgentDefinition( description="Runs and analyzes test suites.", prompt="You are a test execution specialist...", tools=["Bash", "Read", "Grep"], ), }, ), ): if hasattr(message, "result"): print(message.result)
import { query } from "@anthropic-ai/claude-agent-sdk"; for await (const message of query({ prompt: "Review the authentication module for security issues", options: { allowedTools: ["Read", "Grep", "Glob", "Agent"], agents: { "code-reviewer": { description: "Expert code review specialist.", prompt: "You are a code review specialist...", tools: ["Read", "Grep", "Glob"], model: "sonnet" }, "test-runner": { description: "Runs and analyzes test suites.", prompt: "You are a test execution specialist...", tools: ["Bash", "Read", "Grep"] } } } })) { if ("result" in message) console.log(message.result); }

AgentDefinition 設定欄位

description (必要)
此 agent 何時該被使用的自然語言描述
prompt (必要)
定義 agent 角色與行為的系統 prompt
tools
允許的工具名稱陣列, 省略則繼承全部工具
disallowedTools
從工具集中移除的工具名稱, 也支援 mcp__server 這類 MCP 伺服器層級的樣式
model
覆寫此 agent 的模型, 可用 fable, opus, sonnet, haiku, inherit 或完整模型 ID
skills
在啟動時預先載入到此 agent 脈絡的 skill 名稱清單
memory
此 agent 的記憶來源, 'user' | 'project' | 'local'
mcpServers
此 agent 可用的 MCP servers, 用名稱或內嵌設定指定
maxTurns
此 agent 停止前的最大 agentic 輪數
background
被呼叫時是否以非阻塞的背景任務執行
effort
推理強度等級: low, medium, high, xhigh, max 或數值
permissionMode
此 agent 內工具執行的權限模式
巢狀 Subagent

自 Claude Code v2.1.172 起, subagent 可以再產生自己的 subagent. 主 agent 以下第五層的 subagent 無法再產生 subagent (無論前景或背景執行). 若要防止某 subagent 產生其他 subagent, 從其 tools 中省略 Agent 或將其加入 disallowedTools.

檔案系統定義

也可在 .claude/agents/ 目錄以 markdown 檔案定義 subagents. 程式化定義的 agent 若與檔案系統定義同名, 會優先套用程式化定義. 即使沒有自訂 subagent, Claude 仍可呼叫內建的 general-purpose subagent.

Subagent 會繼承什麼

Subagent 的脈絡從空白開始 (沒有父層對話), 但並非完全空白. 父層傳給 subagent 的唯一管道是 Agent 工具的 prompt 字串, 因此請把 subagent 需要的檔案路徑, 錯誤訊息或決策直接寫進該 prompt.

Subagent 會收到

自己的系統 prompt 與 Agent 工具的 prompt

專案 CLAUDE.md (透過 settingSources 載入)

工具定義 (繼承自父層, 或 tools 指定的子集)

Subagent 不會收到

父層的對話歷史或工具結果

預先載入的 skill 內容, 除非列在 AgentDefinition.skills 中

父層的系統 prompt

保留原始輸出

父層會原封不動收到 subagent 的最終訊息作為 Agent 工具結果, 但父層自己的回應中可能會加以摘要. 若要在使用者可見的回應中保留 subagent 輸出原文, 需在傳給主要 query() 呼叫的 prompt 或 systemPrompt 選項中明確加入指示.

呼叫 Subagents

1 · 自動呼叫
2 · 明確呼叫
3 · 動態設定

Claude 會根據任務內容與每個 subagent 的 description 自動決定是否呼叫. 例如若你定義了一個描述為 "Performance optimization specialist for query tuning" 的 performance-optimizer subagent, 當 prompt 提到優化查詢時 Claude 就會自動呼叫它. 撰寫清楚具體的描述, 才能讓 Claude 正確配對任務與 subagent.

要確保 Claude 使用特定 subagent, 可在 prompt 中直接指名:

"Use the code-reviewer agent to check the authentication module"

這會略過自動配對機制, 直接呼叫指定的 subagent.

你可以依據執行期條件動態建立 agent 定義. 以下範例建立一個依嚴格程度使用不同模型的安全審查者, 嚴格模式使用更強大的模型.

def create_security_agent(security_level: str) -> AgentDefinition: is_strict = security_level == "strict" return AgentDefinition( description="Security code reviewer", prompt=f"You are a {'strict' if is_strict else 'balanced'} security reviewer...", tools=["Read", "Grep", "Glob"], model="opus" if is_strict else "sonnet", )

偵測呼叫與恢復執行

Subagents 透過 Agent 工具被呼叫. 要偵測何時呼叫了 subagent, 檢查 name 為 "Agent" 的 tool_use 區塊 (v2.1.63 之前為 "Task", 建議兩者都檢查以確保相容性). Subagent 脈絡內的訊息會帶有 parent_tool_use_id 欄位.

1. 擷取 session_id
在第一次 query 期間從訊息中取得
2. 擷取 agentId
從 Agent 工具結果文字中解析出 agentId: <id>
3. 恢復 session
在第二次 query 選項中傳入 resume: sessionId, 並在 prompt 中包含 agent ID
注意

必須恢復同一個 session 才能存取 subagent 的完整記錄, 每次 query() 呼叫預設會開啟新 session. 內建的 Explore 與 Plan agents 是一次性的, 不會回傳 agentId, 需要恢復時請改用自訂 agent 或 general-purpose. Subagent 記錄獨立於主對話持續存在: 主對話壓縮不會影響它們, 且依 cleanupPeriodDays 設定 (預設 30 天) 自動清除.

工具限制與常見組合

唯讀分析
Read, Grep, Glob — 可檢查程式碼但無法修改或執行
測試執行
Bash, Read, Grep — 可執行指令並分析輸出
程式碼修改
Read, Edit, Write, Grep, Glob — 完整讀寫存取但不能執行指令
完整存取
所有工具 — 省略 tools 欄位, 繼承父層全部工具

擴大規模與疑難排解

Subagents 適合每輪少量的委派任務. 若要協調數十到數百個 agent, 改用 Workflow 工具, 將協調邏輯移到執行期外部的腳本中執行. Workflow 工具自 TypeScript Agent SDK v0.3.149 起提供.

Claude 未委派給 subagent
確認 Agent 已加入 allowedTools; 用明確 prompt 指名 subagent; 撰寫清楚的 description
檔案系統 agent 未載入
.claude/agents/ 中的 agent 只在啟動時載入, 新增檔案後需重啟 session
Windows 長 prompt 失敗
命令列長度限制 (8191 字元) 可能導致失敗, 請精簡 prompt 或改用檔案系統定義

Subagents 是隔離脈絡, 平行處理與套用專門知識的核心機制. 少量委派任務用程式化或檔案系統定義的 subagent 即可, 若需要協調大量 agent, 則應改用 Workflow 工具.
