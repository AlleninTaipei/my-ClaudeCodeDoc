用 Hooks 攔截並控制 Agent 行為

在關鍵執行點攔截並自訂 agent 行為: 封鎖危險操作, 稽核工具呼叫, 轉換輸入輸出

Hooks 如何運作

1 · 事件觸發
2 · SDK 收集已註冊的 hooks
3 · Matcher 過濾
4 · Callback 執行
5 · 回傳決策

agent 執行過程中發生某件事: 工具即將被呼叫 (PreToolUse), 工具回傳結果 (PostToolUse), subagent 開始或結束, agent 閒置, 或執行結束。

SDK 檢查該事件類型是否有已註冊的 hooks, 包含 options.hooks 中的 callback 與設定檔中的 shell 指令 hooks。

若 hook 有 matcher pattern (例如 "Write|Edit"), SDK 會拿它與事件目標 (例如工具名稱) 比對, 沒有 matcher 的 hook 對每個該類型事件都會執行。

每個符合的 hook 的 callback 函式會收到相關資訊: 工具名稱, 參數, session ID, 以及其他事件專屬細節。

執行完任何操作 (記錄, API 呼叫, 驗證) 後, callback 回傳一個輸出物件告訴 agent 該怎麼做: 允許, 封鎖, 修改輸入, 或注入 context。

Step 1 of 5 
async def protect_env_files(input_data, tool_use_id, context):
    file_path = input_data["tool_input"].get("file_path", "")
    if file_path.split("/")[-1] == ".env":
        return {
            "hookSpecificOutput": {
                "hookEventName": input_data["hook_event_name"],
                "permissionDecision": "deny",
                "permissionDecisionReason": "Cannot modify .env files",
            }
        }
    return {}

可用的 Hooks

SDK 在 agent 執行的不同階段提供 hooks, 部分只在 TypeScript SDK 提供。

PreToolUse
工具呼叫請求, 可封鎖或修改, 例如封鎖危險的 shell 指令
PostToolUse
工具執行結果, 例如記錄所有檔案變更到稽核軌跡
PostToolUseFailure
工具執行失敗, 用於處理或記錄工具錯誤
UserPromptSubmit
使用者送出 prompt, 可注入額外 context
Stop
agent 執行停止, 用於離開前儲存 session 狀態
SubagentStart / SubagentStop
subagent 初始化或完成, 用於追蹤平行任務
PreCompact
對話壓縮請求, 用於在摘要前封存完整逐字稿
PermissionRequest
即將顯示權限對話框, 用於自訂權限處理
SessionStart / SessionEnd (TS 限定)
session 初始化或終止
Notification
agent 狀態訊息, 例如轉發到 Slack 或 PagerDuty

設定 Hooks 與 Matchers

透過 agent options 的 hooks 欄位設定 hook, 鍵是事件名稱, 值是 matcher 與 callback 的陣列。

options = ClaudeAgentOptions(
    hooks={"PreToolUse": [HookMatcher(matcher="Bash", hooks=[my_callback])]}
)

只包含字母, 數字, 底線, 連字號, 空格, 逗號, 或直線的 matcher 會以精確字串比對, 例如 Write|Edit 恰好比對這兩個工具。包含其他字元的 matcher 會以未錨定的正則表達式評估, 例如 ^mcp__ 會比對所有 MCP 工具。

提示

盡量使用 matcher 鎖定特定工具, 省略 pattern 會讓 callback 對每次該事件都執行。對於工具型 hooks, matcher 只比對工具名稱, 若要依檔案路徑過濾, 需在 callback 內檢查 tool_input.file_path。

Callback 的輸入與輸出

輸入

型別化的事件詳情物件, 每種 hook 類型有各自形狀, 皆共用 session_id, cwd, hook_event_name。

工具使用 ID: 關聯同一次工具呼叫的 PreToolUse 與 PostToolUse。

輸出

頂層欄位: systemMessage 顯示訊息給使用者, continue 決定 hook 後 agent 是否繼續。

hookSpecificOutput: 控制目前操作, 例如 PreToolUse 的 permissionDecision (allow/deny/ask/defer)。

注意

當多個 hooks 或權限規則同時適用時, deny 優先於 defer, defer 優先於 ask, ask 優先於 allow。任一 hook 回傳 deny, 操作就會被封鎖。

範例

選擇範例: 修改工具輸入 新增 context 並封鎖 自動核准唯讀工具 追蹤 subagent 活動

攔截 Write 呼叫並在 file_path 前加上 /sandbox, 把所有寫入導向沙箱目錄。回傳 updatedInput 時必須同時附上 permissionDecision: 'allow' 才會自動核准修改後的輸入。

return {
    "hookSpecificOutput": {
        "hookEventName": input_data["hook_event_name"],
        "permissionDecision": "allow",
        "updatedInput": {**input_data["tool_input"], "file_path": f"/sandbox{original_path}"},
    }
}

封鎖對 /etc 的寫入並同時告知模型與使用者原因: permissionDecisionReason 說給模型聽避免重試, systemMessage 顯示給使用者看。

if file_path.startswith("/etc"):
    return {
        "systemMessage": "Remember: system directories like /etc are protected.",
        "hookSpecificOutput": {"permissionDecision": "deny", "permissionDecisionReason": "..."},
    }

自動核准 Read, Glob, Grep 等唯讀工具, 讓它們不需使用者確認即可執行, 其餘工具仍走正常權限流程。

read_only_tools = ["Read", "Glob", "Grep"]
if input_data["tool_name"] in read_only_tools:
    return {"hookSpecificOutput": {"permissionDecision": "allow", ...}}

用 SubagentStop hook 監控 subagent 何時完成, 記錄 agent_id, transcript 路徑與工具使用 ID。

async def subagent_tracker(input_data, tool_use_id, context):
    print(f"[SUBAGENT] Completed: {input_data['agent_id']}")
    return {}

修正常見問題

Hook 未觸發
檢查事件名稱大小寫是否正確, matcher 是否精確比對工具名稱
Matcher 過濾異常
Matcher 只比對工具名稱, 若要依檔案路徑過濾需在 callback 內自行檢查
Hook 逾時
提高 HookMatcher 的 timeout 值, 或用 AbortSignal 處理取消
工具被意外封鎖
檢查所有 PreToolUse hooks 是否回傳 deny, 確認 matcher 沒有過寬
修改的輸入未生效
確認 updatedInput 放在 hookSpecificOutput 內而非頂層
Subagent 重複要求權限
Subagent 不會自動繼承父層權限, 用 PreToolUse hooks 自動核准特定工具
