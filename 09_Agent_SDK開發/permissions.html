設定 Agent SDK 權限 (Configure permissions)

透過權限模式, hooks 與宣告式允許/拒絕規則, 掌控你的 agent 如何使用工具。

權限評估的六個步驟

當 Claude 請求使用工具時, SDK 會依照固定順序依序檢查, 任何一步做出決定就會停止往下評估。

2 · 拒絕規則
3 · 詢問規則
4 · 權限模式
5 · 允許規則
6 · canUseTool 回呼
STEP 1

最先執行的是 hooks。hook 可以直接拒絕呼叫, 也可以放行讓流程繼續。即使 hook 回傳 allow, 仍不會跳過下方的拒絕與詢問規則, 那兩步一定會被評估。

STEP 2

檢查 disallowed_tools 與 settings.json 中的 deny 規則。一旦符合, 該工具就會被封鎖, 即使在 bypassPermissions 模式下也一樣。裸名規則 (例如 Bash) 會在此步驟之前就把整個工具從 Claude 的可視範圍移除, 只有像 Bash(rm *) 這種帶範圍的規則才會走到這裡才被檢查。

STEP 3

檢查 settings.json 中的 ask 規則。一旦符合, 呼叫會進入你的 canUseTool 回呼等待確認, 即使在 bypassPermissions 模式下也一樣。在 dontAsk 模式下, 符合的 ask 規則會直接變成拒絕, 因為該模式從不詢問。

STEP 4

套用目前生效的權限模式。bypassPermissions 會核准所有走到這一步的請求; acceptEdits 會核准檔案操作; plan 模式會讓所有檔案編輯與寫入類工具一律導向 canUseTool 回呼, 不受允許規則影響; 其餘模式則繼續往下評估。

STEP 5

檢查 allowed_tools 與 settings.json 中的 allow 規則。一旦符合就核准該工具。

STEP 6

若以上步驟都沒有決定結果, 就呼叫你的 canUseTool 回呼交由使用者判斷。在 dontAsk 模式下這一步會被跳過, 直接拒絕。

Step 1 of 6

允許與拒絕規則

allowed_tools 與 disallowed_tools 會加入上方評估流程中的允許與拒絕規則清單。允許規則只影響核准與否, 未列出的工具仍會落到權限模式繼續評估; 拒絕規則則依是否指定完整工具名稱, 或是限定範圍的樣式, 而有不同行為。

allowed_tools=["Read","Grep"]
Read 與 Grep 自動核准, 未列出的工具仍會落到權限模式與 canUseTool。
disallowed_tools=["Bash"]
Bash 工具定義會被整個移除, Claude 完全看不到也無法嘗試呼叫。
disallowed_tools=["Bash(rm *)"]
Bash 仍然可用, 但符合 rm * 的呼叫在任何模式下都會被拒絕, 包括 bypassPermissions。其餘 Bash 呼叫照常評估。
disallowed_tools=["*"]
移除所有工具定義。拒絕規則支援萬用字元, mcp__* 可比對所有伺服器的 MCP 工具。

鎖定型 agent 範例

const options = {
  allowedTools: ["Read", "Glob", "Grep"],
  permissionMode: "dontAsk"
};
注意

自動核准的工具永遠不會走到 canUseTool。透過更早步驟核准的呼叫 (acceptEdits, bypassPermissions, 或 allow 規則) 會直接跳過你的 canUseTool 回呼。若要確保每次呼叫都被檢查, 請改用 PreToolUse hook。

注意

allowed_tools 不會限制 bypassPermissions。設定 allowed_tools=["Read"] 同時搭配 permission_mode="bypassPermissions", 仍然會核准包含 Bash, Write, Edit 在內的所有工具。若需要 bypassPermissions 但要封鎖特定工具, 請改用 disallowed_tools。

SUBAGENT 繼承

當父層使用 bypassPermissions, acceptEdits 或 auto 時, 所有 subagent 都會繼承該模式且無法個別覆寫。subagent 可能擁有不同系統提示與較寬鬆的行為, 因此繼承 bypassPermissions 等於授予它們完整且自主的系統存取權。明確的 ask 規則仍會強制觸發提示。

設定權限模式的兩種時機

你可以在建立 query 時一次性設定權限模式, 也能在串流 session 進行中動態切換。

查詢時設定

建立 query 時傳入 permission_mode (Python) 或 permissionMode (TypeScript), 此設定會套用在整個 session, 除非之後動態變更。

query({
  prompt: "Help me refactor this code",
  options: {
    permissionMode: "default"
  }
});
串流過程中動態切換

呼叫 set_permission_mode() (Python) 或 setPermissionMode() (TypeScript) 可以在 session 中途改變模式, 新模式會立即套用到後續所有工具請求, 例如先從嚴格模式開始, 待建立信任後再放寬為 acceptEdits。

await q.setPermissionMode("acceptEdits");
