部署 Agent SDK

在正式環境部署 Agent SDK: subprocess 架構, session 持久化, 擴展, 可觀測性, 多租戶隔離

Subprocess 模型

當程式碼呼叫 query() 時, SDK 會啟動獨立的 claude CLI subprocess 並透過 stdio 溝通。該 subprocess 擁有 shell, 工作目錄, 與本地磁碟上的 JSONL session 逐字稿。一個 agent session 對應一個 subprocess, N 個並行 session 就是 N 個 subprocess。

Session 逐字稿
預設位於 ~/.claude/projects/, 容器重啟即遺失
CLAUDE.md 記憶檔案
使用者層級與專案層級, 同樣不隨容器持久化
工作目錄產出物
session 工作目錄下的檔案, 需自行規劃儲存策略
要點

以上三種狀態都活在容器檔案系統上, 都不會撐過容器重啟, 縮減, 或搬到不同節點。要跨主機保留逐字稿, 需設定 SessionStore adapter。

選擇 Session 模式

選擇模式: Ephemeral 短暫 Long-running 長駐 Hybrid 混合 Multi-agent 容器

為每個使用者任務建立容器, 任務完成即銷毀。適合一次性任務, 例如錯誤調查修復, 發票資料擷取, 文件翻譯。容器執行一次性 entrypoint, 呼叫 SDK 後即結束。

執行持久容器實例, 常常一個容器承載多個 SDK 行程, 服務持續性工作。適合會主動採取行動, 提供內容服務, 或處理高流量訊息串流的 agent, 例如信件分流 agent, 網站建置工具, 聊天機器人。

短暫容器在啟動時從 SessionStore 復原, 並將更新寫回。適合跨多次互動但互動間會閒置的 session, 例如個人專案管理助理, 間歇性深度研究, 客服 agent 讀取工單歷史。若無 SessionStore, 容器關閉會連逐字稿一起遺失。

在一個容器內執行多個 SDK subprocess, 適合需要緊密協作的 agent, 例如多 agent 模擬情境中互動的 agent。務必給每個 agent 各自的工作目錄, 避免互相覆寫檔案。

生產環境考量

選擇主題: Session 持久化 可觀測性 認證與密鑰 擴展與並行 多租戶隔離

對任何使用者期望能復原的 session, 用 SessionStore adapter 將逐字稿鏡射到持久儲存。SessionStore 只鏡射逐字稿, 不含 CLAUDE.md 或其他工作目錄產出物, 這些需要另外掛載共享磁碟或同步。

SDK 繼承環境中的 OpenTelemetry 設定, 在容器或協調器層級設定 OTEL 環境變數, 每次 query() 呼叫就會匯出 spans, metrics, 與 log events 到你的 collector。

CLAUDE_CODE_ENABLE_TELEMETRY=1
OTEL_TRACES_EXPORTER=otlp
OTEL_METRICS_EXPORTER=otlp
OTEL_LOGS_EXPORTER=otlp

Subprocess 從環境讀取 ANTHROPIC_API_KEY。對外流量應放在能注入憑證, 記錄請求的 egress proxy 之後, agent 只負責發出呼叫, proxy 負責加上憑證。

每個 session 都在自己的 subprocess 中執行, 一台主機的並行數受限於 RAM 能容納多少 subprocess: agents per host = (host RAM - overhead) / (per-session RAM ceiling)。

共享容器中, 預設會從檔案系統讀取設定與 CLAUDE.md, 可能讓一個租戶的 context 外洩到另一個租戶。應設定 settingSources: [], CLAUDE_CODE_DISABLE_AUTO_MEMORY=1, 每租戶獨立的 CLAUDE_CONFIG_DIR 與工作目錄。
