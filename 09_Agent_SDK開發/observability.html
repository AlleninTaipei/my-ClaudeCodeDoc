Observability with OpenTelemetry

透過 OpenTelemetry 從 Agent SDK 匯出 traces, metrics 與 events 到你的可觀測性後端

How telemetry flows from the SDK

Agent SDK 以子行程執行 Claude Code CLI, 透過本機 pipe 溝通。CLI 內建 OpenTelemetry 儀器化: 記錄每次模型請求與工具執行的 span, 發出 token 與成本計數器的 metrics, 並發出提示與工具結果的結構化日誌事件。SDK 本身不產生遙測資料, 只是把設定傳給 CLI 行程, 由 CLI 直接匯出到你的收集器。

Process environment

在應用程式啟動前, 於 shell, 容器或協調器中設定變數。每次 query() 呼叫自動套用, 無需改程式碼, 為正式環境建議做法。

Per-call options

在 ClaudeAgentOptions.env 設定變數。適用同一行程中不同代理需要不同遙測設定。TypeScript 的 env 會整個取代繼承的環境, 需自行展開 process.env。

三種獨立訊號

Metrics
token, 成本, session, 程式碼行數, 工具決策計數器 — OTEL_METRICS_EXPORTER
Log events
每則提示, API 請求, API 錯誤, 工具結果的結構化紀錄 — OTEL_LOGS_EXPORTER
Traces (beta)
每次互動, 模型請求, 工具呼叫, hook 的 span — OTEL_TRACES_EXPORTER + CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1

Enable telemetry export

遙測預設關閉, 需設定 CLAUDE_CODE_ENABLE_TELEMETRY=1 並選擇至少一個匯出器。

Python
TypeScript
OTEL_ENV = {
    "CLAUDE_CODE_ENABLE_TELEMETRY": "1",
    "CLAUDE_CODE_ENHANCED_TELEMETRY_BETA": "1",  # traces 需要, metrics/logs 不需要
    "OTEL_TRACES_EXPORTER": "otlp", "OTEL_METRICS_EXPORTER": "otlp", "OTEL_LOGS_EXPORTER": "otlp",
    "OTEL_EXPORTER_OTLP_ENDPOINT": "http://collector.example.com:4318",
}
options = ClaudeAgentOptions(env=OTEL_ENV)
const otelEnv = {
  CLAUDE_CODE_ENABLE_TELEMETRY: "1",
  CLAUDE_CODE_ENHANCED_TELEMETRY_BETA: "1",
  OTEL_TRACES_EXPORTER: "otlp", OTEL_METRICS_EXPORTER: "otlp", OTEL_LOGS_EXPORTER: "otlp",
  OTEL_EXPORTER_OTLP_ENDPOINT: "http://collector.example.com:4318",
};
// env 會取代繼承的環境, 記得展開 ...process.env
options: { env: { ...process.env, ...otelEnv } }
注意

不要把 console 設為匯出器, 因為 SDK 用 stdout 作為訊息通道。要在本機檢視遙測, 改指向本機收集器或 Jaeger 容器。

Flush telemetry from short-lived calls

CLI 會批次匯出遙測資料, 預設 metrics 每 60 秒, traces 與 logs 每 5 秒匯出一次。若行程在 CLI 關閉前被強制結束, 緩衝區內的資料會遺失, 可縮短匯出間隔降低風險。

Read agent traces

設定 CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1 後, agent loop 每個步驟都會變成可在追蹤後端檢視的 span。

claude_code.interaction包裹 agent loop 單一輪次, 從收到提示到產生回應
claude_code.llm_request包裹每次 Claude API 呼叫, 含模型名稱, 延遲, token 數
claude_code.tool包裹每次工具呼叫, 子 span 含權限等待與執行過程
claude_code.hook包裹每次 hook 執行, 需額外的 detailed beta tracing 變數

當代理透過 Task 工具產生子代理, 子代理的 span 會巢狀掛在父代理的 claude_code.tool span 下, 整條委派鏈成為同一條 trace。所有 span 預設帶有 session.id 屬性, 方便依 session 過濾。

Link traces 與 Tag telemetry

SDK 會自動把 W3C trace context 傳遞到 CLI 子行程。在應用程式中有作用中的 OpenTelemetry span 時呼叫 query(), SDK 會注入 TRACEPARENT/TRACESTATE, 讓 CLI 的 interaction span 成為你的 span 的子節點, 代理執行會出現在你應用程式的 trace 中, 而非獨立的根節點。

啟用 trace context 傳遞後, CLI 也會將 TRACEPARENT 轉發給每個 Bash 與 PowerShell 指令。

options = ClaudeAgentOptions(
    env={
        "OTEL_SERVICE_NAME": "support-triage-agent",
        "OTEL_RESOURCE_ATTRIBUTES": "service.version=1.4.0,deployment.environment=production",
    },
)

執行多個代理或與其他服務共用同一收集器時, 可覆寫 service name 並附加資源屬性, 方便在後端依代理過濾。

Attribute actions to your end users

CLI 會依所用的憑證為每個事件附加身分屬性, 這辨識的是你服務的憑證, 而非代表哪位終端使用者行動。若要讓工具呼叫與 MCP 活動能歸因到終端使用者, 需在每次 query() 呼叫時注入使用者身分作為資源屬性。

OTEL_RESOURCE_ATTRIBUTES: `enduser.id=${encodeURIComponent(request.userId)},tenant.id=${encodeURIComponent(request.tenantId)}`

附上終端使用者身分後, tool_decision, tool_result, mcp_server_connection, permission_mode_changed 等事件就成為可轉送給 SIEM 平台的逐使用者稽核軌跡。

Control sensitive data in exports

遙測預設是結構性的: 持續時間, 模型名稱, 工具名稱都會記錄, 但代理讀寫的內容預設不會被記錄。以下變數為選擇性加入內容:

OTEL_LOG_USER_PROMPTS=1
在 user_prompt 事件與 interaction span 上加入提示文字
OTEL_LOG_TOOL_DETAILS=1
在 tool_result 事件上加入工具輸入參數 (檔案路徑, shell 指令等)
OTEL_LOG_TOOL_CONTENT=1
在 claude_code.tool 上加入完整工具輸入輸出內容, 截斷於 60 KB, 需啟用 tracing
OTEL_LOG_RAW_API_BODIES
完整 Messages API 請求/回應 JSON, 啟用即代表同意揭露上述三者的所有內容
注意

除非可觀測性流程已核准儲存代理處理的資料, 否則不要設定這些變數。
