在 SDK 中使用 Claude Code 功能

將專案指示, skills, hooks 等 Claude Code 檔案系統功能載入你的 SDK agent

範圍標示 UNIVERSAL CLI 與 SDK 共通概念 API-SPECIFIC 僅 SDK 程式化選項

控制檔案系統設定來源 settingSources API-SPECIFIC

省略 settingSources 時, query() 會讀取與 CLI 相同的檔案系統設定: 使用者, 專案與本地設定, CLAUDE.md 檔案, 以及 .claude/ 底下的 skills, agents 與 commands。

選擇來源查看載入內容: project user local
載入內容
專案 CLAUDE.md, .claude/rules/*.md, 專案 skills, 專案 hooks, 專案 settings.json
位置
<cwd>/.claude/ 用於 settings.json 與 hooks; <cwd> 及所有父目錄用於 CLAUDE.md 與 rules
載入內容
使用者 CLAUDE.md, ~/.claude/rules/*.md, 使用者 skills, 使用者 settings
位置
~/.claude/
載入內容
CLAUDE.local.md, .claude/settings.local.json
位置
<cwd>/.claude/ 用於 settings.local.json; <cwd> 及所有父目錄用於 CLAUDE.local.md
async for message in query(
    prompt="Help me refactor the auth module",
    options=ClaudeAgentOptions(
        # "user" 讀取 ~/.claude/, "project" 讀取 ./.claude/
        setting_sources=["user", "project"],
        allowed_tools=["Read", "Edit", "Bash"],
    ),
):
    ...

settingSources 不會控制的項目

Managed policy settings
MDM, registry policy, 或 server-managed settings, 一律從主機載入
~/.claude.json
全域設定一律讀取, 可用 CLAUDE_CONFIG_DIR 搬移
Auto memory
預設載入系統提示, 可設 autoMemoryEnabled: false 停用
claude.ai MCP connectors
使用 claude.ai 訂閱認證時載入, 需設 strictMcpConfig 停用
警告

多租戶部署不要依賴預設選項。因為上述項目不受 settingSources 控制, 應設定 settingSources: [] 加上 CLAUDE_CODE_DISABLE_AUTO_MEMORY=1, 每個租戶使用獨立檔案系統。

專案指示 CLAUDE.md 與規則 UNIVERSAL

CLAUDE.md 與 .claude/rules/*.md 給予 agent 持久的專案脈絡: 程式碼慣例, 建置指令, 架構決策。當 settingSources 包含 "project" 時, SDK 會在 session 開始時載入這些檔案。

Project (root)
<cwd>/CLAUDE.md, settingSources 包含 project 時載入
Project rules
<cwd>/.claude/rules/*.md 及每層父目錄
Local
<cwd>/CLAUDE.local.md, settingSources 包含 local 時載入
User
~/.claude/CLAUDE.md, settingSources 包含 user 時載入

所有層級都是疊加的: 若專案與使用者 CLAUDE.md 同時存在, agent 會同時看到兩者。沒有硬性優先順序規則, 若指示衝突, 建議在更明確的檔案中直接陳述優先順序。

Skills UNIVERSAL

Skills 是給予 agent 專門知識與可呼叫工作流程的 markdown 檔案。與每個 session 都會載入的 CLAUDE.md 不同, skills 是按需載入。

async for message in query(
    prompt="Review this PR using our code review checklist",
    options=ClaudeAgentOptions(
        setting_sources=["user", "project"],
        skills="all",
        allowed_tools=["Read", "Grep", "Glob"],
    ),
):
    ...
注意

Skills 必須以檔案系統形式建立 (.claude/skills/<name>/SKILL.md)。SDK 沒有提供程式化註冊 skills 的 API。

Hooks UNIVERSAL

SDK 支援兩種定義 hooks 的方式, 兩者並行執行。

Filesystem hooks

settings.json 中定義的 shell 指令, 與互動式 Claude Code session 使用相同格式。

適合在 CLI 與 SDK session 間共用 hooks。

Programmatic hooks

直接傳入 query() 的 callback 函式, 在你的應用程式行程中執行, 可回傳結構化決策。

適合應用程式專屬邏輯與流程內整合。

async def audit_bash(input_data, tool_use_id, context):
    command = input_data.get("tool_input", {}).get("command", "")
    if "rm -rf" in command:
        return {
            "hookSpecificOutput": {
                "hookEventName": "PreToolUse",
                "permissionDecision": "deny",
                "permissionDecisionReason": "Destructive command blocked",
            }
        }
    return {}  # 空字典代表允許執行

選擇正確的功能

Agent SDK 提供多種擴充 agent 行為的方式, 下表將常見目標對應到正確的做法。

CLAUDE.md
設定 agent 永遠遵循的專案慣例, settingSources 自動載入
Skills
給予 agent 按需載入的參考資料, 或可重複使用的工作流程
Subagents
將獨立子任務委派給全新的 context, 透過 agents 參數設定
Agent teams
多個 Claude Code 實例協調共享任務清單, 為 CLI 限定功能
Hooks
在工具呼叫上執行確定性邏輯, 例如稽核, 封鎖或轉換
MCP
給予 Claude 對外部服務的結構化工具存取, 透過 mcpServers 參數
要點

Subagents 是短暫且獨立的: 全新對話, 單一任務, 回傳摘要給父層。Agent teams 則是多個獨立 Claude Code 實例共享任務清單並直接互相傳訊息, 是 CLI 限定功能。
