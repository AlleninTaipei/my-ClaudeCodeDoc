建立與呼叫自訂工具

工具由四個部分組成: 名稱, 描述, 輸入 schema, 與 handler。

const getTemperature = tool(
  "get_temperature",
  "Get the current temperature at a location",
  {
    latitude: z.number(),
    longitude: z.number()
  },
  async (args) => {
    const response = await fetch(`https://api.open-meteo.com/...`);
    const data = await response.json();
    return { content: [{ type: "text", text: `Temperature: ${data.current.temperature_2m}°F` }] };
  }
);
const weatherServer = createSdkMcpServer({
  name: "weather",
  version: "1.0.0",
  tools: [getTemperature]
});

Server 在你的應用程式行程內執行, 不是獨立行程。

for await (const message of query({
  prompt: "What's the temperature in San Francisco?",
  options: {
    mcpServers: { weather: weatherServer },
    allowedTools: ["mcp__weather__get_temperature"]
  }
})) { ... }

mcpServers 的 key 會成為工具全名的 {server_name} 區段: mcp__{server_name}__{tool_name}。

const weatherServer = createSdkMcpServer({
  name: "weather",
  version: "1.0.0",
  tools: [getTemperature, getPrecipitationChance]
});
// 用萬用字元一次允許整個 server 的所有工具
allowedTools: ["mcp__weather__*"]

新增工具註解

Tool annotations 是描述工具行為的選用中繼資料, 所有欄位都是布林值。

readOnlyHint (預設 false)
工具不修改環境, 控制能否與其他唯讀工具平行呼叫
destructiveHint (預設 true)
工具可能執行破壞性更新, 僅供參考
idempotentHint (預設 false)
相同參數重複呼叫沒有額外效果, 僅供參考
openWorldHint (預設 true)
工具會連到行程外部的系統, 僅供參考
注意

Annotations 是中繼資料而非強制規則。標記 readOnlyHint: true 的工具若 handler 真的寫入磁碟, 依然會寫入, 請確保標記與 handler 行為一致。

控制工具存取

tools 選項與 allowed/disallowed 清單影響兩個層面: 可用性 (工具是否出現在 context 中) 與權限 (呼叫是否需要核准)。

tools: [...]
可用性層面, 只有列出的內建工具會出現在 context 中
tools: []
移除所有內建工具, Claude 只能使用你的 MCP 工具
allowedTools
權限層面, 列出的工具無需核准即可執行
disallowedTools
裸名稱同時影響兩層, 範圍規則 (如 Bash(rm *)) 只影響權限

MCP 工具名稱格式固定為 mcp__{server_name}__{tool_name}, 例如 weather server 的 get_temperature 會變成 mcp__weather__get_temperature。

處理錯誤

Handler 拋出未捕捉例外

Agent loop 停止, Claude 永遠看不到錯誤, query 呼叫直接失敗。

Handler 回傳 isError: true

Agent loop 繼續, Claude 把錯誤當成資料看待, 可以重試, 換工具, 或向使用者解釋失敗原因。

try {
  const response = await fetch(args.endpoint);
  if (!response.ok) {
    return { content: [{ type: "text", text: `API error: ${response.status}` }], isError: true };
  }
  ...
} catch (error) {
  // 在這裡捕捉能讓 agent loop 存活, 未捕捉的拋出會終止整個 query
  return { content: [{ type: "text", text: `Failed: ${error}` }], isError: true };
}

回傳圖片與資源

選擇內容類型: image 區塊 resource 區塊
type: "image"
固定值
data: string
Base64 編碼的原始位元組, 不含 data: 前綴
mimeType: string
必填, 例如 image/png, image/jpeg

圖片沒有 URL 欄位, 若要回傳位於某個網址的圖片, 需在 handler 內先 fetch 再 base64 編碼。

resource.uri
內容的識別字串, 任何 URI scheme 皆可
resource.text / blob
文字或二進位內容, 擇一提供
resource.mimeType
選填

URI 只是 Claude 可以之後參照的標籤, SDK 不會實際去讀那個路徑。

回傳結構化資料與範例

structuredContent 是結果上獨立於 content 陣列的選填 JSON 物件, 讓 Claude 讀取精確欄位而非從文字或圖片中解析。

return {
  content: [{ type: "image", data: chartPngBuffer.toString("base64"), mimeType: "image/png" }],
  structuredContent: { series: "temperature_2m", points: [62.1, 63.4] }
};

設定 structuredContent 時, Claude 會收到 JSON 加上任何圖片或資源區塊, content 中的文字區塊不會被轉發, 因為系統假設它們與結構化資料重複。單位轉換器範例展示了 enum schema 與不支援輸入時回傳 isError 的完整模式。
