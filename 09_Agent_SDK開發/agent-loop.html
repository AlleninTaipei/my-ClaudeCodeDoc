Agent Loop 運作原理

了解訊息生命週期, 工具執行, 情境視窗, 以及支撐 SDK agent 運作的架構

迴圈總覽

每個 agent session 都遵循相同的循環: 接收提示, 評估並回應, 執行工具, 重複, 回傳結果。使用下方的步驟導覽逐一了解每個階段。

1 · 接收提示
2 · 評估並回應
3 · 執行工具
4 · 重複
5 · 回傳結果
STEP 1

Claude 接收你的提示, 連同系統提示, 工具定義, 以及對話歷史。SDK 會產生一個 subtype 為 "init" 的 SystemMessage, 內含 session 中繼資料。

STEP 2

Claude 評估目前狀態並決定如何進行, 可能回覆文字, 請求一個或多個工具呼叫, 或兩者皆有。SDK 會產生包含文字與工具呼叫請求的 AssistantMessage。

STEP 3

SDK 執行每個被請求的工具並收集結果, 每組工具結果會回饋給 Claude 做下一步決策, 你可以用 hooks 來攔截, 修改或封鎖工具呼叫。

STEP 4

步驟 2 和 3 會重複循環, 每個完整循環稱為一個 turn, Claude 會持續呼叫工具與處理結果, 直到產出不含工具呼叫的回應為止。

STEP 5

SDK 產生最後一則不含工具呼叫的 AssistantMessage, 接著是包含最終文字, token 使用量, 成本, 與 session ID 的 ResultMessage。

Step 1 of 5

輪次與訊息 (Turns and Messages)

一個 turn 是迴圈中一次完整的往返: Claude 產出包含工具呼叫的輸出, SDK 執行工具, 結果自動回饋給 Claude。以「修正 auth.ts 中失敗的測試」為例, 完整流程如下:

Turn 1呼叫 Bash 執行 npm test, 收到三個失敗結果
Turn 2呼叫 Read 讀取 auth.ts 與 auth.test.ts
Turn 3呼叫 Edit 修正 auth.ts, 再次執行 npm test, 全數通過
Final Turn產出純文字回應, 無工具呼叫: 修好了, 三個測試都通過了
限制迴圈

可用 max_turns / maxTurns 限制工具使用回合數, 或用 max_budget_usd / maxBudgetUsd 依花費上限停止, 未設限時迴圈會執行到 Claude 自行完成為止。

訊息類型 (Message Types)UNIVERSAL

迴圈執行過程中, SDK 會產生一連串訊息, 每則訊息都帶有類型欄位, 標示它來自迴圈的哪個階段。

SystemMessage
session 生命週期事件, 例如 init, compact_boundary
AssistantMessage
每次 Claude 回應後產生, 包含文字與工具呼叫區塊
UserMessage
每次工具執行後產生, 內含回傳給 Claude 的結果
StreamEvent
僅在啟用 partial messages 時產生, 包含原始串流事件
ResultMessage
標示迴圈結束, 包含最終文字, token 用量, 成本與 session ID

範例: 檢查訊息類型並處理結果

from claude_agent_sdk import query, AssistantMessage, ResultMessage

async for message in query(prompt="Summarize this project"):
    if isinstance(message, AssistantMessage):
        print(f"Turn completed: {len(message.content)} content blocks")
    if isinstance(message, ResultMessage):
        if message.subtype == "success":
            print(message.result)
        else:
            print(f"Stopped: {message.subtype}")

工具執行 (Tool Execution)

沒有工具時, Claude 只能以文字回應, 有了工具, Claude 就能讀取檔案, 執行指令, 搜尋程式碼, 與外部服務互動。

Read / Edit / Write
讀取, 修改, 建立檔案
Glob / Grep
依模式尋找檔案, 用正規表示式搜尋內容
Bash
執行 shell 指令, 腳本, git 操作
WebSearch / WebFetch
搜尋網路, 擷取並解析網頁
ToolSearch
依需動態尋找並載入工具, 而非預先全部載入
Agent / Skill / AskUserQuestion
產生子代理, 呼叫技能, 詢問使用者, 追蹤任務
平行執行

唯讀工具 (Read, Glob, Grep, 標記為 read-only 的 MCP 工具) 可平行執行, 會修改狀態的工具 (Edit, Write, Bash) 則依序執行以避免衝突。

控制迴圈運作方式

可限制迴圈的輪次數量, 花費上限, 推理深度, 以及工具是否需要核准。

選擇 effort 等級查看說明: low medium high xhigh max
行為
最少推理, 回應快速
適合場景
尋找檔案, 列出目錄

權限模式

acceptEdits

自動核准檔案編輯與常見檔案系統指令 (mkdir, touch, mv, cp), 其他 Bash 指令仍走預設規則。

bypassPermissions

所有允許的工具都不經詢問直接執行, 僅限隔離環境使用, 不可在 Unix 以 root 執行。

情境視窗 (The Context Window)

情境視窗是 Claude 在一個 session 期間可用的資訊總量, 不會在各輪次之間重置, 所有內容都會累積。

系統提示與 CLAUDE.md

每次請求都會載入, 屬固定成本, 且會被 prompt cache 快取以降低成本。

工具定義

內建工具每次請求都會載入, MCP 工具 schema 預設延後載入。

對話歷史

隨每個 turn 累積, 包含提示, 回應, 工具輸入與輸出。

技能描述

啟動時載入簡短摘要, 完整內容僅在被呼叫時才載入。

自動壓縮 (Automatic Compaction)

重要

當情境視窗接近上限時, SDK 會自動壓縮對話: 摘要較舊的歷史以釋放空間, 同時保留最近的交流與關鍵決策。持久性規則應寫在 CLAUDE.md, 而非放在初始提示中。

處理結果 (Handle the Result)

迴圈結束時, ResultMessage 會告訴你發生了什麼並提供輸出, subtype 欄位是判斷終止狀態的主要依據。

success
任務正常完成, result 欄位可用
error_max_turns
完成前已達 maxTurns 上限
error_max_budget_usd
完成前已達 maxBudgetUsd 上限
error_during_execution
迴圈執行過程中發生錯誤中斷
error_max_structured_output_retries
重試上限內未產生有效的結構化輸出

綜合運用

下例結合本頁重點概念, 建立一個修復失敗測試的完整 agent: 設定允許工具, 專案設定, 以及輪次與推理深度的安全上限。

async def run_agent():
    async for message in query(
        prompt="Find and fix the bug causing test failures",
        options=ClaudeAgentOptions(
            allowed_tools=["Read", "Edit", "Bash", "Glob", "Grep"],
            setting_sources=["project"],
            max_turns=30,  # 避免失控的 session
            effort="high",
        ),
    ):
        if isinstance(message, ResultMessage):
            if message.subtype == "success":
                print(f"Done: {message.result}")

掌握這個迴圈後, 就能決定何時該用 hooks 稽核工具呼叫, 何時該用 subagents 把工作卸載到獨立情境, 以及如何用串流即時呈現進度。
