Agent SDK 中的 Plugins

透過 Agent SDK 以程式化方式從本地目錄載入 plugins, 為 agent session 加入 skills, agents, hooks 與 MCP servers。

Plugins 是什麼

Plugins 是可跨專案共享的 Claude Code 擴充功能包, 可以包含以下四種元件:

Skills
由模型自主呼叫的能力, 也能透過 /skill-name 手動呼叫。
Agents
針對特定任務設計的專用 subagent。
Hooks
回應工具使用與其他事件的事件處理器。
MCP servers
透過 Model Context Protocol 整合的外部工具。
注意

commands/ 目錄是舊格式, 新的 plugin 請改用 skills/。Claude Code 仍會同時支援兩種格式以維持回溯相容。

載入 Plugins

在 options 設定中提供本地檔案系統路徑即可載入 plugin。type 欄位必須是 "local", 這是 SDK 目前唯一接受的值。若 plugin 來自 marketplace 或遠端 repository, 需先下載再提供本地目錄路徑, SDK 支援同時從不同位置載入多個 plugin。

for await (const message of query({
  prompt: "Hello",
  options: {
    plugins: [
      { type: "local", path: "./my-plugin" },
      { type: "local", path: "/absolute/path/to/another-plugin" }
    ]
  }
})) {
  // Plugin commands, agents, and other features are now available
}

路徑指定方式

相對路徑

以目前工作目錄為基準解析, 例如 "./plugins/my-plugin"。

絕對路徑

完整檔案系統路徑, 例如 "/home/user/plugins/my-plugin"。

注意

路徑應指向 plugin 的根目錄, 也就是 skills/, agents/, hooks/, commands/ (舊格式) 或 .claude-plugin/ 的上一層目錄, 而不是其中某個子目錄。

驗證 Plugin 安裝

plugin 成功載入後會出現在系統初始化訊息中, 可以透過 init 訊息確認已載入哪些內容。

plugins
已載入的 plugin 清單, 例如 [{ name: "my-plugin", path: "./my-plugin" }]
skills
plugin skill 會以 plugin 名稱為前綴, 例如 ["my-plugin:greet"]
slash_commands
與 plugin commands 共用相同前綴, skills 也會一併出現在這裡, 例如 ["compact", "context", "my-plugin:custom-command", "my-plugin:greet"]

使用 Plugin Skills

來自 plugin 的 skill 會自動以 plugin 名稱加上命名空間避免衝突。若要直接呼叫, 傳入 /plugin-name:skill-name 作為 prompt 即可。

query({
  prompt: "/my-plugin:greet", // 使用帶命名空間的 plugin skill
  options: {
    plugins: [{ type: "local", path: "./my-plugin" }]
  }
});
注意

若你是透過 CLI 安裝 plugin (例如 /plugin install my-plugin@marketplace), 仍可在 SDK 中使用, 只要提供其安裝路徑即可, CLI 安裝的 plugin 通常位於 ~/.claude/plugins/。

完整範例

下面示範載入 plugin 並列出其可用 skills 與 commands 的完整流程。

const pluginPath = path.join(__dirname, "plugins", "my-plugin");

for await (const message of query({
  prompt: "What custom commands do you have available?",
  options: { plugins: [{ type: "local", path: pluginPath }], maxTurns: 3 }
})) {
  if (message.type === "system" && message.subtype === "init") {
    console.log("Loaded plugins:", message.plugins);
    console.log("Available skills:", message.skills);
  }
}

Plugin 結構參考

plugin 目錄通常包含一份選用的 .claude-plugin/plugin.json 清單檔。若省略, Claude Code 會依目錄結構自動判斷元件。

my-plugin/
├── .claude-plugin/
│   └── plugin.json          // 選用, 省略時自動偵測元件
├── skills/                   // Agent Skills
│   └── my-skill/
│       └── SKILL.md
├── commands/                 // 舊格式, 請改用 skills/
│   └── custom-cmd.md
├── agents/                   // 自訂 agents
│   └── specialist.md
├── hooks/                    // 事件處理器
│   └── hooks.json
└── .mcp.json                // MCP server 定義

常見使用情境

開發與測試plugins: [{ type: "local", path: "./dev-plugins/my-plugin" }], 開發階段不需先全域安裝即可載入
專案專屬擴充將 plugin 放入專案 repository, 讓團隊共享一致的擴充設定
多來源組合同時組合來自不同位置的多個 plugin, 例如本地路徑與 ~/.claude/custom-plugins/ 共用

疑難排解

Plugin 未載入
確認路徑指向 plugin 根目錄, 驗證 plugin.json 是否為合法 JSON, 檢查目錄是否可讀取。
Skills 未出現
以 /plugin-name:skill-name 命名空間呼叫, 確認 init 訊息中 skills 清單含正確命名空間, 檢查每個 skill 是否各自有獨立子目錄下的 SKILL.md。
路徑解析問題
確認目前工作目錄, 優先使用絕對路徑以提高可靠性, 並以路徑工具正確組合路徑。
