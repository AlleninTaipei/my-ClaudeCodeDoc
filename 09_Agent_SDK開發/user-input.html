Handle User Input 處理核准與使用者輸入

將 Claude 的核准請求與釐清問題呈現給使用者, 再把使用者的決定回傳給 SDK。

偵測 Claude 何時需要輸入

Claude 在工作時有時需要與使用者確認, 例如刪除檔案前需要許可, 或需要詢問新專案要用哪個資料庫。這些請求都需要應用程式呈現給使用者, Claude 才能根據回覆繼續執行。

Claude 會在兩種情況下請求使用者輸入: 需要工具使用許可 (例如刪除檔案或執行指令), 以及有釐清問題 (透過 AskUserQuestion 工具)。兩者都會觸發 canUseTool 回呼, 暫停執行直到你回傳回應, 這與一般對話回合 (Claude 結束後等你的下一則訊息) 不同。

語言: 
async def handle_tool_request(tool_name, input_data, context):
    # 提示使用者並回傳 allow 或 deny
    ...

options = ClaudeAgentOptions(can_use_tool=handle_tool_request)
async function handleToolRequest(toolName, input, options) {
  // options 包含 { signal: AbortSignal, suggestions?: PermissionUpdate[] }
  // 提示使用者並回傳 allow 或 deny
}

const options = { canUseTool: handleToolRequest };
工具需要核准
Claude 想使用未被權限規則或權限模式自動核准的工具, 檢查 tool_name (如 "Bash", "Write")
Claude 提出問題
Claude 呼叫 AskUserQuestion 工具, 檢查 tool_name == "AskUserQuestion" 以不同方式處理
注意

已自動核准的工具永遠不會觸發此回呼。權限評估流程中較早的核准, 例如允許規則, 或 acceptEdits / bypassPermissions 等模式, 會在 canUseTool 被詢問前就解析完成呼叫。若要套用到每個工具呼叫的邏輯, 請改用在流程其餘部分之前執行的 PreToolUse hook。

處理工具核准請求

一旦在查詢選項中傳入 canUseTool 回呼, 當 Claude 想使用權限流程中尚未核准的工具時就會觸發。回呼接收三個參數:

toolName
Claude 想使用的工具名稱, 例如 "Bash", "Write", "Edit"
input
Claude 傳給工具的參數, 內容依工具而異
options / context
額外內容, 包含選用的 suggestions (建議的 PermissionUpdate) 與取消訊號
Bash
command, description, timeout
Write
file_path, content
Edit
file_path, old_string, new_string
Read
file_path, offset, limit

回應工具請求的六種方式

除了允許或拒絕之外, 也可以修改工具輸入, 或提供協助 Claude 調整做法的內容。

使用者原樣核准動作, 直接把回呼收到的 input 原封不動傳回, 工具就會照 Claude 要求的方式執行。

if approved:
    return PermissionResultAllow(updated_input=input_data)
return PermissionResultDeny(message="User declined")

使用者核准但想先修改請求, 可以在工具執行前更動 input。Claude 會看到結果, 但不會被告知內容被改過, 適合用於淨化參數或限縮存取範圍。

if tool_name == "Bash":
    sandboxed_input = {**input_data, "command": input_data["command"].replace("/tmp", "/tmp/sandbox")}
    return PermissionResultAllow(updated_input=sandboxed_input)

使用者核准且不想同類呼叫再次被詢問。第三個回呼參數帶有 suggestions, 是現成的 PermissionUpdate 項目, 挑一個回傳到 updated_permissions 即可套用, 目的地為 localSettings 的建議會寫入 .claude/settings.local.json。

if choice == "always":
    persist = [s for s in context.suggestions if s.destination == "localSettings"]
    return PermissionResultAllow(updated_input=input_data, updated_permissions=persist)

使用者不希望這個動作發生, 封鎖工具並附上說明理由的訊息, Claude 看到這則訊息後可能會嘗試不同做法。

if not approved:
    return PermissionResultDeny(message="User rejected this action")
return PermissionResultAllow(updated_input=input_data)

使用者不想要這個特定動作, 但有別的想法, 封鎖工具並在訊息中提供指引, Claude 會讀取並依你的回饋決定如何進行。

if tool_name == "Bash" and "rm" in input_data.get("command", ""):
    return PermissionResultDeny(
        message="User doesn't want to delete files. They asked if you could compress them into an archive instead."
    )

若是徹底改變方向 (不只是小幅調整), 可使用串流輸入直接傳送新指示給 Claude, 這會略過目前的工具請求, 給 Claude 全新指示。

處理釐清問題

當任務有多種合理做法, Claude 需要更多方向時, 會呼叫 AskUserQuestion 工具, 這會以 toolName 設為 AskUserQuestion 觸發 canUseTool 回呼。釐清問題在 plan mode 中特別常見, Claude 會先探索程式碼庫並提問, 再提出計畫。

1 · 傳入回呼
2 · 偵測問題
3 · 解析問題
4 · 收集回答
5 · 回傳答案

在查詢選項中傳入 canUseTool 回呼。預設會提供 AskUserQuestion, 若指定 tools 陣列限制 Claude 的能力 (例如只有 Read, Glob, Grep 的唯讀 agent), 記得把 AskUserQuestion 也加進陣列, 否則 Claude 無法提出釐清問題。

在回呼中檢查 toolName 是否等於 AskUserQuestion, 以便和其他工具分開處理:

if tool_name == "AskUserQuestion":
    return await handle_clarifying_questions(input_data)
return await prompt_for_approval(tool_name, input_data)

輸入內容的 questions 陣列包含 Claude 的問題, 每個問題有 question (顯示文字), options (選項), 與 multiSelect (是否允許多選)。

question
要顯示的完整問題文字
header
問題的簡短標籤, 最多 12 個字元
options
2 到 4 個選項, 各有 label 與 description, TypeScript 可選 preview
multiSelect
若為 true, 使用者可選擇多個選項

把問題呈現給使用者並收集他們的選擇, 做法依應用程式而定, 可以是終端機提示, 網頁表單, 或行動裝置對話框。

建立 answers 物件, 每個鍵是問題文字, 值是所選選項的 label, 多選問題可傳陣列或用逗號串接。

questions
傳回原始的 questions 陣列 (工具處理所需)
answers
鍵為問題文字, 值為所選 label 的物件
response
選用的自由回覆, 僅在使用者略過結構化問題直接輸入時設定
Step 1 of 5
選項預覽 (TypeScript)

toolConfig.askUserQuestion.previewFormat 可為每個選項加上 preview 欄位, 讓應用程式顯示視覺化模擬。未設定時欄位不存在, Claude 不會產生 preview。"markdown" 會產生 ASCII 圖與程式碼區塊, "html" 會產生樣式化的 div 片段 (SDK 會在回呼執行前拒絕 script, style, DOCTYPE)。

釐清問題支援 1 到 4 個問題, 每題 2 到 4 個選項。AskUserQuestion 目前在透過 Agent 工具產生的 subagent 中無法使用。

限制

Subagents
AskUserQuestion 目前無法在透過 Agent 工具產生的 subagent 中使用
問題數量限制
每次 AskUserQuestion 呼叫支援 1 到 4 個問題, 每題 2 到 4 個選項

其他取得使用者輸入的方式

canUseTool 回呼與 AskUserQuestion 工具涵蓋大多數核准與釐清情境, 但 SDK 還提供其他取得使用者輸入的方式。

串流輸入

中斷 agent 進行中的任務, 傳送取消訊號或改變方向

在 Claude 詢問前提供額外內容

建立聊天介面, 讓使用者在長時間操作期間傳送後續訊息

自訂工具

收集超出 AskUserQuestion 選擇題格式的結構化輸入, 例如表單或精靈

整合現有的票務, 工作流程或核准平台

實作應用程式專屬的互動, 例如程式碼審查介面或部署檢核清單
