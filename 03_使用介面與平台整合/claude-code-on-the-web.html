Use Claude Code on the web

Configure cloud environments, setup scripts, network access, and Docker in Anthropic's sandbox. Move sessions between web and terminal with --cloud and --teleport.

GitHub authentication options

Cloud sessions need access to your GitHub repositories to clone code and push branches. You can grant access in two ways.

GitHub App

Authorize the Claude GitHub App during web onboarding.

Best for browser onboarding and teams that want Auto-fix.

/web-setup

Run /web-setup in your terminal to sync your local gh CLI token to your Claude account.

Best for individual developers who already use gh.

NOTE

With either method, a cloud session can access any repository the connecting GitHub account can see. The GitHub App is required for Auto-fix, which uses the App to receive PR webhooks. Organizations with Zero Data Retention enabled can't use /web-setup.

The cloud environment

Each session runs in a fresh Anthropic-managed VM with your repository cloned. Cloud sessions start from a fresh clone; anything committed to the repo is available, anything installed only on your own machine isn't.

Work with GitHub issues and pull requests

Built-in GitHub tools let Claude read issues, list pull requests, fetch diffs, and post comments without setup, authenticated through a GitHub proxy so your token never enters the container. To use a gh command the built-in tools don't cover:

1 · Install gh
2 · Provide token

Add apt update && apt install -y gh to your setup script.

Add a GH_TOKEN environment variable to your environment settings. gh reads GH_TOKEN automatically, no gh auth login step needed.

Step 1 of 2

Run tests, start services, add packages

service postgresql start
service redis-server start

Test runners like pytest, jest, and cargo test are pre-installed. Docker is available for containerized services; ask Claude to run docker compose up.

Setup scripts

A setup script is a Bash script that runs when a new cloud session starts, before Claude Code launches. Scripts run as root on Ubuntu 24.04.

#!/bin/bash
apt update && apt install -y gh
TIP

If the script exits non-zero, the session fails to start. Append || true to non-critical commands. Keep total runtime under roughly five minutes so the environment cache can build.

Setup scripts vs. SessionStart hooks

Setup scripts

Attached to the cloud environment, configured in the cloud environment UI.

Runs before Claude Code launches, cloud environments only.

SessionStart hooks

Attached to your repository, configured in .claude/settings.json.

Runs after Claude Code launches, on every session, both local and cloud.

{
  "hooks": {
    "SessionStart": [{
      "matcher": "startup|resume",
      "hooks": [{ "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/scripts/install_pkgs.sh" }]
    }]
  }
}

Network access

Network access controls outbound connections from the cloud environment. The default is Trusted, which allows package registries and other allowlisted domains.

None
No outbound network access
Trusted
Allowlisted domains only: package registries, GitHub, cloud SDKs
Full
Any domain
Custom
Your own allowlist, optionally including the defaults

GitHub proxy and security proxy

All GitHub operations go through a dedicated proxy: the git client authenticates using a scoped credential, restricts push to the current working branch, and enables cloning, fetching, and PR operations. All outbound internet traffic passes through a security proxy for abuse prevention, rate limiting, content filtering, and a DNS-level audit trail.

DEFAULT ALLOWED

Under Trusted access, common package registries are allowed by default: npm, PyPI, RubyGems, crates.io, Go modules, Maven/Gradle, Docker Hub and other container registries, GitHub/GitLab/Bitbucket, and major cloud platform domains.

Move tasks between web and terminal

Direction:
Terminal to web
Web to terminal
claude --cloud "Fix the authentication bug in src/auth/login.ts"

Creates a new cloud session on claude.ai, cloning your current directory's GitHub remote at your current branch. --cloud works with a single repository at a time. Use /tasks to check progress.

claude --cloud "Fix the flaky test in auth.spec.ts"
claude --cloud "Update the API documentation"

Each --cloud command creates its own session that runs independently, so tasks run in parallel.

claude --teleport
# or, inside a session:
/teleport

Pulls a cloud session into your terminal. If you have uncommitted changes, you'll be prompted to stash them first. Distinct from --resume, which reopens local history without listing cloud sessions.

Clean git state
No uncommitted changes, or you'll be prompted to stash
Correct repository
Same repository, not a fork
Branch available
Must have been pushed to the remote
Same account
Authenticated to the account used in the cloud session

Work with sessions

Sessions appear in the sidebar at claude.ai/code. From there you can review changes, share with teammates, archive finished work, or delete sessions permanently.

/compactSummarizes the conversation to free up context
/contextShows what's currently in the context window
/clearNot available, start a new session from the sidebar instead

Each session shows a diff indicator like +42 -18. Select it to open the diff view and leave inline comments. Sharing visibility depends on account type: Enterprise/Team accounts get Private/Team, Max/Pro accounts get Private/Public. Archived sessions are hidden from the default list; deletion is permanent and requires confirmation.

Auto-fix pull requests

Claude can watch a pull request and automatically respond to CI failures and review comments, subscribing to GitHub activity and pushing a fix if one is clear. Requires the Claude GitHub App installed on the repository.

Clear fixes
Claude makes the change, pushes it, explains what was done
Ambiguous requests
Claude asks before acting
Duplicate / no-action
Claude notes it and moves on
WARNING

Repositories with comment-triggered automation such as Atlantis, Terraform Cloud, or custom GitHub Actions should review automation before enabling auto-fix, since Claude replies on your behalf and can trigger those workflows.

Security and isolation

Each cloud session runs in an isolated, Anthropic-managed VM. Network access is limited by default and can be disabled, though Claude Code can still reach the Anthropic API. Sensitive credentials like git credentials or signing keys are never inside the sandbox; authentication goes through a secure proxy using scoped credentials, and code is analyzed and modified in isolated VMs before creating PRs.

Troubleshooting

Issue:
Session creation failed
Remote Control expired
Environment expired

Claude Code could not allocate a cloud environment. Check status.claude.com, retry after a minute, and confirm the connecting GitHub account has access to the repository.

--teleport connects through Remote Control infrastructure, so expiry surfaces as "Remote Control session expired" or "Access denied". Run /login locally to refresh credentials and confirm you're signed in to the account that owns the session.

Cloud sessions stop after a period of inactivity and the environment is reclaimed. Reopen the session from claude.ai/code to provision a fresh environment with conversation history restored.

Limitations

Rate limits
Shared with all other Claude and Claude Code usage; parallel tasks consume more proportionately
Repository authentication
Can only move sessions from web to local on the same account
Platform restrictions
Cloning and PR creation require GitHub; GitLab/Bitbucket can be sent as a local bundle but can't push back
Org IP allowlist
Cloud sessions call the Anthropic API from Anthropic infrastructure, not your network, so IP allowlisting breaks authentication
